# v1.36.0 Pre-Analysis — Migration Completeness (Gate 0)

## 1. Link migration (the Gate 0 item) — decided

`cv` skipped symlink/hardlink entries (`foreign_transcode.cpp`, "link_skipped")
because the staging pipeline spools to a filesystem path and the mutator's
link variants read the link's times from disk. The mutator's link records,
however, already take the target as a caller-supplied string
(`prepare_add_symlink(..., target, is_dir_target, ...)` — the path argument
feeds only `get_file_times`).

**Decision:** add `prepare_add_symlink_from_memory` /
`prepare_add_hardlink_from_memory` — identical FileBlock construction with
times taken from the foreign entry's already-clamped `mtime_sec` (the unix
HTIME fields are 32-bit; sub-second foreign precision is not representable
here, and the staging detour cannot apply to a non-existent filesystem
object). Targets migrate **verbatim**.

**Security review (the actual Gate 0):** a migrated target originates in an
untrusted foreign archive. Enforcement does not move: `ArchiveReader`'s
extraction path already refuses absolute and escaping relative targets,
scans for symlink parents, applies the spec-07 skip-with-warning semantics
(`archive_reader.cpp:2598-2611`), and handles the Windows privilege class
(1314) — all existing, tested behavior. Staging a REDIR record adds no
surface the writer does not already carry (the `a` path emits identical
records from filesystem symlinks). The extraction side is the policy
enforcement point and is unchanged.

**Hardlink resolution rule:** a RAR5 hardlink record references an earlier
entry by name. A foreign hardlink whose master did not migrate (skipped,
refused, name-empty) cannot resolve and is skipped with
`link_target_missing` in the report instead of emitting a dangling record.
Migration order follows foreign archive order; POSIX tar hardlinks
conventionally follow their masters, and forward references are skipped by
the same rule (documented behavior, not an error).

**Symlink dir-target-ness:** foreign metadata does not reliably carry it;
the conservative file-target default is used (it only affects Windows
directory-symlink creation at extraction).

## 2. Output-shaping switches — scope decision

- `-ts` (timestamps): foreign metadata carries **mtime only**
  (`ForeignEntry::mtime_sec/nsec`); there is nothing to shape beyond the
  default MTIME mask. Documented, no code.
- `-s` (solid): the batch writer's solid support is exercised only by the
  `a` path's SolidPacker wiring; wiring cv's spool-then-stage pipeline into
  it is a follow-up, not part of the link-migration surface. Deferred to the
  discovery pool with the mutator-solid note.
- `-v` (volumes): the mutator has no volume writer; a cv `-v` requires the
  multi-volume machinery to grow a batch-writer mode. Deferred to the
  discovery pool.

## 3. FILECOPY default-materialization policy — decided

`cv` re-compresses every migrated file at `options.method` (the pipeline
decodes the source entry and re-emits through `prepare_add_file`). A foreign
STORED entry therefore becomes a compressed RAR5 entry at the requested
method. Decision: **keep re-compression as the default** (predictable
output, ratio-optimal for the requested method) — `-m0` already expresses
the stored pass-through policy for users who want byte-faithful speed. No
new switch; the policy is this document.

## 4. Gates

The transcode suite gains `test_transcode_tar_links_migrate`: file + symlink
+ resolvable hardlink + dangling hardlink; asserts `migrated_links == 2`,
the dangling skip with report, and the REDIR records on the wire (types,
verbatim targets, dangling absent). The full transcode/archive suites, the
interop gate (Tracks 11-13 are cv), and the CLI exit taxonomy are the
release gates.
