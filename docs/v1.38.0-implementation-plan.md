## What this arc ships (and explicitly does not)

The roadmap's flat-table and SIMD-dispatch predictions are **measured
negatives** on the target host (pre-analysis §0/§5); the rebuild-trap
arithmetic they relied on was ~30x too pessimistic (§3). The arc ships the
levers the measurements support, at the scale the measurements support:

- **M1a** — phase-1 record-emission slimming, no ownership changes [D2].
- **M1b** — per-worker record-buffer pool — ONLY if M1a's measurement shows
  the residual allocation cost justifies the lifetime complexity [D2].
  *Measured after M1a: the in-span reserve closed the entire warm-vs-cold
  gap (136.0 → 135.8 ms on text m3); M1b is not needed and is not built.*
- **M2a** — apply-stage filter-queue head cursor replacing
  `erase(begin())` [D3]. *Shipped; measured neutral at the tested scale
  (~16 pending regions), kept as the principled O(n²)→O(n) discipline.*
- **M2b — filter-region extraction memcpys: measured negative, declined.**
  The wrap-split memcpy region read won its isolated micro-bench by 24x and
  lost end-to-end by +16% on exelike m3 sequential (stabilized 413.5 →
  479.7 ms; the bisect isolated the extraction as the sole cause). The
  per-byte ring walk ships unchanged; the reversal is recorded in the
  pre-analysis §6 so the micro-bench's verdict is never trusted alone.
- **M3 (declined, with measurements)** — flat tables, SIMD dispatch, delta
  ch>1, BMI2 bit reader: each carries its measured reason in the pre-analysis
  (§0, §3, §5). Not shipped, not re-attempted without new evidence.
- **Entry 23 disposition** — `docs/question-log.md` entry recording the
  corrected BlockBitSize model (token-start check; reader already
  reference-equivalent) and the three oracle experiments that would settle
  any future doubt [D7].
- **M4** — measurement re-records + docs. Neutral end-to-end results are
  reported as neutral, before any claim is written [D4].

Invariants: `HuffmanDecoder` and `BitReader` semantics ship byte-for-byte
unchanged; every decode consumer (CLI x/t in-process and sandboxed worker,
DLL extract/test, buffer API, stream_decoder, wasm decompress_buffer_raw)
routes through the same `decompressor50.cpp` — no sibling kernel copy exists
(HuffmanDecoder has exactly one definition; swept). Pack-side rows stay
byte-identical (encoder untouched). Extraction memory stays
O(dictionary window + slice buffers) — no table-memory delta exists
(pre-analysis §9).

## M1a — record-emission slimming (no ownership changes) [D2]

Files: `src/compress/decompressor50.cpp` (`decode_span`),
`src/compress/parallel_decode.cpp` (`worker_body`).

1. **Pre-reserve at span start**: `out.recs.reserve(est_recs)`,
   `out.lit_pool.reserve(est_pool)` with modest estimates derived from the
   span's packed size (NOT the full G5 cap — review round 1: a full-cap
   reserve would multiply resident memory by ~workers). Implemented:
   `est_pool = min(rec_cap, max(64 KiB, span_packed))`,
   `est_recs = min(rec_cap / 12, max(4096, span_packed / 2))`; a reserve
   throw fails the span cleanly (F1).
2. **Bulk literal-run emission**: `push_lit` accumulates into a 255-byte
   stack run buffer; `close_run` appends with a single
   `lit_pool.insert(lit_pool.end(), run, run + n)`. `run_start` is recorded
   as `lit_pool.size()` before the insert (the record's pool offset is
   unchanged). The capacity-preserving contract survives: insert keeps
   existing capacity warm.
3. **Hoisted record-cap counter** [D8]: replace the per-token
   `rec_bytes() > rec_cap` lambda with a running byte counter updated at the
   append sites (`close_run`, non-literal record pushes). The check point
   stays at the loop top, BEFORE the token's records are appended — the G5
   bound fails on exactly the same token as today; only the representation
   changes.
4. M1b (contingent, same files + driver): per-worker pool of
   `MAX_IN_FLIGHT_AHEAD + 2` `SpanRecords`, publish by pointer, recycle
   gated on `sync.applier_pos > span_index`; the applier consumes and
   releases the slot back to the owning worker's pool. Only implemented if
   the M1a measurement leaves ≥ 5% of span decode in allocation.

Gates for M1a: full `tools/gate.ps1` + fuzz + golden/interop; the
`two_phase_span_records` identity rows must stay green unchanged (records are
byte-identical by construction — same fields, same order, same cap
semantics).

## M2a — filter-queue head cursor (the extraction memcpy is declined, see above)

File: `src/compress/decompressor50.cpp` (`ApplyEngine::flush_pending`),
`src/compress/decompressor50.hpp` (the `filters_head_` member).

1. **Queue cursor**: `filters_` gains a head index; the flush loop reads
   `filters_[filters_head_]` and advances it per consumed region instead of
   `erase(begin())`; the consumed prefix compacts ONCE per flush call. The
   push side (`filters_.push_back`, `.back()` overlap check, the 65536
   pending bound — now `size() - head_`) is unchanged; compaction at the
   end of each flush call keeps `.empty()/.back()` semantics identical to
   the erased queue; the solid per-block queue carry keeps its
   absolute-coordinate frame (invariants §4 / coordinate-frame rule).
2. Named identity rows [D3]: the existing filter-bearing chunk-identity
   rows stay green; added `filter region crosses window wrap` (128 KiB
   window, E8 member — the ring read wraps every second region by
   construction) and the zero-length + 300-region cursor row
   (`filter_zero_length_regions_cursor`).

stages) + clang-format pre-commit (C++ only; never on .py). The parked
branch `arc/v1.37.0-parallel-decode-wip` stays untouched (the scout it holds

default target [D6]. WASM/ILP32: no new SIMD code exists to compile out; the
parallel-decode G6 gate is untouched.

delta ch>1, BMI2, encoder changes, two-phase gating/decision function,
solid-chain parallel decode, durability.
