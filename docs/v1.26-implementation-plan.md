# v1.26.0 Implementation Plan — CDC-Driven Solid-Chain Packing (Gate 0 Cleared)

**Status:** governing plan for the v1.26.0 arc. Gate 0 format-legality
review complete (docs/v1.26-pre-analysis.md): chunk-store and cross-archive
designs REJECTED as illegal RAR5; the surviving design is **CDC-driven
solid-chain packing** — ordinary RAR5 solid compression with packer-side
ordering only. Architect-challenge round 1: conditional approval, seven
directives — all folded into THIS revision (§2 constraints, §4 FMM, §6
test plan). Normative inputs: `docs/ROADMAP.md` §v1.26.0,
SECURITY_ARCHITECTURE §5.4.

**Honest scope statement:** this arc is a **packer-side ordering
heuristic**, not a deduplication format. The reduction claim is
window-bounded and measured against a plain-solid same-window baseline
(directive 1). Extraction sees ordinary RAR5 solid streams — zero
decoder/WASM changes (directive: divergence screen).

## 1. Design

1. **CDC fingerprinting engine** (`src/compress/cdc_chunker.*`):
   FastCDC-style Gear-hash chunker with normalized cut points
   (TargetAvg 64 KiB, min 16 KiB, max 256 KiB; mask-driven boundary at
   fixed bit positions per normalization level). Per file: a fingerprint
   list (offset, length, 128-bit Gear hash truncated to 64 bits).
   Parallel per-file (files are independent); indices merged in canonical
   (path, chunk-idx) order — decision-determinism, Pillar 7.8.
2. **Fingerprint index** (bounded, honest memory model): `kFingerprintCap
   = 2,000,000` entries × 16 bytes (u64 hash + u32 file-idx + u32
   chunk-idx) = 32 MiB hard cap. Cap hit → **planner falls back to
   original order for the remaining files, reported on output**
   (directive 5 — no silent degradation).
3. **Affinity planner** (feeds `compress_plan.hpp`): builds a
   similarity graph (files sharing ≥ 30% of the smaller file's chunk
   hashes), emits an ordering: high-affinity files adjacent within one
   solid run, ordered so earlier chunks of the earlier file sit within
   the window of the later file's matching chunks. Stable tie-break:
   original archive order. Deterministic at any `-mt` (canonical merge).
   Exact duplicates → `-oi` FILECOPY takes precedence (see §2.3).
4. **`select_volume_source`-style single decision point**: the planner is
   the ONLY component that reorders; the batch writer consumes the
   reordered list via the existing `write_batch_add_ex` (atomic rewrite
   preserved — Pillar 7.3).
5. **Timestamp clamping wiring** (rolled-in, security-arch §4.4
   reconciliation): `clamp_mtime`/`MtimeBounds` applied in
   `ArchiveReader` at file-commit time and in the deferred dir-meta
   application; out-of-bounds stamps are clamped and surface as the
   `timestamp_clamped` security flag in the JSON summary +
   skip-with-report console line.

## 1b. Challenge round 2 — critical finding + applied directives

**Critical finding:** the pre-analysis claimed `-oi` FILECOPY creation was
"shipped" — it is NOT. The reader extracts FILECOPY entries (tested) but
there is no `-oi` switch parsing, no duplicate detection, and no
FHEXTRA_REDIR type-5 emission anywhere in the creation path (verified:
zero `redir_type = 5` writers in archive_mutator.cpp). The README's
`-oi[0-4]` row is changelog-as-contract drift (Pillar 7.6). The arc
therefore ADDS the -oi creation side as an explicit milestone.

**Applied directives:**
1. **M2a (new): `-oi` creation side** — content-hash duplicate detection →
   FHEXTRA_REDIR type-5 emission (threshold honored, README row becomes
   true). FILECOPY redirs are emitted OUTSIDE solid runs (no data area —
   the writer breaks runs around them; pinned by test 5).
2. **Switch shape:** a separate `-cdc` switch (implies identical-file
   references); `-oi[0-4]`'s numeric scale stays report-verbosity.
3. **Three-number gate moves to tests/bench**: the CLI's pack-time report
   prints logical/packed/window/CDC-flag only (computing the plain-solid
   baseline at pack time would triple compression work); the baseline
   comparison lives in the bench + the reduction-report test.
4. **Test 5 pinned** to verify the writer's run-breaking around redir
   entries (solid chain decodable across a redir gap).
5. **`-cdc` + `-oi1` interaction**: single combined report, no
   double-reporting.
6. **Small-duplicate handling** (below FILECOPY threshold): solid-window
   affinity is their only dedup path — stated in the planner spec.

## 2. Constraints & interactions (challenge directives)

1. **Baseline gate (directive 1):** the reduction report prints THREE
   numbers per corpus — (a) store total, (b) plain solid original-order
   at the plan's window, (c) CDC-packed at the same window. (c) must beat
   (b) by a measured margin or the planner reports "no improvement" and
   the CLI suggests plain solid. No claim without all three numbers.
2. **`-oi` collision (directive 3):** CDC packing ships as `-oi5`
   (identical-file references + similarity packing). FILECOPY redir
   entries carry NO data area → they cannot sit inside a solid run: the
   planner emits redir'd duplicates OUTSIDE solid runs (the run breaks
   around them), which is legal — runs are per-file chains, a non-solid
   file between runs is ordinary.
3. **Extraction-order change (directive 4):** documented as user-visible
   (header order = listing order); the switch is opt-in; ordering
   stability pinned by test (same input ⇒ byte-identical archive at any
   `-mt`).
4. **Window selection (directive 6):** the planner states the window it
   packed for; reduction re-measured at that window.
5. **Degenerate inputs (directive 7):** 0-byte/tiny files yield empty or
   single-chunk fingerprint sets — planner handles them as
   original-order, non-affinity entries.
6. **RR interaction (pre-analysis R3):** CDC-packed sets get the full
   recovery-record test battery re-run (repair on reordered solid runs).
7. **Caps cross-check (§5.4):** dedup-expanded streams are ordinary solid
   streams — `ExtractionLimits` apply unchanged; a test pins
   max_total_output_bytes on a CDC-packed archive (directive: §5.4
   cross-check).

## 3. Failure-Mode Matrix

Phases: C = chunk/fingerprint, P = plan/order, W = batch rewrite (existing
atomic path). Classes: crafted input, OOM/cap, disk-full, cancellation,
parallelism.

| Phase \ Class | crafted input | OOM/cap | disk-full | cancel | parallelism |
| :--- | :--- | :--- | :--- | :--- | :--- |
| C | pathological cut-shift → bounded chunks (min/max clamps); fuzz-pinned | index cap → fallback to original order, reported | n/a (read-only) | cancel → abort, no partial state | canonical merge order; per-file parallelism is race-free |
| P | affinity graph from untrusted names → keyed by content hashes only | planner cap → original-order tail, reported | n/a | n/a | deterministic at any -mt |
| W | unchanged atomic rewrite (write_batch_add_ex) | unchanged | unchanged (temp + atomic replace) | unchanged (cancel polls) | unchanged (single writer thread) |

## 4. CLI surface

- `-oi5` — CDC packing (implies -oi1 identical-file references).
- Reduction report (stdout, and `--json-summary` when present):
  `cdc: logical=X packed=Y plain-solid=Z saving=(Y-Z)/Y%` — the
  three-number gate made user-visible.

## 5. Milestones

- **M1** — chunker + fingerprint engine + index cap fallback; chunker
  fuzz tests (boundary stability under byte flips: cut points shift by ≤ 1
  chunk).
- **M2a** — `-oi` creation side: content-hash duplicate detection →
  FHEXTRA_REDIR type-5 emission (threshold honored); redirs outside solid
  runs; README `-oi` row becomes true.
- **M2b** — affinity planner + `-cdc` switch (implies identical-file
  references) + ordering-stability test + FILECOPY/redir interaction
  tests; CLI report: logical/packed/window/CDC-flag (three-number baseline
  gate lives in the bench + tests, not at pack time).
- **M3** — timestamp clamping wiring (rolled-in) + `timestamp_clamped`
  flag + skip-with-report test.
- **M4** — caps cross-check (§5.4) + RR-on-CDC-packed repair tests +
  oracle round-trips (WinRAR/UnRAR read CDC-packed solid archives).
- **Release** — CHANGELOG, stamp 1.26.0 (MINOR), roadmap, full preflight,
  release commit, tag, push, assets, notes.

Each milestone lands with its named negative tests green on all CI legs
before the next begins.

## 6. Named Negative Tests

1. `oi_creation_side_emitted` — `a -cdc` on a corpus with exact
   duplicates emits FHEXTRA_REDIR type-5 entries outside solid runs;
   extraction produces identical bytes (also pins the README `-oi` row —
   Pillar 7.6 drift fix).
1a. `cdc_chunk_boundary_fuzz` — bit flips near cut points shift boundaries
   by ≤ 1 chunk (rolling-hash locality property, fuzz-pinned).
2. `cdc_index_cap_falls_back_reported` — fingerprint cap hit → original
   order for the tail, fallback reported on stdout.
3. `cdc_packing_order_stable` — same input ⇒ byte-identical archive at
   `-mt1` and `-mt8`.
4. `cdc_reduction_report_three_numbers` — report carries store /
   plain-solid / CDC-packed; CDC-packed ≤ plain-solid.
5. `cdc_filecopy_precedence` — exact duplicates become FILECOPY redirs
   outside solid runs; identical content never double-packed.
6. `cdc_packed_caps_enforced` — `max_total_output_bytes` fires on a
   CDC-packed solid stream (§5.4 cross-check).
7. `cdc_packed_rr_repair` — recovery record + repair works on a
   CDC-packed reordered solid archive.
8. `timestamp_clamped_flag` — out-of-bounds mtime clamped + flag in JSON
   summary + skip-with-report line.
9. `cdc_degenerate_inputs` — 0-byte and <min-chunk files pack in original
   order, no crash, no affinity edges.
