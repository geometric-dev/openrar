> scope: no encoder code before M0 lands and §3/§6 existed (directive 4).

## 1. Design

**M1 — slot-257 run-collapse (all methods 1..5).**

New token type `TokenType::LastLen` (packed type code 6 — 7 unused) in
`Compressor50Token` (src/compress/compressor50.hpp). Emission decision
lives inside `process_available()`'s existing rep-evaluation block
(compressor50.cpp:1349-1423) — the single shared loop for one-shot,
streaming, and solid-carry paths (decision-function determinism):

- Encoder keeps `last_length_` shadow (new member, `size_t`), mirroring
  the decoder exactly: set to full length INCLUDING distance increment on
  match emission; set to length WITHOUT increment on rep emission;
  unchanged by literals/filters/257; reset to 0 whenever `reset_old_dist()`
  fires (non-solid file start / fresh session).
- 257 fires only INSIDE the existing rep-win decision (challenge
  directive 1 — no new competition path): the rep thread must already
  have won (`rep_best_len + 1 > best.length`), the winning thread must
  be `rep_idx == 0`, and then ALL of: (a) `last_length_ != 0`;
  (b) `old_dist_[0]` valid (≠ -1, ≠ 0, ≤ max_dist_, within written
  prefix); (c) `rep_best_len >= last_length_` — **actual byte
  verification inherited from the rep scan** (`rep_length` is a real
  comparison; directive 1 of the Gate 0 challenge); (d) **emission
  bound: `last_length_ <= cur_max_lz`** — a 257 copies exactly
  `last_length_` bytes, so the copied span must fit inside the current
  filter region (a clamped *verification* with an unclamped *emission*
  would copy past the region end — the decoder un-transforms per region
  and the encoder has not yet transformed bytes past `rem`; the
  v1.21.25 boundary class). Emitted coverage is exactly `last_length_`
  bytes (directive 2); `OldDist` is not rotated; the next position
  re-decides. When the rep thread wins with `rep_best_len <
  last_length_`, or the winning thread is rep1-3 (challenge directive
  3, rep0-only), or the rep thread loses to a fresh match, the existing
  rep/fresh/lazy logic decides unchanged — so lazy evaluation and
  FailCount interactions are inherited, not re-opened. The decision
  adds O(1): the `rep_length(cur_, old_dist_[0], …)` value the rep scan
  already computes is reused.
- Frequency: `freq_ld_[257]++` per 257 token (per-block tables keep the
  no-257-no-table-cost property).
- Filter interaction: the existing region clamp (`cur_max_lz = rem`)
  applies to the verification length — a 257 chain never crosses a filter
  token region (byte-verification length is `min(last_length_, rem)` and
  condition (c) uses the clamped value).
- 257 chains join the FailCount accounting identically to rep matches
  (`len >= 8` resets `fail_count_`).

**M2 — binary-tree match finder for m4/m5.**

New finder alongside the chains, selected in `init_match_params()`-driven
setup (one decision function): methods 4-5 with `win_size_ <= 64 MiB` use
the tree; everything else keeps chains. Structure: keep `head_`/`head64_`
as the hash head; replace `prev_` with two child arrays `child_l_`/
`child_r_` (u32, win-sized) on the small-window path; on the solid-carry
stream the tree arrays join the KEEP set beside `head_/prev_/prev64_`
(`begin_stream(continue_window)`, challenge directive 4). Tree insert+search is
the classic binary-tree walk (zlib deflate / bt-style): insert walks down
comparing 3-byte hash then match length, recording the path; search reuses
the walk with `max_chain` reinterpreted as the node-visit budget and
`nice_len` unchanged. Literal positions keep the O(1)-amortized batch
insert (the walk IS the insert; no separate pass). Sliding window /
`pos_base_` / 32-bit truncation (`reconstruct_pos`) semantics preserved
verbatim; the tree stores the same truncated positions chains do. Bit
limits: `is_large_window_` (>4 GiB) keeps chains (pre-existing memory
profile; tree never touches the u64 path). WASM keeps chains: the
selection rule is method AND window AND build — emscripten builds
compile with `OPENRAR_MATCHFINDER_CHAINS` defined by default (the
escape hatch in pre-analysis §2b, now a compile-time gate so the rule
and the engine-trace table agree; revisit only if a measured wasm
benefit justifies the budget review).

**M3 — parameter re-tune (m1 primary).** Sweep `chains`/`nices`/`lazies`
for m1 (candidate grid around {4,8,16}×{128,256,512}×{0,1}) scored on the
canonical + mixed + zeros corpora with the perf protocol; m5 re-checks
nice_len only (finder change shifts the optimum). Winners replace the
`init_match_params()` tables AND spec 03's heuristics table (docs-as-
contract, directive 6).

**M4 — re-baseline + docs + release.** Golden re-baseline
(tests/fixtures/golden/{mutator,writer} + tools/check_golden.ps1) with
UnRAR + WinRAR extracting the new bytes hash-exact; PERFORMANCE.md rewrite
(zeros bullet corrected in M0; m5/m1 rows refreshed); README perf rows;
CHANGELOG [1.31.0]; MINOR bump v1.31.0, PATCH counter reset at the release
commit (anchor v1.31.0, `git rev-list --count v1.31.0..HEAD` protocol per
docs/versioning.md); version-consistency set moves together: CMakeLists.txt,
wasm/js/package.json, bindings/python/pyproject.toml, bindings/csharp
csproj (directive 10).

## 2. Constraints & interactions (directive 2: engine trace)

The 257 shadow and the tree selection are traced through every engine:

| Engine | 257 shadow | Finder selection |
|---|---|---|
| One-shot `compress()` | per-file reset via `reset_old_dist()` site | method+window rule |
| Streaming `feed`/`finish_stream` | same shared loop; reset on `begin_stream` (non-continue) | same |
| Solid carry `begin_stream(continue_window)` | shadow in the KEEP set beside `old_dist_` | same (window unchanged by contract) |
| One-shot solid (`solid_packer`) | per-file reset for non-solid members; carried for solid | same |
| `compress_buffer_parallel` | chunk-local (fresh per chunk, matches are chunk-bounded) | same; per-chunk windows ≤ 8 MiB default |
| WASM block codec | same class, same rules | chains (compile-time `OPENRAR_MATCHFINDER_CHAINS` default for emscripten builds) |

Parity tests (T8) pin byte-identical output per method per input WITHIN
each engine across {scalar, SSE2, AVX2} dispatch (v1.22 lesson), with
the two pre-existing cross-engine identities: streaming ≡ one-shot
(the stream_encoder_tests gate), and parallel deterministic per its
published chunk geometry (chunked output ≠ one-shot by design —
per-chunk windows — unchanged by this arc).

## 3. Failure-Mode Matrix

| New path | Failure mode | Behavior |
|---|---|---|
| 257 emission | shadow desync vs decoder (solid carry, filter clamp, rep rotation) | Never: conditions (a)-(d) mirror decoder rules; negative tests T1-T5; cross-extraction on every matrix config |
| 257 emission | emitted when bytes don't repeat | Impossible: condition (c) is a real byte comparison; T1 pins the corruption class as unreachable |
| 257 emission | first token of a file (no last match) | Condition (a) false → literal/match path; T2 |
| 257 emission | filter region boundary mid-run | Clamped verification length; chain stops at region end; T3 |
| 257 emission | dest/window edge (`FirstWinDone` prefix) | `rep_length` already bounds dist ≤ written prefix; unchanged; T4 |
| Tree finder | OOM at 64 MiB window (2 child arrays) | Tree only ≤ 64 MiB windows; allocation failure → fall back to chains fail-closed with a VISIBLE `W:`-class notice on stderr (suppressed under `-q`, same convention as the sandbox fallback — challenge directive 4; silently-degraded effort would be fail-open), output still valid — chains are always legal; T6 |
| Tree finder | window slide invalidates stale child entries | Same slide semantics as `prev_` (positions bounded by `pos_base_`; `reconstruct_pos` rejects out-of-window); T7 |
| Tree finder | infinite walk / cycle | Walk budget = visit cap derived from max_chain; positions strictly decrease; T7 |
| Re-tune | ratio regression on an unmeasured corpus class | Full matrix gate + m3 noise-band gate; losers not shipped |
| Release | stale version in one consistency file | M4 checklist item; preflight catches |

## 6. Named Negative Tests

- **T1 `slot257_byte_verification`:** crafted input where the shadow
  matches but bytes diverge at offset < last_length_ — encoder must emit
  rep0/literal, never 257; decode + CRC byte-exact.
- **T2 `slot257_first_token`:** file starting with a repeat pattern — no
  257 before any match; stream decodes byte-exact (UnRAR oracle).
- **T3 `slot257_filter_region_boundary`:** e8-filtered binary with a run
  ending exactly at a region boundary — 257 chain stops; cross-validated
  decode (the v1.21.25 boundary class). Covers BOTH filter paths: the
  in-loop transform (streaming/file path) and the `compress_buffer`
  pretransformed path (challenge directive 5) — their region-remainder
  arithmetic differs.
- **T4 `slot257_window_prefix`:** run within the first window (no wrap) —
  dist ≤ written prefix holds; decode byte-exact. Extended (challenge
  directive 3) with the EOF-tail dest-clamp case: final match clamped by
  remaining output → tail position takes the literal/rep path (never
  257 — the decoder keeps `last_length_` pre-clamp), decode byte-exact.
- **T5 `slot257_solid_carry_parity`:** solid set (match end → file
  boundary → next file continues the run): shadow carried across the
  boundary; streaming vs one-shot vs solid-carry byte-identical.
- **T6 `tree_oom_fallback`:** fault-injected child-array allocation
  failure at m5/64 MiB → chains fallback, output valid, result reported.
- **T7 `tree_slide_bounds`:** 3× window slide with in-window/out-of-window
  candidates — no stale reads (ASan leg), walk terminates, output matches
  one-shot.
- **T8 `finder_engine_parity`:** per method × {one-shot, streaming,
  parallel, solid} × {scalar, SSE2, AVX2} — byte-identical outputs.
- **T9 `pure_addition_when_suppressed`:** corpus where 257 never fires
  (distinct-(len,dist)-forced inputs) → output byte-identical to v1.30.4
  at every method (directive 9). Reference bytes: captured from the
  pre-M1 build (v1.30.4 code, tracer reverted) BEFORE the M1 commit
  changes emission — compressed-stream SHA-256s for a small deterministic
  corpus at each method are committed as test fixtures alongside M1, and
  the test compares against them via the `Compressor50TestAccess`
  seam (257 emission suppressed) or an equivalent test-only switch.
- **T10 `slot257_cross_interop`:** new-stream archives decoded by UnRAR +
  WinRAR hash-exact across {zeros, canonical, mixed, filtered} (the
  legality proof; interop gate stages re-run per emission-touching commit).
