## 1. Executive Summary & Scope

The v1.47 cycle delivers four key platform and security engineering pillars:
1. **macOS Seatbelt Decision Record & Residual Capability-Gap Table (`M0`, `M0b`):**
   Formalize the macOS sandboxing architecture. Evaluate Apple's Seatbelt mechanism (`sandbox_init` / SBPL) vs. unprivileged plain-spawn, publish the mandatory capability-gap matrix across Windows AppContainer, Linux seccomp-BPF, and macOS Seatbelt, and wire the capability-unavailable branch to explicit, loud runtime disclosures (**V-2**).
2. **Foreign-Format Fuzzers (`M1`, `M2`):**
   Implement `fuzz_zip` (covering CD-vs-LFH discrepancies, ZIP64 extensions, truncation, and overlaps with exit-code oracles) and `fuzz_tar` (covering GNU long names, oversized PAX headers, sparse-entry abuse, and truncated records).
3. **Parallel Decode Concurrency Hardening (`M3`, `M4`):**
   Target ThreadSanitizer (TSan) coverage on `parallel_decode.cpp` span workers and applier handoffs, asserting that the parallel path actively engages without data races or lock inversion. Assess MemorySanitizer (MSan) viability.
4. **WAV Delta Audio Detection UB Fix (`M5`, OPT-F01):**
   Fix integer truncation and overflow vulnerability in `Filters50::detect_filter` (`filters50.cpp:140`), computing audio stride in 32-bit unsigned arithmetic with explicit bounds verification prior to narrowing. Seed regression and fuzz corpora with adversarial RIFF headers (`channels=0xFFFF, bps=0xFFFF` and `channels=2, bps=1032`).

## 2. Milestone Decomposition

### M0 & M0b — macOS Seatbelt Decision Record & Capability Gap

#### Architectural Facts:
- `platform_sandbox_available()` is declared in `src/sandbox/spawn.hpp:49` and implemented per-OS in `src/sandbox/spawn.cpp:21` (Windows AppContainer/LPAC), `:224` (Linux seccomp-BPF + namespaces), and `:391` (macOS plain-spawn fallback, currently returning `false`).
- Apple's Seatbelt mechanism uses `sandbox_init(const char *profile, uint64_t flags, char **errorbuf)` or `sandbox_init_with_parameters`.
- **Engineering Assessment:**
  1. Profile definitions in SBPL (Scheme-like syntax) are compile-time strings where validation failures produce opaque runtime errors without diagnostic telemetry.
  2. Apple formally deprecated `sandbox_init` in macOS 10.8 in favor of App Sandbox entitlements, yet CLI utilities cannot embed code-signed entitlements outside of code-signed bundles.
  3. Per `v1.30-pre-analysis.md:508-512`, shipping an opaque, brittle profile risks creating a "sandbox that does not actually sandbox". OpenRAR's posture: *"A cut ships two solid models plus honest docs"*.
- **Decision:**
  - Implement Seatbelt SBPL profile for macOS worker child processes restricting filesystem writes and outbound network access.
  - Where Seatbelt is disabled or unavailable, route the fallback path through loud user-visible warnings and structured JSON disclosures (`symlink_dropped`, `sandbox_unavailable`).

#### Mandatory Residual Capability-Gap Table

| Capability | AppContainer (Windows) | seccomp-BPF (Linux) | Seatbelt (macOS) | Disposition | User-Visible Disclosure |
|---|---|---|---|---|---|
| **Process Creation** | Blocked via JobObject (`JOB_OBJECT_LIMIT_ACTIVE_PROCESS = 1`) | Blocked via `clone`/`fork` deny in BPF filter | Blocked via `(deny process-fork)` SBPL directive | `ship` | `none — fully enforced by kernel` |
| **Filesystem Write** | Denied to all paths except explicitly granted worker IPC pipes | Denied by mount namespace (read-only root) & `write` syscall filter | Denied via `(deny file-write*)` SBPL directive | `ship` | `none — fully enforced by kernel` |
| **Filesystem Read** | LPAC grants read only to specified package/input handles | Restricted via mount namespace to input file descriptor | Allowed for dynamic linker and system libs, `(deny file-read* (subpath "/Users"))` except input | `mitigate` | `W: sandbox restricted read policy active` |
| **Network Outbound** | Blocked (no network capabilities in AppContainer token) | Blocked via `socket` syscall deny in BPF filter | Blocked via `(deny network-outbound)` | `ship` | `none — fully enforced by kernel` |
| **Network Inbound** | Blocked (no inbound firewall / socket capability) | Blocked via `socket`/`bind` syscall deny | Blocked via `(deny network-inbound)` | `ship` | `none — fully enforced by kernel` |
| **Arbitrary `exec`** | Blocked via process creation mitigation policy | Blocked via `execve`/`execveat` deny in BPF filter | Blocked via `(deny process-exec)` | `ship` | `none — fully enforced by kernel` |
| **Syscall Filtering** | N/A (Object Manager ACLs + LPAC token security) | Fine-grained BPF filter with `SECCOMP_RET_KILL_PROCESS` | Unchecked at syscall layer (profile operates at VFS/IPC level) | `accept-gap` | `none — documented architectural difference in SECURITY.md` |
| **Path Traversal Policy** | Strict Win32 path normalization and handle-only delegation | Sandboxed worker operates only on passed file descriptor | Worker operates on passed file descriptor; path traversal blocked | `ship` | `none — path sanitization active` |

### M1 & M2 — Foreign-Format Fuzzing (`fuzz_zip` & `fuzz_tar`)

#### `fuzz_zip` Target Specifications:
- **Corpus / Seeds:** Valid ZIP archives, ZIP64 archives, multi-file ZIPs.
- **Vulnerability / Edge Vectors:**
  1. **CD-vs-LFH discrepancies:** Mismatched names, uncompressed sizes, compressed sizes, CRC32, and compression methods between Central Directory and Local File Header. Must trigger exit code 2 (structural refusal) without output.
  2. **ZIP64 overflow & circular headers:** 64-bit field expansions where size or offset exceeds `INT64_MAX` or points past file boundaries.
  3. **Overlapping entries:** Malicious ZIPs where entry data ranges overlap with Central Directory or other entries.
  4. **Directory traversal:** `../` relative traversal attempts in entry filenames (must be normalized cleanly).

#### `fuzz_tar` Target Specifications:
- **Corpus / Seeds:** Standard ustar archives, PAX extended archives, GNU tar format archives.
- **Vulnerability / Edge Vectors:**
  1. **GNU LongLink / LongName abuse:** Extremely long entry names, truncated long-name blocks, consecutive long-name blocks without data.
  2. **Oversized PAX records:** Malformed PAX attribute lengths, non-numeric values, cyclic references.
  3. **Sparse file records:** Hostile sparse map entries declaring byte offsets exceeding file bounds or overlapping regions.
  4. **Truncated tar blocks:** 512-byte block truncations and invalid header checksums.

### M3 & M4 — TSan Coverage on Parallel Decode

- **Target Component:** `src/compress/parallel_decode.cpp`
- **Race Condition Attack Surface:**
  - `apply_span_records` worker threads and applier handoff (`parallel_decode.cpp:240, :327`).
  - Ring buffer synchronization, `std::condition_variable` notifications, and `std::atomic` progress counters.
- **Validation Rule:**
  - CI TSan test suite must execute `two_phase_tests` and `parallel_compress_tests`.
  - The parallel decode path must be verified to have *actively engaged* (using `OPENRAR_PARALLEL_DECODE_SPAN_FLOOR` for small test cases) so that TSan exercises real multi-threaded execution rather than silent sequential fallback.

### M5 — WAV Audio Detection UB Fix (OPT-F01)

#### The Vulnerability in `Filters50::detect_filter` (`filters50.cpp:138-145`):
```cpp
core::uint16 channels = core::read_le16(data + 22);
core::uint16 bits_per_sample = core::read_le16(data + 34);
core::uint8 stride = static_cast<core::uint8>((channels * bits_per_sample) / 8);
if (stride >= 1 && stride <= 32) {
    out_channels = stride;
    return FilterType::Delta;
}
```

#### Defect Mechanisms:
1. **Integer Truncation:** If `channels = 2` and `bits_per_sample = 1032`, then `(2 * 1032) / 8 = 2064 / 8 = 258`. Truncating to `uint8` yields `258 & 0xFF = 2`. The filter check `stride <= 32` evaluates `2 <= 32` as `true`, erroneously applying a 2-byte delta filter to an invalid audio stream.
2. **Arithmetic Overflow:** If `channels = 0xFFFF` and `bits_per_sample = 0xFFFF`, `65535 * 65535 = 4,294,836,225`. In 32-bit signed integer promotion, this overflows signed 32-bit int, invoking Undefined Behavior (UB).

#### Remediation:
```cpp
const core::uint32 ch = core::read_le16(data + 22);
const core::uint32 bps = core::read_le16(data + 34);
const core::uint32 total_bits = ch * bps;
const core::uint32 stride = total_bits / 8;
if ((total_bits % 8 == 0) && stride >= 1 && stride <= 32) {
    out_channels = static_cast<core::uint8>(stride);
    return FilterType::Delta;
}
```

## 4. Negative Test Plan

1. **WAV Detection Negative Cases (`compress_tests.cpp`):**
   - `channels = 2, bps = 1032` (stride 258 -> must return `FilterType::None`).
   - `channels = 0xFFFF, bps = 0xFFFF` (must return `FilterType::None`).
   - `channels = 1, bps = 12` (`total_bits % 8 != 0` -> must return `FilterType::None`).
   - `channels = 33, bps = 8` (stride 33 > 32 -> must return `FilterType::None`).
2. **Foreign Reader Negative Cases (`foreign_format_tests.cpp`):**
   - ZIP CD-vs-LFH name mismatch -> rejected with exit code 2.
   - ZIP CD-vs-LFH CRC32 mismatch -> rejected.
   - TAR oversized PAX header (> 64 KiB) -> rejected gracefully.
   - TAR invalid checksum -> rejected as corrupt.
3. **Sandbox Fallback Disclosure Verification:**
   - Assert `platform_sandbox_available()` returns expected value per platform.
   - In non-sandboxed environment, assert loud warning is emitted when sandbox is requested.
