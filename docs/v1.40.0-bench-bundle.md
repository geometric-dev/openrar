# v1.40.0 — OpenRAR benchmark bundle (`openrar-bench.exe`)

Self-contained Windows benchmark package: one double-clickable SFX console
stub containing the `runbench.exe` driver and all three engines. It generates
its own deterministic corpora at runtime, runs the full
OpenRAR-vs-WinRAR-vs-UnRAR matrix, writes a JSON report to
`%USERPROFILE%\openrar-bench-results.json`, and removes every file it created.
No dependencies beyond the VC runtime. Nothing proprietary is committed —
WinRAR's `rar.exe`/`UnRAR.exe` are copied from the local install at package
time only (D4), and the whole output tree lives under the gitignored `dist/`.

## Components

| File | Role |
|---|---|
| `tools/bench_run.cpp` | The driver (CMake target `runbench`, C++17, links `openrar_core`). Not a test. |
| `tools/make_bench_bundle.ps1` | Stages the payload, writes the SFX comment, packs `dist\openrar-bench.exe`, runs the `-sfxnoexec` smoke. |
| `dist/openrar-bench.exe` | Bundle output (gitignored, never committed). |

Payload layout inside the SFX (extracted flat into `%TEMP%\OpenRAR-<hex>`):

```
runbench.exe    Setup= target; CWD = extraction dir
openrar.exe     built from this repo
UnRAR.exe       copied from the local WinRAR install at package time (D4)
rar.exe         copied from the local WinRAR install at package time (D4)
```

Engine discovery (`tools/bench_run.cpp`): `OPENRAR_EXE`/`UNRAR_EXE`/`RAR_EXE`
env overrides first, then beside the driver (the bundle layout), then the dev
tree / `Program Files\WinRAR` fallbacks. All three engines are always recorded;
a missing or deselected engine yields `skipped` rows so the row set is stable.

## Building

```powershell
cmake --build build --config Release --target runbench openrar Default.SFX
powershell -ExecutionPolicy Bypass -File tools\make_bench_bundle.ps1
```

The script fails fast if `runbench.exe`, `openrar.exe`, `Default.SFX.exe`,
or the WinRAR-install `UnRAR.exe`/`rar.exe` cannot be resolved
(`-RunbenchExe`, `-OpenrarExe`, `-Stub`, `-WinrarDir` override the search).

## Driver flags

```
--quick             2 timed runs, no warm-up, skips the 1 GB section (smoke)
--runs N            timed runs per config (default 3, quick 2; sets runs_flag)
--engines LIST      subset of openrar,unrar,winrar (default all; openrar forced)
--out PATH          report path (default %USERPROFILE%\openrar-bench-results.json)
--keep              keep the work directory (corpora + archives)
--no-pause          do not wait for Enter at exit
--gen-only          generate corpora, print fingerprints, run nothing
--prng-selftest     validate the MT19937 port against CPython vectors
```

Exit codes: `0` all rows ok, `1` some rows failed, `2` fatal (no openrar.exe,
corpus generation failure, unwritable work dir).

## Protocol (parity with `tools/perf_vs_winrar.py`)

- Full mode: 1 untimed warm-up + 3 timed runs, **median** reported,
  `(max-min)/median` spread; `--quick` = 2 timed, no warm-up (dev quick parity,
  `range(4)` drop-first). Fresh outputs each run, pre-deleted outside the timed
  window; timing covers spawn→exit (dev `subprocess.run` parity).
- Row labels match the dev harness (`o_m0_st` … `w_big_m3_mt`,
  `extract_m3_*`, `many_*`); the many-entry section also carries the dev
  `config` names (`m0_entry`, `m0_batch`, `m3_entry`, `m3_batch`, `m3_unrar`).
- Compression rows are cross-extracted (openrar + unrar) and SHA-256
  tree-hash-verified against the source corpus; extraction rows verify every
  run (dev leaves them unverified).
- Corpora are byte-parity with the dev generators where the dev generator has
  no repo dependency (verified against `tools/perf/data`: `zeros512`,
  `canonical/text.txt`, `canonical/random.bin`, and all 610 `many` files
  identical). **Documented drift (D2):** `canonical/code.cpp`, `big/code.cpp`
  and the six `mixed/src_*.cpp` files differ — dev embeds the repo `src` tree,
  which a standalone bundle cannot see; the report's per-corpus fingerprints
  detect this instead of misreading it as a regression.
- PRNG: a CPython MT19937 port (`init_by_array` + twist-before-first-draw =
  variant 2) validated by `--prng-selftest` against five captured ground-truth
  vectors (getrandbits/randbytes/randint/choice). The lazy startup selftest is
  silent; re-capture the vectors with `python3` whenever the dev generator
  seeds change.

## Report

`%USERPROFILE%\openrar-bench-results.json` (D3, overwritten per run, `run_id`
inside): `schema_version`, `run_id`, `quick`, `status`
(`running|ok|failed|fatal|gen-only`), `host{cpu,cores,ram_gb,os}`,
`tools{openrar,unrar,winrar}`, `protocol{warmup,timed,runs_flag,...}`,
`engines` line, `corpora` fingerprints, `rows[]` (label/engine/corpus/status/
runs/median/min/spread/size/verified), `failures[]`, `summary`. The report is
saved incrementally after every row (atomic tmp+rename), so a killed run still
leaves a usable JSON.

## Consent, containment, cleanup

- One consent prompt before `Setup=` runs (default **Don't Run**; press `A`).
- The stub contains every child in a job object (KILL_ON_JOB_CLOSE,
  2 GiB/process, 64 active processes) with ACG; engines are non-JIT.
- `TempMode=`: extraction goes to `%TEMP%\OpenRAR-<hex>` (owner-only),
  `Setup` runs with that dir as CWD, and the stub deletes the subtree after
  `Setup` exits. The driver additionally removes the `bench-work` dir it
  creates beside its own exe (`--keep` to retain it). The report in
  `%USERPROFILE%` is the only persistent output.

## Smoke and release check

```powershell
dist\openrar-bench.exe -sfxnoexec                           # extraction-only smoke
dist\openrar-bench.exe --quick                              # direct driver, no SFX
powershell -File tools\make_bench_bundle.ps1                # includes the smoke
```

`-sfxnoexec` stub behaviors the smoke relies on: `TempMode=` overrides any
`-d` destination (payload lands in a new `%TEMP%\OpenRAR-<hex>` dir), and the
noexec branch returns before the TempMode cleanup — so the script verifies the
payload in the new dir and removes it itself (what the interactive run's
cleanup does after `Setup` exits).

Manual once-per-release pass: double-click the bundle, press `A` at the
consent prompt, let the run finish, press Enter; confirm the report landed in
`%USERPROFILE%` and no `OpenRAR-*` subtree remains in `%TEMP%`. Non-TTY stdin
auto-denies consent, so CI must run the driver directly (never the SFX).

## Operational notes

- Needs ~5 GB free disk (512 MB zeros + 1 GB big corpora + archives +
  per-run extraction copies). A full disk surfaces as engine rc≠0
  (`There is not enough space on the disk`) and fails the affected rows.
- Runtime on this project's 2c/4t laptop: `--quick` ≈ 11 min, full ≈ 31 min
  (33 rows, all verified, measured 2026-10-09).
- The report path, engine sets and labels are stable across runs so two JSON
  reports can be diffed row-by-row.
