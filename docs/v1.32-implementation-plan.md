# v1.32.0 Implementation Plan — Throughput Scaling: MT Encoder

> Status: **PROPOSAL — Gate 0 open, not approved.** Companion to
> `docs/v1.32-pre-analysis.md` §7, which invites challenge on the scope
> itself. Nothing here is binding until that challenge lands. M0 is
> deliberately measurement-only: the arc's central question (pre-analysis
> §2) is whether our 1.48x ST→MT scaling is Amdahl-limited or
> parallel-ceiling-limited, and the two answers imply different programs.
>
> Base: v1.31.0 @ 5f6b717. Reuses the v1.32.0 version number from the
> removed optimal-parse arc (`docs/ROADMAP.md`, descoped section).

## 1. Design

**Byte-identical MT encoder scaling.** All parse work stays exactly as it is.
The arc divides *work*, never *output*. The single binding safety property is
byte-identity with v1.31.0 at every method and every chunk geometry (T8),
which is a tripwire rather than a fallback.

- **Scope:** chunk-size/worker-count tuning, per-worker encoder reuse, and
  per-chunk warm-up amortization — all inside the existing chunk-parallel
  design in `src/compress/parallel_compressor.cpp`.
- **Out of scope:** match-level parallelism and cross-chunk match sharing.
  Both change emitted bytes and are deferred to a future arc (pre-analysis
  §3, Designs B and C), per the "no quiet emission change" constraint in §0.

## 2. Constraints & interactions (engine trace)

| Engine | MT behavior |
|---|---|
| `compress_buffer_parallel` | the arc's subject: chunking, worker lifetime, warm-up |
| one-shot `compress()` | **unchanged**; ST is the control and must not move |
| streaming `feed`/`finish_stream` | unchanged |
| solid `begin_stream(continue_window)` | out of scope (measured ST 8.74 s, MT solid deferred) |
| WASM | single-threaded by construction; no change, size gate unaffected |
| CLI | none — no new switches, no exit-code change, no ABI change |

## 3. Failure-mode matrix

| New path | Failure mode | Behavior |
|---|---|---|
| chunk-size / worker tuning | ST or small-file regression | knobs are MT-only; ST is a pinned control |
| per-worker encoder reuse | stale tables / rep-state / window leak across chunks | explicit per-chunk reset contract, pinned by test |
| warm-up amortization | cheaper warm-up, worse first block per chunk | per-chunk size non-regression check |
| any | **emitted bytes drift** | T8 byte-identity at every method × chunk geometry — the arc's tripwire |

## 4. CLI / tool surface

None. No switches, no exit-code changes, no ABI surface change.

## 5. Milestones

- **M0 — measurement, no code:** answer pre-analysis §2. Instrument the
  existing MT path to attribute the 1.48x (per-chunk fixed cost vs parallel
  ceiling), and measure the "no ratio cost from chunking" claim on a
  **long-range** corpus, not just the canonical one (pre-analysis R2 — this
  is a real gap in the current evidence). Publish the split. **This milestone
  can end the arc**: if the answer is "parallel ceiling", the remaining 2x
  requires Design B, which this arc explicitly does not do.
- **M1 — scheduling:** chunk-size/worker-count sweep against the M0
  attribution; per-worker encoder reuse if M0 shows per-chunk fixed cost
  dominating. T8 byte-identity pinned before any of it lands. Commit.
- **M2 — warm-up amortization** *only if M0 attributes cost to it*;
  per-chunk size non-regression. Commit.
- **M3 — matrix + finals:** re-run the full perf matrix with the core count
  stated explicitly (R3); confirm the ST lead is not eroded (R1); commit.
- **M4 — docs + release v1.32.0:** PERFORMANCE.md scaling rows, CHANGELOG,
  version consistency set, preflight, tag last.

## 6. Named negative tests

- **T-M1 `mt_byte_identity`:** gate-off/ST and every MT chunk geometry
  produce v1.31.0 bytes at every method. *The arc's tripwire — run first,
  on every commit.*
- **T-M2 `mt_encoder_reuse_reset`:** a reused per-worker encoder produces
  identical output to a freshly constructed one, across a chunk boundary
  that changes filter state, rep-state and window position.
- **T-M3 `mt_longrange_ratio`:** on a long-range corpus, MT size ≤ ST size
  (pre-analysis R2 — asserts the "chunking is free" claim that is currently
  only evidenced on the canonical corpus).
- **T-M4 `mt_scaling_measurement`:** the M0 attribution is reproducible and
  records the host core count (R3).
- **T-M5 `st_unaffected`:** ST timing and output unchanged by any MT knob.
- **T-M6 `mt_determinism`:** MT output is byte-identical across runs and
  across worker counts (chunk geometry is fixed, not work-distribution
  dependent).

## 7. Definition of Done

Byte-identity at every method and chunk geometry (T-M1) with the interop gate
green; ST output and timing unchanged (T-M5); the scaling result reported
with its host core count and its attribution, whether or not it reaches 2x;
the long-range ratio claim tested (T-M3) rather than assumed; ctest 45/45 +
new suites on MSVC Debug, WSL fresh-mirror -Werror, clang-format; docs
(PERFORMANCE.md, CHANGELOG) in-arc; release v1.32.0 per the versioning
protocol. **If 2x is unreachable without an emission change, the arc ships the
smaller win and says so** — it does not trade away the ST lead (R1).
