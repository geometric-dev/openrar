# v1.32.0 Implementation Plan — Throughput Scaling: MT Encoder

> Status: **M1-a landed** (MT enablement fix). The scope changed during Gate 0:
> MT was found to be effectively switched off, so this began as "tune a
> 1.48x curve" and became "restore a feature that was not running, then bound
> what enabling it costs". See `docs/v1.32-pre-analysis.md` §8.
>
> Base: v1.31.0 @ 5f6b717. Reuses the v1.32.0 version number from the
> removed optimal-parse arc (`docs/ROADMAP.md`, descoped section).

## 1. Design

**Byte-identical ST, measured MT.** The parse is untouched.

- **ST is the invariant.** The fix touches only which path the MT flag
  selects; `compress()`'s output must not move (T-M5, T-M1).
- **MT is the thing that was never measured.** Its archive size is
  corpus-dependent to a degree nobody characterised — up to **20x** worse on
  long-range-redundant input, because independent 2 MiB chunks cannot match
  across a boundary that an 8 MiB ST window spans. The arc's remaining work
  is to make that predictable, not to make MT faster; scaling already
  measures 2.3–3.7x.
- **Out of scope:** match-level parallelism (changes bytes, deferred) and
  anything that touches the ST path.

## 2. Constraints & interactions (engine trace)

| Engine | MT behavior |
|---|---|
| `compress_buffer_parallel` | the arc's subject: chunking, worker lifetime, warm-up |
| one-shot `compress()` | **unchanged**; ST is the control and must not move |
| streaming `feed`/`finish_stream` | unchanged |
| solid `begin_stream(continue_window)` | out of scope (measured ST 8.74 s, MT solid deferred) |
| WASM | single-threaded by construction; no change, size gate unaffected |
| CLI | none — no new switches, no exit-code change, no ABI change |

## 3. Failure-mode matrix

| New path | Failure mode | Behavior |
|---|---|---|
| chunk-size / worker tuning | ST or small-file regression | knobs are MT-only; ST is a pinned control |
| per-worker encoder reuse | stale tables / rep-state / window leak across chunks | explicit per-chunk reset contract, pinned by test |
| warm-up amortization | cheaper warm-up, worse first block per chunk | per-chunk size non-regression check |
| any | **emitted bytes drift** | T8 byte-identity at every method × chunk geometry — the arc's tripwire |

## 4. CLI / tool surface

None. No switches, no exit-code changes, no ABI surface change.

## 5. Milestones

- **M0 — measurement (DONE, and it found a bug instead of an attribution):**
  the Amdahl-vs-ceiling question turned out to be unanswerable because MT was
  not running. See pre-analysis §8.1–8.2. The measured baseline is now
  2.3–3.7x at −0.02% size on non-redundant data.
- **M1-a — MT enablement fix (DONE):** correct the inverted path selection so
  MT engages when no filter would fire, and takes the sequential path when one
  would, so `-mc` parity is not silently lost. `parallel_compress_tests` and
  `cli_tests` green.
- **M1-b — bound the ratio cost (THE arc's real work).** Decide and implement
  how MT behaves on long-range-redundant input, where the measured cost is
  **20x**. Options in preference order: (a) share a match index across chunk
  boundaries — changes bytes, needs the interop gate; (b) a cheap
  redundancy probe that declines MT when chunks will lose badly, keeping
  output identical; (c) document loudly and leave opt-in. **Pre-committed:
  the arc ships a *characterised* behaviour, not an unbounded one, and the
  choice is recorded with its measurement either way.**
- **M2 — scheduling:** per-worker encoder reuse, chunk-size/worker-count
  sweep, throttle head-of-line review. Second-order now that scaling is
  already ~2.5x; take it only if M1-b lands cheaply.
- **M3 — matrix + finals:** re-run the perf matrix with the core count stated
  and the MT row re-measured end to end (the v1.31.0 MT row is invalid,
  pre-analysis §8.1). Commit.
- **M4 — docs + release v1.32.0:** PERFORMANCE.md MT rows, CHANGELOG, version
  consistency set, preflight, tag last.

## 6. Named negative tests

- **T-M1 `mt_byte_identity`:** ST output at every method is byte-identical to
  v1.31.0. *The arc's tripwire — run first, on every commit.*
- **T-M2 `mt_path_selection`:** the path-selection decision is correct for
  both branches — no-filter-detected → MT, filter-detected → sequential — and
  is independent of thread count and chunk geometry. **New, and it is the
  test whose absence let this bug ship.**
- **T-M3 `mt_longrange_ratio`:** on a long-range-redundant corpus, assert a
  *documented bound* on MT-vs-ST size (not "no cost" — the cost is real and
  large; the point is that it is bounded and known).
- **T-M4 `mt_filter_parity`:** with a filter that would fire, `-mtN` output
  matches `-mt1` output (sequential path honours `-mc`).
- **T-M5 `st_unaffected`:** ST timing and output unchanged by any MT knob.
- **T-M6 `mt_determinism`:** MT output is byte-identical across runs and
  across worker counts (chunk geometry is fixed, not work-distribution
  dependent).

## 7. Definition of Done

ST byte-identical to v1.31.0 at every method (T-M1, T-M5) with the interop
gate green; the path-selection decision pinned by test (T-M2) and `-mc` parity
held (T-M4); **the long-range ratio cost characterised and bounded (T-M3)**,
with the choice recorded and its measurement; MT scaling re-measured end to
end with the host core count stated, replacing the invalid v1.31.0 MT row;
ctest 45/45 + new suites on MSVC Debug, WSL fresh-mirror -Werror,
clang-format; docs (PERFORMANCE.md, CHANGELOG) in-arc; release v1.32.0 per
the versioning protocol. **MT must not ship as an unbounded ratio trade**
(R1) — that is the arc's defining deliverable, not the 2x number.
