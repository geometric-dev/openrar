## Coordinate frame (normative)

Data chunk k = archive bytes `[k·group_count, min(k·group_count +
group_count, protected_size))` counted from **file offset 0** (signature
included). Entry k = raw CRC-64 (poly 0x1100B-family CRC-64/XZ parameters
but **init 0, no final XOR**) over chunk k's **unpadded** bytes. The same
frame is used by the parity fold, the entries pass, T0 localization, and
E3 reassembly — converted nowhere else.

## M1 — E1: emit the state blob (writer)

Files: `src/recovery/recovery_writer.cpp` (build_shard, add_recovery_record,
the RR-resize splice path), `src/recovery/recovery_writer.hpp` (no signature
change), layout comment (D3).

1. Compute the D entries over the protected prefix in the same pass that
   feeds the parity fold (no second file read); serial and `threads>1`
   produce identical bytes (D12) — the entry pass is per-chunk independent;
   when the parity pool runs, entries are computed in a parallel-for over
   the chunk axis before the fold.
2. `build_shard` gains the entries + extent and writes `final_state = 0`
   (D1); shard CRC-64 recomputed after fill (existing code). Scaled
   headers: entries live in the first unscaled region; the scale remainder
   stays zero.
3. Layout comment rewritten: zeros claim retired, expC behavior recorded.
4. Tests (tests/unit/recovery_tests.cpp):
   - `rr_entries_match_reference_model` — entries byte-match an independent
     Python-recomputed fixture (probe corpus recipe, T-UNIT-1).
   - `rr_record_reproducible` — two builds byte-identical (D1).
   - `rr_entries_thread_count_stable` — `threads=1` vs `threads=4`
     byte-identical records (D12).
   - `rr_extent_populated` — extent = unpadded tail length.
   - `rr_zero_entry_records_still_accepted` — reader acceptance of legacy
     zero-entry records unchanged (T-UNIT-3 partial).
5. Goldens: re-baseline RR-bearing goldens only; assert non-RR goldens
   byte-identical (T-REG-1).
6. Oracle (wiped build, T-ORACLE-1): Rar 7.20 `t` All OK + `r` on pristine
   → "0 blocks"; `r` on 1-byte damage → byte-exact; UnRAR `t` All OK

## M2 — E3: multi-physical record reassembly (reader)

Files: `src/recovery/recovery_writer.cpp` (repair-path record loading).

1. Physical-piece grouping by `shard_index` with validation per D8/D13:
   per-piece CRC-64 + unscaled geometry first; coverage/no-gap/overlap of
   `[0, group_count)`; logical fields + entries identical across pieces;
   piece-count bounds enforced before map insertion.
2. Reassembled logical payload feeds the existing per-index decode path.
3. Tests: crafted multi-physical records (valid; gapped; overlapped;

   (T-UNIT-3 rows F4); repair of our own scale>1 archive after corruption.
4. Oracle (T-ORACLE-4): our `r` on a damaged reference 16 MiB record →

## M3 — E2: chunk-granularity multi-erasure decode (reader)

Files: `src/recovery/recovery_writer.cpp` (repair driver — new T0 tier
before the Tier-1 syndrome walk), `src/recovery/recovery_record.cpp`
(no change expected; repair_data already maps missing→parity).

1. T0 (D5/D7/D13/D14): entries present (non-all-zero) + shard CRC-64s
   verified → recompute per-chunk raw CRC-64 over current bytes in the
   existing streamed prefix pass; erasure set = mismatches; `|E| ≤
   valid_parity` → decode; reconstructed chunks re-verify against entries
   before splice; empty set + invalid parity → existing parity-rebuild
   branch (D14); any other outcome → fall through to T1/T2 or refuse
   (D6).
2. Tests (T-UNIT-2): damage k ∈ {1..NR−1} chunks × widths {1 B, 1 KiB,
   full chunk} × entry states {E1 entries, zeroed, hostile}; F1/F2 rows;
   zero-entry records take T1/T2 byte-identically to v1.33.5 (F7 pin).
3. Oracle (T-ORACLE-3): our `r` on multi-damaged reference archives —
   damage patterns: ≥2 words in one chunk; 1 word in each of k chunks —
   byte-exact both.
