# v1.39.1 Remediation Plan

## Priority Order

### P1: H1 — `--durability=batch` silently ignored on parallel path

**Root cause**: `ReaderSlots::init` (main.cpp:701-709) constructs fresh `ArchiveReader` instances that default to `Entry` granularity. `set_durability_granularity` is only called on the main reader (main.cpp:2368). The JSON field and banner report `"batch"` regardless.

**Fix**: Propagate durability granularity to slot readers. Add a `DurabilityGranularity` parameter to `ReaderSlots::init` and call `set_durability_granularity` on each slot reader. Also propagate `decode_threads`, `preserve_suid`, `no_mmap`, and `keep_broken` for consistency (same class of bug).

**Files**: `src/cli/main.cpp` (ReaderSlots::init signature + call site)

### P2: H2 — Test hooks in production code

**Root cause**: `configure_test_failure_hooks()` reads env vars and is called from `set_durability_granularity`. The crash hook calls `std::exit(99)` from the io library layer. No compile-time gate.

**Fix**: Gate behind `#ifdef OPENRAR_TEST_HOOKS` (defined only in test/CI builds via CMake). The hooks become no-ops in production. The env-var reading and `std::exit(99)` are compiled out entirely.

**Files**: `src/io/extraction_journal.hpp`, `src/io/extraction_journal.cpp`, `CMakeLists.txt`

### P3: H3 — ren_iso.cpp stack buffer overflow

**Root cause**: `char fsname[MAX_PATH + 1]` passed as `(LPWSTR)fsname` to `GetVolumeInformationW` which writes up to 260 wchar_t (520 bytes) into a 261-byte buffer. Also unused variables `free_`/`total` cause C4101 warnings.

**Fix**: Change to `wchar_t fsname[MAX_PATH + 1]`, use `wprintf` for output, remove unused variables.

**Files**: `tools/ren_iso.cpp`

### P4: M1 — Durability banner to std::cerr unconditionally

**Root cause**: Banner uses `std::cerr` while surrounding banner uses `(g_json_stdout_only ? std::cerr : std::cout)`.

**Fix**: Use the same conditional as the surrounding banner.

**Files**: `src/cli/main.cpp`

### P5: M2 — Contained journal-create failure leaks journal file

**Root cause**: `register_temp_contained` failure paths close/delete the `LockedFile` but never remove the journal file created by `anchored_create_journal`.

**Fix**: Add `std::filesystem::remove(jpath)` on all failure paths in `register_temp_contained`, matching the path-based `register_temp`.

**Files**: `src/io/extraction_journal.cpp`

### P6: M3 — New k-prefixed constants

**Root cause**: `kBatchJournalLruCap`, `kBatchSyncBoundary`, `kNtFileRenameInformationEx`, `kStatusInvalidParameter`, `kStatusNotSupported`, `kStatusInvalidDeviceRequest` violate CONTRIBUTING rule 6.

**Fix**: Rename to `BATCH_JOURNAL_LRU_CAP`, `BATCH_SYNC_BOUNDARY`, `NT_FILE_RENAME_INFORMATION_EX`, `STATUS_INVALID_PARAMETER`, `STATUS_NOT_SUPPORTED`, `STATUS_INVALID_DEVICE_REQUEST`.

**Files**: `src/io/extraction_journal.hpp`, `src/io/file_stream.cpp`

### P7: L1 — Stale comments

**Fix**: Update comments to match batch-mode reality.

**Files**: `src/io/extraction_journal.hpp`, `src/io/extraction_journal.cpp`

### P8: L2 — Weak tests

**Fix**: Add a test that LRU eviction actually occurs (create >64 journals, verify eviction). Strengthen `test_frozen_surface_absence` to actually exercise the DLL surface or rename it.

**Files**: `tests/unit/extraction_atomic_tests.cpp`
