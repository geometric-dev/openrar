## 1. Design

1. **Injection-gate foundation (M1).** The choke point is the render-time
   idempotent sanitizer (pre-analysis G-A): `sanitize_for_display` is
   idempotent (pinned by test, directive 7), so every name-shaped field
   is sanitized AT RENDER regardless of what the caller did. Gap closures
   (pre-analysis §1.2): archive comment (main.cpp:479) and `lt`
   owner_user/owner_group (main.cpp:535) pass through the sanitizer;
   local-path `W:` lines (main.cpp:1605/1773/1857) sanitize
   `p.string()`/`src_path`; `json_escape` (extraction_report.cpp:5)
   neutralizes invalid UTF-8 bytes as the ASCII escape sequence
   `\uFFFD` (directive 6 — never the raw character), so `--json-summary`
   output is always valid UTF-8 (RFC 8259); VT capability follows the
   SINK (§1.5 below, directive 5). Exception messages that embed entry
   text are fixed at composition (sanitize at insertion), verified by the
   e2e hostile-corpus net (directive 8).
2. **DualProgress renderer (M2).** `src/cli/tui.hpp` replaces the
   CLIProgress render core; the public mutator API is preserved
   (`init/set_totals/start_file/update_bytes/note_file_done/spin/done/
   clear`) so call sites do not churn.
   - **Pure render core:** `render_tui(const TuiState&, int width)` →
     string, no I/O — unit-testable without a terminal. Region ≤ 6 lines:
     badge / OVERALL bar / CURRENT-FILE bar + display name / meta (count,
     ETA, rate) / worker hint. The current-file slot shows the most
     recently STARTED file; the overall bar counts completed bytes only
     (counters never regress).
   - **Single-writer rule (directive 2):** ONLY one thread writes
     terminal bytes and mutates terminal mode. Mutators hold the state
     mutex across their render (the shipped serialization model — every
     writer is the renderer while it holds the lock); a 30 ms tick guard
     inside `render_locked` coalesces bursts. The keyboard thread (§1.4)
     NEVER writes and never touches modes.
   - **Width discipline:** per-render width probe
     (`GetConsoleScreenBufferInfo` / `ioctl(TIOCGWINSZ)`; probe failure →
     80). Every line clamped; name truncation is UTF-8-aware (never
     splits a sequence) with a `…` tail. POSIX SIGWINCH sets a flag →
     next render re-probes (≤ 30 ms); Windows re-probes every render
     (no dedicated event needed — documented). This fixes the shipped
     wrap-garble class (fixed BAR_WIDTH 28 + unwrapped names).
3. **Within-file progress + mid-file cancel (M2).** The reader already
   carries the seam: `ReaderHooks` (archive_reader.hpp:43 — `progress`
   and `cancel`, polled per output chunk ≤ 64 KiB stored, per solid
   flush, per header during open; used today only by the streaming APIs
   and `test_entry_stream`). The plan wires an INSTANCE-LEVEL hook
   setter (`reader.set_hooks(...)`) consumed by the disk-extraction
   path, for the CLI reader and every slot reader (hooks are per-reader;
   slots are exclusive per job — race-free by construction). Progress
   drives the CURRENT-FILE bar (done/total within file — closes the gap
   where a multi-GB file showed no movement); cancel polls the TUI's
   atomic flag so ESC/`q`/`^C` aborts the in-flight file (hook non-zero
   → extraction aborts → temp abandoned, journal sweep handles, entry
   `unprocessed`/`failed`, run exits 255 with JSON `aborted`).
4. **Interactive cancel (M2).** Keyboard thread (started ONLY when the
   renderer is engaged AND stdin is a TTY): Windows `_kbhit`/`_getch`
   loop; POSIX termios raw + `poll()` on fd 0. Reads ESC/`q` → sets the
   atomic cancel flag; EOF → thread exits quietly (cancel stays
   available via `^C`). Terminal mode changes happen on the main thread
   around TUI-active scopes through an RAII `TerminalGuard` (restore on
   every exit incl. exceptions). **PROMPT state (directive 2):**
   `Prog.pause_for_prompt()` clears the region, restores cooked mode,
   parks the keyboard thread (atomic pause flag); `resume()` redraws.
   `ask_overwrite` (main.cpp:2505 — fires mid-run) is wrapped in
   pause/resume. **SIGINT policy (directive 3):** the cooperative
   handler is installed ONLY within TUI-active scopes (POSIX `sigaction`
   flag-setter; Windows `SetConsoleCtrlHandler`) and removed on scope
   exit; `^C` outside the TUI keeps today's terminate semantics (pinned
   by test). Cancel is observed between entries AND mid-file via §1.3.
5. **Non-TTY contract (M3)** (pre-analysis N-A, directive 4):
   - **L1 stdout-not-a-TTY:** renderer never engages — zero VT bytes;
     per-file `Extracting <name> ... OK/FAILED` lines (sanitized names);
     plain `done()`; `W:` lines unchanged; exit codes identical to the
     TTY run for the same archive + flags + STDIN STATE (parity tests
     redirect stdin on BOTH legs).
   - **L2 stdout-TTY, stdin-not:** TUI renders; keyboard thread disabled;
     `^C`/console-close cancels via the signal path. `--json-summary` +
     TTY-stderr edge: capability computed on the SINK (`stderr`) —
     per-file lines suppress, TUI renders to stderr (named contract
     line, tested by wiring).
   - **L3 switches:** `-q`/`-inul`/`-idq`, `-plain`/`--plain`/`-idp`,
     `NO_COLOR`, `TERM=dumb` — behavior as shipped, now PINNED.
   - ONE decision function (directive 5): `is_vt_supported_for(sink)`
     (fd-testable core `is_vt_supported_fd(int)`); every render /
     per-file-line / suppression site consumes it. `p` exemption
     (directive 12): data bytes to stdout are pipe semantics — outside
     the name-render gate like extraction content; verified it prints no
     unsanitized name headers.
6. **Benchmark engine v2 (M4).** `tests/bench/openrar_bench.cpp` grows a
   suite registry `{name, kind(compute|io), unit, fn}` + protocol runner
   (pre-analysis B-A): 1 warm-up + 7 timed passes per suite, result =
   MEDIAN, spread = (max−min)/median. Compute suites carry the <5%
   claim ON A QUIESCENT HOST; I/O suites (50 GB listing) are labeled
   `kind:"io"` and excluded (their corpus build IS the warm-up — no
   extra untimed pass, directive 9). Hardware disclosure: `[bench] host`
   line + JSON `host` object (CPU brand via cpuid/sysctl fallbacks,
   logical cores, OS family, build type + compiler, `steady_clock`,
   passes, warm-up). `--json`: stdout becomes JSON-only (schema_version
   1: host/protocol/suites[{name,kernel,kind,unit,median,passes,
   spread_pct}]), human `[bench]` lines move to stderr (directive 9
   consumer migration — CI steps reading `[bench]` lines run WITHOUT the
   flag, unchanged). `--suite <name>` (repeatable), `--quick` (3 passes),
   `--strict` (spread > threshold → exit 1; quiescent-host-only,
   documented; test hook `--spread-threshold-pct` for determinism).
   New suites: extract_throughput_store / extract_throughput_m3 /
   add_throughput_m3 (deterministic seeded corpus) and
   **cdc_three_number** — rollover item 2: store / plain-solid /
   CDC-packed measured by the engine on the same engineered corpus as
   the unit gate (cli_tests.cpp:1283).

## 2. Constraints & interactions (challenge directives, where each lands)

1. **Engine trace (Pillar 7.2)** — TUI state plumbing traced through ALL
   engines that feed it; every site consumes the ONE decision function:

   | Engine / site | Mutators used | Cancel observed |
   | :--- | :--- | :--- |
   | sequential `x`/`e` loop | start_file, hooks.progress → current-file, update_bytes | between entries + hooks.cancelled mid-file |
   | parallel phase 1 workers | note_file_done (mutex; workers never render) | hooks.cancelled (per-slot reader) |
   | parallel phases 2/3 (slot reader 0) | note_file_done | hooks.cancelled |
   | `t` path | start_file/update_bytes + per-file lines | existing test_stream cancel hook (main.cpp:760) |
   | batch add (`spin` callers, main.cpp:1368–1942) | spin, set_totals, start_file, update_bytes, done | between files (existing) |
   | `l`/`lb`/`lt`, comment, owner lines | direct prints through the sanitizer | n/a |

2. **Two-sanitizer reconciliation (§4.4):** disk name =
   `sanitize_archive_path` (path layer); displayed name =
   `sanitize_for_display` (terminal layer); the `--json-summary` name IS
   the on-disk name (pinned since v1.24, extraction_report_tests.cpp:161).
   The TUI renders the SAME pre-computed `display_name` the report loop
   and prompts use (one computation, main.cpp:2223) — plus the render-
   time re-sanitize. No new name computation is introduced anywhere.
3. **v1.24 parallel guarantees:** untouched by construction — per-entry
   isolation (flags + try/catch), archive-order report, temp-name
   uniqueness (ExtractionSession + journals) have no rendering
   dependency; hooks are per-reader (slots exclusive per job).
4. **Journals/log files:** no archive names in persisted artifacts —
   journal records carry engine-generated temp paths only (verified,
   extraction_journal.hpp:67–68). The machine artifacts are
   `--json-summary` (M1 UTF-8 gate) and bench `--json` (new, engine-
   generated content). Directive confirmed.
5. **Exit taxonomy:** no new exit codes; cancel → 255 (user-break),
   `--strict` bench failure → the TOOL exits 1 (tool contract, not the
   archive CLI's taxonomy — the CLI binary is untouched by bench flags).
6. **Timestamps/encryption/solid/-cdc/-oi/-v interactions:** none —
   rendering and measurement only; hooks ride existing extraction flow.
