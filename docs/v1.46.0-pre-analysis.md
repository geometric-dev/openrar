## 0. Gate 0 Statement & Re-Chartering (M0)

### 0.1 The v1.43 Ratio Attribution Verdict
The ratio attribution census in v1.43 (§7.1 M2 Axis 2) conclusively measured that **dictionary reach is off-axis for closing the ratio gap to the reference implementation**:
- On text and heterogeneous corpora (`big24.bin`, 26.85 MiB), `-md` sweeps above 1 MiB proved flat: at identical declared 8 MiB windows, OpenRAR still trailed WinRAR by 3.65% (m3) and 1.97% (m5).
- The residual gap was localized to match length distribution and arbiter candidate-pricing (A-6), not dictionary reach.
- Small dictionaries (128 KiB) on local-redundancy data are actually slightly smaller than 64 MiB because they avoid expensive, wide distance slots.

**Chartering Principle:** Per the §7.4 charter rule (*"consume v1.43's attribution; off-axis → stop and re-charter memory-only"*), `-md=auto` is chartered around **memory footprint, cache efficiency, and consumer-side decode cost**, rather than ratio breakthrough.

### 0.2 Invariant G-3: Cross-Host Determinism (No RAM Input)
- **Hard Constraint:** `resolve_auto_dict` MUST NOT read host physical memory or system status (e.g., `sysconf`, `GlobalMemoryStatusEx`, `get_phys_pages`).
- Sizing is a pure, deterministic function: `f(method, input_size) -> window_size`.
- The exact same input stream compressed with the same method on a 512 MiB VM, a 16 GiB laptop, or a 128 GiB server **must produce byte-identical archives** (`_cross_host_identical` gate).

## 1. Current State & Delta Audit (Delta Work — Verify, Don't Build)

1. **CLI Switch Parsing (`src/cli/main.cpp:3813–3901`):**
   - Current behavior: parses unit suffixes (`k, m, g, t`) and parses numerical values via `std::stod(tail)`.
   - Current defect: passing `-md=auto`, `-mdauto`, or `-md:auto` causes `std::stod` to throw/fail, exiting with `Error: invalid dictionary size '-md=auto'` (code 7).
   - Delta work: normalize delimiters (`=`, `:`) and case-insensitively match `auto`. Set `opt_dict_auto = true`.

2. **Method Table Defaults (`src/compress/compress_plan.hpp:11–28`):**
   - Method defaults (`default_dict_size_for_method`): m0 = 128 KiB, m1 = 512 KiB, m2 = 1 MiB, m3 = 8 MiB, m4 = 16 MiB, m5 = 64 MiB.
   - Legacy scale (I-5, `:38`): `1..15` is `128 KiB << (dict_size - 1)`. `0` = method default. `> 15` = exact bytes.
   - FCI snap (`:63`): power-of-two base + 32 discrete fractional steps.

3. **Per-File Pow2 Clamp Today (`src/archive/archive_mutator.cpp:1264–1270, :3255–3261`):**
   - Existing logic in `prepare_add_file` and `add_file_to_archive_vol`:
     ```cpp
     if (dict_size == 0 && !is_solid && method > 0 && file_sz > 0) {
         core::uint64 file_pow2 = 0x20000ULL; // 128 KiB floor
         while (file_pow2 < file_sz && file_pow2 < win_size) {
             file_pow2 <<= 1;
         }
         win_size = std::min(win_size, file_pow2);
     }
     ```
   - Crucial limitation: this logic only ever **shrinks** (`std::min`), never expands above method default for large files.
   - Under `-md=auto`, the resolver must scale up to method-specific ceilings for large inputs.

4. **RAR7 Non-Power-of-Two Emission:**
   - Already shipped and verified (`OPENRAR_ABI_FEATURE_DICT_EX`, bit 12 in `openrar_dll.h:103–104`).

## 2. Decision Function: `resolve_auto_dict` (M1 & M2)

### 2.1 Specification & Sizing Curves
The single decision function lives in `src/compress/compress_plan.hpp`:
```cpp
inline uint64_t resolve_auto_dict(uint32_t method, uint64_t input_size);
```
Sizing rules:
1. **Floor:** `128 KiB` (`0x20000ULL`) minimum (RAR5 format lower bound).
2. **Small-Input Branch (`input_size < default_dict`):**
   - Round `input_size` up to the next power of two:
     $$W_{small} = \max(128\text{ KiB}, \text{round\_up\_pow2}(input\_size))$$
   - Capped at `default_dict_size_for_method(method)`.
3. **Large-Input Branch (`input_size >= default_dict`):**
   - For compression methods m2..m5, allow the dictionary to expand with larger inputs up to strict method ceilings:
     - **m0:** Fixed 128 KiB.
     - **m1:** Fixed 512 KiB (fastest method preserves throughput).
     - **m2:** Default 1 MiB; input $\ge 4\text{ MiB} \rightarrow 2\text{ MiB}$ ceiling.
     - **m3:** Default 8 MiB; input $\ge 32\text{ MiB} \rightarrow 16\text{ MiB}$; input $\ge 128\text{ MiB} \rightarrow 32\text{ MiB}$; ceiling = 64 MiB.
     - **m4:** Default 16 MiB; input $\ge 64\text{ MiB} \rightarrow 32\text{ MiB}$; input $\ge 256\text{ MiB} \rightarrow 64\text{ MiB}$ ceiling.
     - **m5:** Default 64 MiB; input $\ge 256\text{ MiB} \rightarrow 128\text{ MiB}$; input $\ge 1\text{ GiB} \rightarrow 256\text{ MiB}$ ceiling.
4. **FCI Grid Alignment:**
   - Output passes `snap_window_to_fci_grid(win)`.
5. **Precedence Hierarchy (M2):**
   - `-md<size>` explicit value overrides `auto`.
   - `-md=auto` activates dynamic auto-sizing (`resolve_auto_dict`).
   - Omitting `-md` defaults to `opt_dict_size = 0` (legacy default: method default with pow2 file clamp).

## 3. Engine Trace Across All Execution Modes

| Engine | `auto` Behavior | Invariant / Discipline |
|---|---|---|
| **CLI Batch (Spool & Direct-Stream)** | Resolved at plan time from `stat`-queried `file_size` via `resolve_auto_dict(method, file_size)`. | Deterministic per-file sizing. |
| **Solid Session** | Chain-aggregate input size calculated up-front across all non-dir members (`run_bytes`). Window = `resolve_auto_dict(method, run_bytes)`. | Single window covers entire chain; shrink-or-equal (I-6). |
| **Multi-volume (`archive_mutator.cpp`)** | Resolved per member via shared `resolve_auto_dict(method, file_size)` snapped to FCI grid. | Exact agreement with non-volume paths; solid continuations never grow. |
| **WASM (`archive_api.cpp`)** | Input `window_log2` mapped [1..4] (128k..1M); clamp reported in diagnostics if requested larger. | Strict memory ceiling for browser sandboxes. |
| **Streaming (`StreamEncoder`)** | Non-causal: total size unknown. Resolves to standard method default at chunk 0, never renegotiated. | Non-causal; prevents mid-stream window rupture. |
| **`cv` (Transcode / Convert)** | **Refused** (`main.cpp:4266–4268`). Emits `Error: cv does not support -md=auto` with exit code `EXIT_USAGE`. | Refuses output-shaping flags to avoid transcode divergence. |
| **C ABI (`openrar_dll.h`)** | `dict_size == 0` maps to auto-sizing. `OPENRAR_DICT_AUTO` aliased to `0`. | ABI backwards compatibility. |

## 4. Consumer-Side Window Cost (M5 / OPT-D01)

### 4.1 The Overhead in Shipped Code
In `archive_reader.cpp:2205–2208` and `decompressor50.cpp:312`:
- A 1 KB member inside an archive created with `-md1g` passes `win = 1 GiB` to `Decompressor50`.
- The decompressor allocates and commits address space based on `win`.
- `WindowBuffer::grow_to` calls `vec_.resize(n)`, zero-filling memory unnecessarily.
- Peak commit charge for extracting 10,000 tiny members in a large-dict archive spikes to gigabytes.

### 4.2 M5a: Single Fill & C++17 Uninitialised Allocation
- `CMAKE_CXX_STANDARD` is 17; `std::make_unique_for_overwrite` is C++20 and cannot be used.
- Sanctioned C++17 primitive: define a `default_init_allocator<core::byte>`:
  ```cpp
  template <typename T, typename A = std::allocator<T>>
  struct default_init_allocator : A {
      using A::A;
      template <typename U> struct rebind { using other = default_init_allocator<U, typename std::allocator_traits<A>::template rebind_alloc<U>>; };
      template <typename U> void construct(U* ptr) noexcept(std::is_nothrow_default_constructible<U>::value) {
          ::new (static_cast<void*>(ptr)) U; // default initialization (leaves primitives uninitialized)
      }
      template <typename U, typename... Args> void construct(U* ptr, Args&&... args) {
          std::allocator_traits<A>::construct(static_cast<A&>(*this), ptr, std::forward<Args>(args)...);
      }
  };
  ```
- Use `std::vector<core::byte, default_init_allocator<core::byte>>` in `WindowBuffer`. Resizing avoids zero-filling pages on the heap.

### 4.3 M5b: Clamping Allocation Window vs. Declared Window
- For **non-solid** members with known `unp_size`:
  $$W_{alloc} = \min(W_{declared}, \text{round\_up\_pow2}(\max(unp\_size, 128\text{ KiB})))$$
- **Field Decoupling in `Decompressor50`:**
  - `declared_win_`: used for table flavor selection (RAR7 446 symbols vs RAR5 430 symbols), `ALLOC_LIMIT` checking, and parallel decode qualification.
  - `alloc_win_`: used for physical ring allocation, wrap-around modulo (`wrap_up`), contiguous copy clamps, and distance checks.
- **Corrupt-Stream Oracle Verdict:**
  - Distances $W_{alloc} < d \le W_{declared}$ fail closed as `InvalidInput` in `copy_match`.
  - In a valid stream, all distances are bounded by uncompressed bytes produced so far ($d \le unp\_size \le W_{alloc}$). UnRAR 7.20 cross-verification confirms identical error verdicts on crafted corrupt streams.

## 6. Negative-Test & Verification Plan

1. **`test_boundary_matrix`:**
   - Test files exactly at 128 KiB, 512 KiB, 1 MiB, 8 MiB, 16 MiB, 64 MiB, and $\pm 1$ byte boundaries across methods 1, 3, 5.
2. **`test_cross_host_identical`:**
   - Assert SHA-256 of generated archive is identical regardless of CPU core count or platform.
3. **`test_legacy_scale_precedence`:**
   - Verify `-md8` produces 16 MiB (legacy scale), `-md8m` produces 8 MiB, and `-md=auto` triggers dynamic sizing.
4. **`test_decode_window_tracks_member`:**
   - Generate archive with 1,000 $\times$ 1 KB files with `-md1g`. Verify peak commit charge on Windows does not exceed 32 MiB.
5. **`test_decode_flavor_follows_declared`:**
   - Archive declaring $>4\text{ GiB}$ dictionary with a small 10 KB payload decodes cleanly with 446-symbol tables.
6. **`test_decode_clamp_corrupt_verdicts`:**
   - Fuzz/craft invalid distance streams and assert fail-closed rejection matching UnRAR 7.20.
