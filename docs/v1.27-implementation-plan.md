# v1.27.0 Implementation Plan — Extended Attributes, Quarantine & MotW (Gate 0 Cleared)

**Status:** governing plan for the v1.27.0 arc. Gate 0 format-legality
review complete (docs/v1.27-pre-analysis.md §7: conditional approval, ten
directives — all folded into THIS revision: §2 constraints, §3 FMM, §6
test plan). Normative inputs: SECURITY_ARCHITECTURE §4.3 (MotW local
generation; ownership/mode policy as shipped), §3.1 (exit taxonomy),
§5.4 (limits), docs/ROADMAP.md §v1.27.0.

**Honest scope statement:** the format surface is ONE new extra-record
type (0x08), opt-in via `-ox`, skipped without error by every stock RAR5
reader (spec §5 contract, verified against unrar `headers5.hpp` and
bitplane/rar-research). MotW propagation (`-oz`) emits NOTHING into the
archive — it is an extraction-side policy keyed on the archive file's own
filesystem metadata, with content generated locally (§4.3). The shipped
Zone.Identifier-via-`-os` residue is CLOSED in this arc (pre-analysis
Design Z-B).

## 1. Design

1. **Format layer** (`src/format/headers.hpp`, `header_reader.cpp`,
   `header_writer.cpp`): `FHEXTRA_XATTR = 0x08`.
   `FileBlock::xattrs` — `std::vector<FileXattr>` of `{name, value}`
   (name = full xattr name INCLUDING namespace prefix; value = opaque
   bytes). Record: `Size vint, Type vint(0x08), Flags vint(=0),
   Count vint`, then per attribute `NameLen vint (1..255), Name,
   ValueLen vint (0..65536), Value`. Parse branch in the extra-area
   loop (header_reader.cpp:868 fallback is the malformed destination);
   writer branch before the unknown re-emit (header_writer.cpp:393).
   **Malformed ⇒ verbatim unknown-extra capture, never an abort, never
   a partial parse** (flags≠0, NameLen 0/>255, ValueLen > 65536,
   length/count overrun, duplicate names).
2. **io layer** (`src/io/posix_xattr.{hpp,cpp}`): `list_xattrs` /
   `get_xattr` / `set_xattr` using the `l`-variants only
   (flistxattr/lgetxattr/lsetxattr; macOS `extattr`-equivalents via the
   same xattr(2) family). Windows translation unit compiles empty —
   capture/restore are platform-gated, the FORMAT layer is
   cross-platform (records parse and re-emit on every OS).
3. **Capture side (`-ox`)** (`archive_mutator.cpp` `prepare_add_file`,
   `prepare_add_dir`, `prepare_add_filecopy`): read source xattrs,
   namespace allow-list: `user.*`, `security.*`, `trusted.*`,
   `com.apple.metadata.*`; EXCLUSIONS (verbose report, never stored):
   `system.*` (POSIX ACLs stay with the `-ow` ACL path — no side
   door), `com.apple.quarantine`, `com.apple.provenance` (provenance —
   Design Z-A territory), `com.apple.ResourceFork`,
   `com.apple.FinderInfo`, `com.apple.decmpfs` (deferred to 2.1).
   Writer-side caps: value ≤ 64 KiB, name ≤ 255 bytes, total ≤ 1 MiB
   per file, count ≤ 4096 — over-cap attributes skipped with report,
   never truncated. Attributes sorted by name (deterministic bytes,
   Pillar 7.8). **Redir entries (symlink/hardlink) capture NO xattr
   records** (an extracted hardlink IS the master's inode — a record
   would re-apply onto shared inode state); FILECOPY refs capture their
   own source's. `-ox` on Windows: accepted, no-op capture.
4. **Restore side** (cli/main.cpp `restore_children` — the ONE lambda
   shared by the sequential and parallel engines, main.cpp:2482 /
   2554 / 2590 / 2613; dirs via `apply_deferred_dir_metadata`
   archive_reader.cpp:299): post-commit apply on the committed path
   (the chmod/chown/STM pattern). Restore allow-list: `user.*` +
   `com.apple.metadata.*` always; `security.*`/`trusted.*` only with
   the new `--xattr-security` admin opt-in (the `--preserve-suid`
   model); everything else never restored. Per-attribute failure
   (EPERM/ENOTSUP/ENOSYS) → non-fatal `W:` line, entry status
   unchanged. DLL/WASM apply surfaces out of scope v1 (consistent with
   STM/ACL); C ABI unchanged.
5. **MotW `-oz`** (cli/main.cpp extract path): probe the ARCHIVE file's
   own filesystem metadata once per session — Windows: the archive's
   `:Zone.Identifier` ADS via io::read_alternate_streams (ZoneId value
   only; malformed/out-of-range ⇒ fail-safe 3; parse input bounded at
   64 KiB); macOS: `com.apple.quarantine` on the archive (flag byte
   only). Propagation: fresh content written per extracted FILE
   post-commit — Windows constant `[ZoneTransfer]\r\nZoneId=N\r\n`
   (NEVER any HostUrl/ReferrerUrl pass-through); macOS quarantine value
   generated locally (flag byte from the archive, fresh timestamp +
   UUID + agent). Redirs excluded; FILECOPY-materialized files
   included; multi-volume probes volume 1 only. **Never remove or
   downgrade an existing mark; unmarked archive ⇒ zero writes.**
   Default ON (fail-safe direction, WinRAR 6.23+ parity); `-oz-`
   disables; `-oz` explicit enable. JSON flag `motw_propagated` +
   stderr line per file.
6. **Zone-stream policy closure:** `-os` capture excludes
   `:Zone.Identifier` (win32_meta.cpp / mutator filter — provenance is
   not content; the README `-os` row is amended in the same milestone);
   extraction skips any zone-named STM child — case-insensitive match
   AFTER `:$DATA`-suffix normalization of the SUBDATA name — with
   `zone_stream_skipped` JSON flag + `W:` line, regardless of producer
   (fail-safe against WinRAR-produced archives, whose `-os` stores real
   zone streams; WinRAR's own "restore if more secure" algorithm is a
   documented, deliberate divergence — pre-analysis §1.6).

## 2. Constraints & interactions (challenge directives, where each lands)

1. `-oz`/`-oz-`/`-ox` register BEFORE the `-z` prefix branch
   (main.cpp:3245 `sw_starts("-z")` would swallow `-oz` as comment-file
   "z" — verified); both join the switch-parity list (cli_tests.cpp:448).
2. Zone-skip normalization (directive 2) — restore-side name check in
   restore_children; tested with variant-named crafted children.
3. Zone value contract (directive 3) — content constant pinned by
   `motw_hosturl_never_copied`.
4. Propagation scope (directive 4) — files only, volume 1 only, one
   probe per session.
5. Redir metadata rule (directive 5) — capture skips redirs;
   `prepare_add_hardlink`/`prepare_add_symlink` untouched.
6. Engine trace (directive 6) — anchors named in §1.4; hostile-record
   test runs under BOTH scan engines (io::ReadSource seam — the scan
   path is shared; test parameterizes mapped/buffered).
7. Solid/`-cdc`/`-oi`/`-v` interactions: none — the record adds no data
   area; headers never enter the LZ window (pre-analysis §1.5).
8. Timestamps/encryption: unaffected; 0x08 rides in the (possibly
   encrypted) header like every extra record.

## 3. Failure-Mode Matrix

Phases: P = format parse (0x08), C = capture (`-ox`), R = restore,
Z = zone (`-oz` + STM skip). Classes: crafted input, OOM/cap,
privilege, FS-without-xattr-support, cancel.

| Phase \ Class | crafted | OOM/cap | privilege | FS-without-xattr | cancel |
| :--- | :--- | :--- | :--- | :--- | :--- |
| P | malformed ⇒ verbatim capture, never abort, never misparse (both engines) | bounded by 2 MiB header cap + field caps; no unbounded alloc | n/a | parse is OS-independent | n/a (scan-time) |
| C | allow-list + name/value validation; zone/provenance namespaces excluded | over-cap attribute skipped + report, never truncated | `trusted.*` read EPERM ⇒ skip + report, add succeeds | empty xattr list ⇒ no records, add succeeds | existing batch cancel unchanged |
| R | restore allow-list; policy names never setxattr'd | same caps on read; oversized ⇒ skip + report | EPERM/EPERM-class ⇒ fail-soft `W:`, entry stays `extracted` | ENOTSUP/ENOSYS ⇒ fail-soft `W:` | post-commit, sub-ms — n/a |
| Z | normalized zone-name skip; pinned generated content; never strip an existing mark | archive ADS parse input bounded 64 KiB | mark write EPERM ⇒ fail-soft, file already committed | no ADS/xattr support ⇒ no-op | n/a |

## 4. CLI surface

- `-ox` — save extended attributes (add side; files + dirs; redirs
  excluded; Windows no-op).
- `-oz` / `-oz-` — MotW propagation at extraction (default ON; `-oz-`
  disables). No add-side emission (documented).
- `--xattr-security` — additionally restore `security.*`/`trusted.*`
  (admin opt-in, the `--preserve-suid` documentation pattern).
- JSON: `motw_propagated`, `zone_stream_skipped` (extraction report).

## 6. Named Negative Tests

1. `xattr_roundtrip_self` (M2/M3) — `-ox` roundtrip preserves `user.*`
   xattrs byte-identically on files and dirs (WSL ext4; probe-then-skip).
2. `xattr_malformed_captured_verbatim` (M1) — every malformed 0x08 shape
   (flags≠0, bad lengths, overrun, duplicate names) captures verbatim,
   survives mutation byte-identically, extraction proceeds.
3. `xattr_hostile_record_no_alloc_beyond_caps` (M1) — crafted oversized
   records parse under both scan engines, no allocation beyond header
   caps, verbatim-preserved.
4. `xattr_caps_enforced_store` (M2) — a >64 KiB value is skipped with
   report; the add succeeds; never truncated.
5. `xattr_system_namespace_never_captured` (M2) — `system.*` names
   excluded at capture even with `-ox` (ACL side door closed).
6. `xattr_security_namespace_not_restored_by_default` (M3) —
   `security.*` stored with `-ox` is NOT restored without
   `--xattr-security` (policy gate asserted; syscall-level effect
   probed-then-skipped).
7. `zone_stream_never_restored` (M4) — crafted + WinRAR-shaped
   `:Zone.Identifier` STM children (incl. case/`:$DATA` variants) are
   skipped with `zone_stream_skipped`; the extracted file's zone is
   untouched.
8. `os_excludes_zone_at_capture` (M4, Windows) — source with a real
   Zone.Identifier + `-os` ⇒ no zone stream stored.
9. `motw_propagated_from_archive_ads` (M4, Windows) — marked archive ⇒
   extracted files carry freshly generated marks.
10. `motw_hosturl_never_copied` (M4, Windows) — archive ADS with
    HostUrl/ReferrerUrl ⇒ extracted content is exactly
    `[ZoneTransfer]\r\nZoneId=N\r\n`.
11. `motw_disabled_by_flag` (M4, Windows) — `-oz-` ⇒ zero writes;
    unmarked archive ⇒ zero writes; never strips an existing mark.
12. `macos_quarantine_value_format` (M4, macOS leg) — generated
    quarantine value shape (compile-gated elsewhere).
13. `filecopy_debits_caps` (M5) — `-oi` archive + `max_total_output_bytes`
    ⇒ FILECOPY materialization debits and aborts at the cap (§5.4
    parity with the EXDEV hardlink fallback).
14. `oi34_no_archive_no_dispatch` (M5) — `-oi3`/`-oi4` exit path runs no
    `-rr`/`-k` dispatch against the nonexistent archive.
15. `switch_parity` additions (M4) — `-ox`, `-oz`, `-oz-`,
    `--xattr-security` accepted, no unknown-switch warning; `-oz` NOT
    parsed as a comment file.
16. `winrar_skips_xattr_records` (M5, Track 10) — local WinRAR/UnRAR
    list+extract an `-ox` archive byte-identically (CI: self-roundtrip).
