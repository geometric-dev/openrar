# OpenRAR v2.3.0 Implementation Plan — Independent Principal Architect Challenge

**Subject:** [`docs/milestones/v2.3.0-implementation-plan.md`](../milestones/v2.3.0-implementation-plan.md) (amended plan of record; D-1 through D-8 discharged)
**Reviewer posture:** Independent Principal Systems & Solution Architect — adversarial, pre-implementation
**Method:** Trace every plan claim through the shipped tree at HEAD (`162300a`), the build/test surface, and the governing invariants (`docs/invariants.md`, `docs/v2.0-charter.md`, `docs/milestones/v2.2-v2.4-roadmap.md`, `docs/reviews/review-master-plan.md`).
**Date:** 2026-11-08
**Verdict as found:** 🔴 **REVISE & RESUBMIT (CRITICAL DEFECTS)**

---

## 1. Verdict and Core Posture

The architectural thesis is sound: complete the VM-reserved window work, remove heap churn from the decompression hot path, fail closed on filter saturation, and gate every SIMD experiment behind a kill switch. The amended plan also correctly re-scoped W1 against HEAD and repaired the worst factual drift from the first adversarial pass.

However, this independent challenge finds that the amended plan is **not implementable as written** — not because the direction is wrong, but because W1's core mechanics contradict the shipped lazy-commit window design, the fixed filter-queue/scratchpad sizing violates the plan's own I-6 and the recorded RAM-ceiling invariant, and the zero-allocation proof is unsatisfiable against the real `StreamDecoder` API. Separately, W3's ratio mechanisms directly contradict invariant I-1's "bit-for-bit identical digests" rule, and the release gate does not enumerate the project's actual verification legs.

On the question "will it compile, run, and survive hostile input?", the verdict is **🔴**. The closing gate was re-opened.

## 2. Critical Red Flags & Fatal Flaws

1. **W1's commit policy is self-contradictory — it is either an access violation or a memory-DoS regression.**
   - Plan §2.2 said "the full dictionary capacity is **committed immediately**"; the mermaid said `cap_ = win_size (Full Ring Ready Up Front)`; Step 1.2 said "make `grow()` a no-op on VM-reserved windows".
   - Reality: `WindowBuffer::init` reserves address space with `VirtualAlloc(..., MEM_RESERVE, PAGE_NOACCESS)` (`src/compress/decompressor50.cpp:384`), commits pages only in `grow_to()` (`:401`, `MEM_COMMIT` at `:421`), and the engine starts at `grow_to(min(win_size_, INITIAL_WINDOW))` (`:455`). `reserve()`/`grow()` are the only commit path (`decompressor50.hpp:538-542`).
   - If `cap_` is set to `win_size_` while commit stays lazy, `reserve()` returns true early and `write_literal`/`copy_match` write into `PAGE_NOACCESS` → immediate access violation. If "committed immediately" is taken literally, a hostile 64 GiB declared window commits 64 GiB at init, destroying the shipped "hostile 64 GiB declaration allocates kilobytes" property (`decompressor50.hpp:491-499`) and violating I-6/I-15 §2. Both readings are unacceptable. The correct design is: logical ring capacity = `win_size`; physical commit stays lazy; `grow()` never *reallocates* but must still commit the next range. *(Resolution: D-9 applied, plan §2.2.1.)*

2. **The fixed filter queue is a 2 MiB inline member — plus 2 MiB of scratchpads — per decoder instance.**
   - `FilterEntry` is 32 bytes (`decompressor50.hpp:139-145`). `FilterEntry ring_[65536]` = **2,097,152 bytes inline** in `ApplyEngine`, inside `Decompressor50`, inside `StreamDecoder` (`stream_decoder.hpp:85`). Pre-allocating both scratchpads to 1 MiB adds 2 MiB of heap per instance.
   - This violates I-6's stated **1.5 MiB WASM total budget** and `docs/invariants.md` §2's "dictionary window + ≤256 KiB slice" RAM ceiling. Worse, `StreamDecoder dec(win, method);` is stack-allocated in existing tests (`tests/unit/stream_decoder_tests.cpp:78,108`); a 2 MiB inline array overflows the default 1 MiB Windows stack. Critical. *(Resolution: the 1.5 MiB figure is the WASM static/module budget, not a working-set ceiling; the plan records the dynamic filter accounting in I-16, compacts `FilterEntry` to 24 B (1.5 MiB worst case), and allocates the ring lazily on the heap — D-10. Plan §2.2.2, `docs/wasm-limitations.md` §4.3.1.)*

3. **The zero-allocation proof cannot pass against the real `StreamDecoder`.**
   - `StreamDecoder` stages input in `in_queue_` (`stream_decoder.cpp:69,74` `insert`) and retains output in `output_` (`:89` `insert`); `finish(std::vector&)` appends to the caller vector. The plan's snippet wrapped `feed`/`finish` in `ScopedAllocTracker` with no flush sink, no `restored.reserve(...)`, and no pre-warmed `in_queue_`, then asserted `alloc_count() == 0`. It will count allocation on the first `output_.insert` (and on the caller vector).
   - M-08 zero-copy work (input staging removal) was **not scheduled in any v2.3 chunk**, so the claimed "full internal call graph" zero-alloc invariant was unreachable. The tracker sketch was also incomplete: no global `operator new` hook, no `inline static thread_local` definitions, and the ctor/dtor pattern broke under nesting. *(Resolution: inspection shows M-08 is partially landed at HEAD; the residual tail staging is scheduled as Step 1.5 with `reserve_staging()`, and the claim is qualified per the §2.3.4 matrix — D-12.)*

4. **Invariant I-1 contradicted W3, and H-19's gate was weaker than I-1.**
   - Plan I-1: "Every compression optimization must maintain **bit-for-bit identical SHA-256 archive digests** across all 30 deterministic cells." W3 (H-22…H-25) explicitly changes match/literal selection to improve ratio — a win *must* change digests. H-19's gate said "zero size or digest **regression**", which would accept a changed-but-smaller stream while violating I-1.
   - W3 must be governed by I-13 (ratchet) with an explicit re-baseline procedure; I-1 must be scoped to behavior-preserving W2 work and H-19 must require **digest identity**.

5. **Release Step 4.1 was invalid in this tree, and the release gate was incomplete.**
   - `ctest -N` in the existing build tree reports **0 tests**; CTest registration lives in `cmake/openrar_tests.cmake:44` (`add_test`) and requires a tests-enabled configure. "55 registered targets pinned via `ctest -N` at HEAD `162300a`" was unverified (historical counts: 52/53/54/56/49/55/47).
   - Step 4 omitted static analysis (Clang-Tidy / MSVC `/analyze`), fuzz legs, ABI gates (`abi_layout_tests`, `abi_export_parity`, `js_error_mirror_parity`, `dll_tests`, `wasm_api_tests`), `anchor_lint`/`layer_check`, and a CHANGELOG contract with anchors.

6. **Component and citation drift remained.**
   - `src/compress/bitwriter.hpp` **does not exist** (`BitOutput` is `compressor50.hpp:17`; `BitReader` is `decompressor50.hpp:16`; `HuffmanDecoder` is `decompressor50.hpp:54`).
   - H-21 cited `compressor50.cpp:450-550` for `find_match`; the definition is at **`compressor50.cpp:1219`** (`find_match_impl` at `:760`). That range is `begin_archive`/`normalize_window_size`/`begin_stream`.
   - H-18 targeted `match_simd.hpp`/`match_avx512.cpp`, which are **match-comparison** kernels (compressor side); decompression wildcopy lives in `decompressor50.cpp` `copy_match`.
   - `_bextr_u64` (BEXTR) is **BMI1**, not BMI2 — CPUID dispatch and the platform-fallback plan must check the correct feature bit.

## 3. Weak Assumptions & Fragile Invariants

- **"Full capacity up front" was treated as free.** It is not: it converts O(decoded output) peak memory into O(declared window), re-opening hostile-header memory DoS and defeating the lazy-commit design the plan says it preserves.
- **I-15 margin vs. geometry.** `WindowBuffer::init(win_size + 64)` in the mermaid conflated allocation capacity with the logical dictionary. If `win_size_` (mask, wrap, distance checks, cadence) becomes `win_size + 64`, distance checks and `flush_cadence()` silently drift. The margin must be capacity-only.
- **Zero-alloc scope.** `std::function` output callbacks are constructed per block (`decompressor50.hpp:225`), and `last_error_str_` is a `std::string`; the plan excluded error strings but not callback/staging allocations.
- **GFNI half-width.** The optimization assumes the affine transform has a zero constant term (`aff(0,m)=0`). If the kernel uses a non-zero GFNI immediate, the "half-width" result is wrong. Also, "half-width symbols" is data-dependent; the 2% end-to-end gate on a 55 GiB/s kernel is unlikely to trigger, and the sparse-detection cost is not modeled.
- **NEON `pmull` is already refuted** by the roadmap design note. Re-running it is optional science, not a v2.3 deliverable — and the plan still has no G-9 rule for unavailable Apple Silicon/QEMU hardware ("blocked" must not be reported as "pass").
- **H-19 SIMD gather.** `_mm256_shuffle_epi8` is lane-local; gathering eight overlapping 4-byte windows from a 32-byte load needs `vpermd`/two shuffles plus blends, not the single shuffle described. The hash must remain `load_le32`-equivalent on every host (C-07 is still open for this function), and SIMD output must be bit-identical to scalar *hashes*, not merely size-neutral.
- **H-20 measurement.** "≥10% branch-misprediction reduction" is a proxy, not a throughput gate; branchless decode can increase L1 table pressure. Gate on cycles/byte or throughput and keep branch-miss as diagnostics.
- **H-21 "dual-track".** Prefetching candidate N+1 requires first loading `prev_[cand]` (a dependent load), so a naive prefetch serializes. The plan must define the two independent chains and node layout.
- **W3 arbiter inputs.** "Zero static distance concessions (k)" and the four-binary set remained undefined, so the gate could not be adjudicated.
- **Test-count pin.** The "55" figure was asserted, not mechanically verified; Step 4.1 must configure `-DOPENRAR_BUILD_TESTS=ON` and run `ctest -N`.

## 5. High-Performance & Mechanical Sympathy Gaps

- **Per-instance fixed memory was the dominant regression.** A 2 MiB inline ring + two 1 MiB scratchpads is 4 MiB per decoder even when the archive has no filters. For a 64 KiB window that is ~13× the dictionary. Fix: lazily allocate/pool the ring on first filter; size scratchpads to the actual block and cap at 1 MiB; keep the object small and heap-owned, with `static_assert` on object size.
- **Zero-copy staging was missing.** `in_queue_.insert`/`output_.insert` and `erase` (`stream_decoder.cpp:69,74,89,102`) are the real hot-path churn. M-08 (decode complete blocks directly from the caller buffer, queue only the tail, hoist the callback) must be in Chunk 1 or the zero-alloc claim must be scoped to `Decompressor50` with a sink.
- **Ring queue correctness.** `push`/`pop` assume a power-of-two capacity (`ring_[tail_ & (Capacity-1)]`); add `static_assert`. Specify peek-vs-pop (`has_completed_filter` peeks; `flush_pending` pops) and the `filters_head_`/erase removal across every `ApplyEngine` call site.
- **H-19 hash equality.** The current kernel is a rolling 4-byte `load_le32` hash (`compressor50.cpp:701-707,721-746`). Preserve exact values; add a scalar-vs-SIMD differential test and a big-endian guard (C-07).
- **H-21 node layout.** `prev_`/`head_` are index arrays; two-track prefetch requires two independent chain heads. Without that, the 4% gate is aspirational.
- **H-20 table pressure.** A branchless 2-level table increases L1 footprint; measure cycles/byte, not only branch misses.

## 6. Omissions, Edge Cases & Recovery Gaps

- **Failure-mode matrix + negative tests** for: hostile 64 GiB header/tiny payload (peak memory must stay kilobytes); 65,537th pending filter → `LimitExceeded`, then `reset()` reusability; tail overshoot at `win_size-1`; filter spanning block/call boundaries; solid-member reset preserving history; 32-bit shift UB; big-endian hash; unavailable benchmark hardware; OOM on `VirtualAlloc` reserve/commit and on vector fallback; cancellation mid-decode.
- **I-6/WASM proof**: 1.5 MiB budget cannot coexist with a 2 MiB ring; the plan must either shrink/relocate the queue or re-baseline I-6 explicitly (and that re-baseline must be recorded).
- **Stack safety**: `StreamDecoder` stack objects in existing tests + 2 MiB inline ring = stack overflow; require heap allocation or a compile-time size assertion.
- **C ABI/WASM error conformance** for `LimitExceeded`: name `dll_tests`, `wasm_api_tests`, `js_error_mirror_parity`.
- **Invariant scoping**: I-1 vs W3; I-13 ratchet re-baseline procedure (`RATCHET_BYTES` update, golden digest refresh, guard re-run) on W3 wins.
- **Release contract**: CHANGELOG bullets with anchors; `anchor_lint`, `layer_check`, static analysis, fuzz, ABI gates, interop, regression guard; `ctest -N` count pin.
- **Document accuracy**: fix `bitwriter.hpp`, `find_match` line, wildcopy component, BMI1/BMI2 label; confirm `MAX_RETAINED_FILTER_SCRATCH` is a local constant (`decompressor50.cpp:719`), not a public symbol; the §0.2 primer's "64 MiB / 1 GiB" window range is narrower than `ALLOC_LIMIT` (64 GiB) and `SPEC_MAX_V1` (1 TB).

### 9.1 Evaluation of Blocking Directives (D-9 through D-12)

1. **AC-1 / D-9 (W1 Commit Semantics): DISCHARGED.**  
   - Logical window geometry (`win_size`, `win_mask`, distance checks, `flush_cadence()`, and archive headers) remains decoupled from physical commitment (`cap_`).
   - Lazy commit is preserved: address space is reserved up-front for `win_size + 64` (Invariant I-15 capacity-only margin), committing page granules dynamically via `VirtualAlloc(MEM_COMMIT)` / `mprotect(PROT_READ|PROT_WRITE)`.
   - `grow()` commits the next granule without reallocation. The erroneous "grow() is a no-op" and "commit full window immediately" mechanics have been permanently excised.
   - Hostile-header property (64 GiB declared / tiny payload commits only kilobytes) is mandated and pinned by negative test `window_hostile_declaration_peak`.
   - Invariant I-15 is recorded in [`docs/invariants.md`](../invariants.md) §8.

2. **AC-2 / D-10 (Filter Queue Size & Invariant I-16): DISCHARGED.**  
   - `FilterEntry` layout is reordered and compacted from 32 bytes to 24 bytes (`block_start` [8], `file_offset` [8], `block_length` [4], `type` [1], `channels` [1], + 2 B padding = 24 B), enforced via `static_assert(sizeof(FilterEntry) == 24)`.
   - The 2 MiB inline ring is eliminated. `FixedFilterQueue<65536>` (1.5 MiB worst case) is heap-allocated lazily on first filter token (`std::unique_ptr<FixedFilterQueue<65536>> filters_`, 8 bytes inline), pooled on decoder destruction. Unfiltered archives allocate 0 bytes.
   - Hostile saturation (> 65,536 pending filters) fails closed with `DecompressErrorCode::LimitExceeded` → `RAR_ERR_LIMIT_EXCEEDED`.
   - Invariant I-16 is recorded in [`docs/invariants.md`](../invariants.md) §9, with build-time object-size assertions (`sizeof(Decompressor50) <= 64 KiB`, `sizeof(StreamDecoder) <= 64 KiB`) and a small-stack usage test.

3. **AC-3 / D-11 (Filter Scratchpads): DISCHARGED.**  
   - `filter_scratch_` and `delta_scratch_` are lazily allocated on first filter block execution, dynamically sized to the actual block length, and capped at `MAX_RETAINED_FILTER_SCRATCH = 1 MiB` (retained capacity released above cap).
   - Unfiltered archives incur zero scratchpad heap allocation.

4. **AC-4 / D-12 (Zero-Allocation Proof & Tracking Allocator): DISCHARGED.**  
   - Primary proof of record is scoped to `Decompressor50::decompress` with a flush sink (unfiltered full-block and filtered steady-state).
   - Qualified secondary proof is defined for `StreamDecoder` with a flush sink and pre-reserved staging (`reserve_staging()`). M-08 residual tail staging is explicitly scheduled as Step 1.5.
   - Complete nesting-safe `ScopedAllocTracker` design specified with global `operator new`/`delete` hooks linked strictly into the dedicated test target `openrar_allocation_tests`.
   - The zero-allocation claim matrix (§2.3.4) honestly identifies included vs excluded paths, prohibiting vacuous passes (Rule G-9).
