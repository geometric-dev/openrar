# v1.42.0 / v1.42.1 Release Notes — Optimization Backlog + Latent Encoder Fixes

Status: **SHIPPED.** `v1.42.0` (optimization backlog + two latent-fix defects)
and `v1.42.1` (WASM worker protocol fix). `v1.42.1` is the published release
(9 artifacts). Plan of record: `docs/v1.41.1-code-review.md`.

## 1. What shipped

The two-phase backlog `OPT-01`..`OPT-29` of `docs/v1.41.1-code-review.md`,
across the compressor, decompressor, filters, DEFLATE, CDC, Reed-Solomon,
CRC-64 and CLI subsystems.

- **Compressor (`OPT-01`..`OPT-09`):** direct-into-block `BitOutput` (no 256 KiB
  staging copy); branchless unsigned modular `reconstruct_pos`; a dedicated
  `crc_pos_` unpacked-CRC cursor; Kraft-exact downward Huffman length-limiting;
  stack-resident Huffman tables; lazy internal-window allocation with per-worker
  `Compressor50` reuse; large-window-specialized `find_match` with cross-platform
  prefetch and a 4-byte prefix skip; synchronous 4-wide batched match-body
  hashing; dead-branch removal in token emission.
- **Decompressor (`OPT-16`..`OPT-19`):** 8-byte `bswap64` accumulator refill and
  single-check `get_bits`; dropped duplicate `unp_ptr_` cursor; distance-1 RLE
  `memset`; bounded persistent filter scratch (≤ 1 MiB, `docs/invariants.md` §2).
- **Filters / DEFLATE / CDC (`OPT-20`..`OPT-25`):** SSE2+NEON Delta
  encode/apply; MSVC-ARM64 bit-scan + `memchr` E8 detection; pre-reversed
  `Inflate` root LUT + chunked window copies; dead 256 KiB `CdcStreamChunker`
  buffer removed (64-bit `fed_`); `StreamDecoder` read-cursor compaction.
- **RS / CRC-64 (`OPT-26`, `OPT-27`):** shared GF(65536) tables + SSSE3/AVX2
  nibble-LUT fold; slicing-by-8 CRC-64.
- **CLI / MT batching (`OPT-14`, `OPT-15`, `OPT-28`, `OPT-29`):** stale 16 MiB
  chunk floor removed; in-memory chunk-seed hand-off + worker/packer recycling;
  multi-file batches no longer starve cores when `queue.size() < -mtN`;
  direct-to-archive streaming for large unencrypted files under `-mt>1`.

## 2. Latent encoder defects the fast paths exposed (both fixed)

1. **`BitOutput::put_bits64` high-word corruption** (`src/compress/compressor50.hpp`).
   The high half was `value >> (num_bits - 32)` — correct only at `num_bits == 64`
   and wrong for every 33..63-bit field. Latent because the original code never
   emitted a >32-bit field; `OPT-09`'s combined distance code+extra (33..49 bits)
   reached it and corrupted every large-distance token at `-m5`. Fixed to
   `value >> 32`. Regression test: `test_bit_output_put_bits64` (widths 1..64).
2. **Parallel store-fallback CRC clobber** (`ArchiveMutator::prepare_add_file`).
   `if (method == 0 || eff_threads <= 1) crc = crc_calc.get();` overwrote the
   parallel pipeline's valid `stream_crc` with a never-fed `crc_calc` (`0`) once
   the store fallback fired for an incompressible file under `-mt>1` — byte-correct
   stored data reported as a checksum error by every decoder. Guarded with
   `used_parallel`. Regression test: `test_store_fallback_parallel_crc`.

**v1.42.1:** the per-call `Worker` probe made the real WASM worker path reachable
and exposed that the Layer-2 test's fake `Worker` never bridged host↔worker in
either direction (it only "passed" against the main-thread fallback). Fixed the
harness bridge; also made `worker-host.mjs` `#call` **reject** instead of
throwing synchronously on a non-cloneable argument.

## 3. Corrections applied to the review text during implementation

Six proposed fixes had boundary defects that were corrected before shipping:
- `OPT-03`: monotonic `advance_crc(up_to)` guard so CRC hashing never rewinds
  across in-place filter lookahead.
- `OPT-05`: stack fast-path sized to 512 symbols so `test_huffman_builder_shrink`
  stays stack-resident.
- `OPT-08`: batch read guard tightened `from + 7` → `from + 8` (1-byte EOF over-read).
- `OPT-16`: `(64 - n_) >> 3` (not `(63 - n_) >> 3`) to keep the ≥57-bit refill invariant.
- `OPT-22`/`OPT-23`: mask the `Inflate` refill word; guard `dist == WINDOW_SIZE`
  in `window_copy`.
- `OPT-28`: ceiling division for `base_inner_threads` (truncating `4 / 3 == 1`
  starved `-mt4` on 3-file batches).
