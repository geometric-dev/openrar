**Honest scope statement:** v1.29.0 adds a parsed-byte surface (ZIP, TAR,

Binding negative: **C ABI unchanged (zero new exports); DLL/WASM have no
transcode surface; no binding conformance test required.** The lean wasm

### M1 — inflate (RFC 1951), `src/compress/inflate.{hpp,cpp}`

Clean-room table-driven decoder beside `decompressor50` (no zlib/puff
code, ground rule 1). Stream shape: `Inflate::feed(const byte* in, size_t,
Sink&)` with `Sink = bool(*)(const byte*, size_t)`; 64 KiB output chunks;
stored/fixed/dynamic block types; end-of-block/stream; **mandatory
in-flight output cap + cumulative debit wired to the archive-layer
LimitState (D5)** — a decoder-level cap constant (16 GiB default passed
by the caller) fires `RAR_ERR_LIMIT_EXCEEDED`-class status the moment
actual output exceeds it, independent of ANY declared size. Trust model
(stated once, normative): declared sizes are verified against actual
bytes, never the reverse. KATs: RFC 1951-derived vectors + streams
produced by oracle tools (python gzip/zipfile at test time) —
`tests/unit/compress_tests.cpp` additions. The nightly fuzz corpus gains
`fuzz_inflate` (new target, seeded from the KATs).

### M2 — ZIP reader, `src/archive/foreign_zip.{hpp,cpp}`

- **Detection (D8):** `detect_foreign_format()` in
  `src/archive/foreign_reader.{hpp,cpp}` — ONE function, documented
  precedence: `Rar!..0x01 0x00` → Rar5 (usage-refusal upstream);
  `Rar!..0x00` → LegacyRar; `PK\x03\x04`/`PK\x05\x06` → Zip; `\x1f\x8b` →
  Gzip; otherwise TAR by 512-byte header checksum validation at offset 0
  (v7-tolerant). A gzip'd tar is GZIP (no recursion — cv yields ONE
  entry); a TAR named .zip is ZIP by signature.
- **Structure:** bounded EOCD backward scan (comment max 64 KiB, window
  cap = 4 MiB — the shipped MAX_SFX_SIZE bound; a hit must validate EOCD
  field consistency else unparseable); EOCD64 locator + EOCD64; CD walk
  with max_header_count/max_header_bytes caps; per-entry ZIP64 extra
  fields (sizes + offsets).
- **CD/LF pre-flight gate (the §2.1 release gate; comparison table per
  D6):** after the CD walk completes, every entry's local header is read
  at its CD-recorded offset and compared —
  | Field | Rule |
  | :--- | :--- |
  | name bytes | strict — any difference → abort |
  | method | strict |
  | LFH offset | strict (and continuity within the CD walk) |
  | crc32, sizes | compared UNLESS GP flag bit 3 (data descriptor: LFH fields are placeholders) or the entry is ZIP64 (LFH sizes are placeholders; the ZIP64 extra is the compared source) |
  | flags | compared subset = {bit 0 (encrypted), bit 3, bit 11 (UTF-8)}; other bits tolerated |
  ANY mismatch outside this table → structural abort (exit 2) BEFORE the
  first staging file exists. The whole pass completes before any output.
- **Decode pass:** method 0 store, method 8 via `Inflate` (cap debit per
  D5); CRC32 verified per entry (format integrity, distinct from the
  transcoder's BLAKE2sp); other methods → per-entry refusal
  (method-named: bzip2 12, LZMA 14, PPMd 98, AES 99); GP bit 0 → per-entry
  refusal (ZipCrypto: "legacy weak cipher refused by policy"; AES-ZIP
  0x9901: "unsupported in Phase 1"). No foreign decryption, no `-p`
  acceptance for foreign sources (pre-analysis CV-D.4).
- **Names (D14 composition — §3 below).** Attrs/times per pre-analysis
  §2: DOS attrs → file_attr; unix mode only with 0170000 type bits;
  NTFS extra = timestamps only, stream sub-blocks NEVER restored (§4.3);
  UT/NTFS/FAT times through `MtimeBounds`. Archive comment → CMT
  (sanitized); per-entry comments → `comment_skipped`.

### M3 — TAR + GZIP readers, `src/archive/foreign_tar.{hpp,cpp}`,
### `src/archive/foreign_gzip.{hpp,cpp}`

- **TAR:** ustar + documented subset: typeflags 0/5 (file/dir), 1/2
  (hardlink/symlink → FHEXTRA_REDIR records, `link_migrated` flag;
  downstream extraction stays default-deny), 3/4/6/7 skipped-with-report,
  `L`/`K` (GNU long name/linkname, bounded), `x`/`g` pax with subset
  {path, linkpath, size, mtime, atime, uid, gid, uname, gname, hdrcharset}
  — unknown keys skipped per POSIX, records size-bounded; GNU sparse (`S`
  + `GNU.sparse.*`) → per-entry refusal (documented subset boundary).
  End: two zero blocks; EOF before padding accepted (documented);
  mid-header EOF → exit 3 truncation. Sizes vs remaining input enforced.
  uid/gid/uname/gname → FHEXTRA_UOWNER via the existing
  `prepare_add_file(default_user/default_group)` parameters — no mutator
  changes.
- **GZIP:** RFC 1952 header (FLG FTEXT/FHCRC/FEXTRA/FNAME/FCOMMENT;
  FHCRC verified; FEXTRA bounded-skip); **multi-member = ONE logical
  entry, payloads concatenated** (the RFC's interoperable concatenation
  reading); CRC32 + ISIZE verified per member; in-flight cap per member
  (D5); FNAME (first member) names the entry after D14 composition;
  absent → source stem convention (documented); FCOMMENT →
  skip-with-report. Header mtime through `MtimeBounds`.

### M4 — Legacy RAR: OUT OF SCOPE (user scope decision)

No legacy reader is built. `detect_foreign_format()` (D8) still
RECOGNIZES the legacy signature (`52 61 72 21 1A 07 00`) so the refusal is
explicit and method-named — a legacy RAR source fails with a clear
"legacy RAR is not supported" message (usage/unparseable class, pinned by
`cv_legacy_rar_refused`), never a confusing "not an archive". The §5.3
VM boundary holds by absence: no legacy decoder, no legacy parser, no VM
— nothing exists that could execute a filter.

### M5 — Transcode orchestrator + `cv` CLI, `src/archive/foreign_transcode.{hpp,cpp}` + `src/cli/main.cpp`

- **Name composition (D14 — ONE pipeline, all readers):**
  `translate_foreign_name(raw_bytes, encoding_hint)` in
  foreign_reader.{hpp,cpp}: decode bytes (UTF-8-strict / cp437 / pax /
  rar3-scheme per source) → percent-encode invalid sequences (§4.4) →
  `io::sanitize_archive_path` (resolve `..`, strip drives/leading
  slashes, harden components) → final name. `\` → `/` normalization
  BEFORE composition for ZIP/TAR (documented lossy rule); names that
  sanitize to empty → entry skipped with report. Traversal-shaped names
  never reach an emitted archive unchanged — cv does not forward
  weapons.
- **Orchestration (CV-A1):** `detect` → reader.open → **collision
  pre-check** over the translated name list (`CollisionDetector::detect`,
  the v1.24 four classes — cv output must not contain an archive our own
  extractor aborts on) → per entry: decode (caps debit + hooks +
  BLAKE2sp-on-the-fly) → staging file/dir (engine-named index paths, mtime
  set clamped) → `prepare_add_file/_dir/_symlink/_hardlink` → staging
  deleted → `write_batch_add` (comment, password, solid, RR per options)
  → **unconditional roundtrip verify (D9)**: fresh `ArchiveReader` on the
  emitted archive, per-entry payload BLAKE2sp equality + entry-count
  parity → `-df` deletes the source ONLY when verify is 100% green AND no
  entry was skipped/failed.
- **Staging lifecycle (D10):** `.openrar-cv-*` engine-named files under
  `temp_directory_path()`, SpoolFileGuard-pattern RAII sweep on every
  exit; crash orphans are engine-shaped names in the OS temp dir; next-run
  best-effort sweep of exact-shape records only — never pattern-matched
  user paths (the §3.3 forged-journal lesson).
- **`cv` CLI (D7 switch table — every row tested by
  `cv_switch_parity`):**
  | Switch | Behavior |
  | :--- | :--- |
  | `-m0..-m5`, `-md<n>`, `-s` | output compression (pipeline pass-through) |
  | `-p`/`-hp` | OUTPUT encryption only; refused for sources (no foreign decryption) |
  | `-o+`, `-y` | dest overwrite (shipped prompt path, PROMPT state) |
  | `-df` | delete source after full verified roundtrip (§1 M5 above) |
  | `-rr[N[%]]` | RR on the output (writer supports it) |
  | `-ts*`, `-v`, `-oi`, `-ep*` | REFUSED with usage error 7 (explicit refusal beats silent ignore for output-shaping switches — the `-v`-with-`-cdc` refusal precedent) |
  | inert switches (`-q`, `-plain`, `--json-summary`, …) | shipped global behavior |
  | unknown switches | shipped warn-and-ignore (M7 pattern) |
  `dest == source` refused (exit 7; the invariants §5 destination-guard
  pattern). RAR5-signature source → usage error (7; re-packing is
  `a`/`u`/`f`); legacy RAR (1.5–4) IS a source.
- **Exit mapping (D1 — the shipped `x` aggregation, pinned per row):**
  all-migrated+verified → 0; policy skips only → 0 with report EXCEPT
  encrypted-refused → 11; any per-entry FAILED → 2; unparseable → 13;
  structural (CD/LF mismatch, collision classes, uncleanable traversal)
  → 2 pre-output; payload CRC (source) → 3; nothing migrated → 10 (no
  output written); usage → 7; cancel → 255. NO exit-1 mapping.
- **JSON (D3):** `ExtractionReport` gains top-level `format`,
  `verified`, `source_deleted` appended AFTER `abort_reason` (documented
  order) and `kExtractionReportSchemaVersion` bumps to 2 — parse test
  asserts v2 fields present and v1 keys unchanged in position;
  per-entry refusals ride the existing `security_flags` vocabulary
  (`method_refused`, `encrypted_refused`, `vm_filter_refused`,
  `comment_skipped`, `link_migrated`, `name_escaped`,
  `timestamp_clamped`). UTF-8 guarantee inherited (v1.28 M1).
- **Render/non-TTY contract:** every cv line through
  `sanitize_for_display`; zero escape bytes when non-TTY; TUI driven by
  the foreign readers' `ReaderHooks`-shaped hooks (progress per chunk,
  cancel → abandon staging + temp, 255); `--json-summary` stdout purity.

## 5b. Arc ledger (M7 findings recorded at release)

- **Defender false positive on the SFX stub (environment):** Windows
  Defender's ML heuristic flags SOME freshly-linked Default.SFX.exe hashes as
  Trojan:Win32/Wacatac.B!ml (a known .!ml false-positive class for
  embed-and-extract binaries) and quarantines them within seconds — which
  breaks the interop gate's SFX stage locally. Mitigated per-commit by
  re-seeding the Release stub with the known-good Debug-stub bytes (the gate
  relinks Release on every compress/archive commit, re-rolling the hash
  dice). **CI handoff to v1.30 (which owns workflow changes): GitHub's
  Windows runners also run Defender; if the tag-CI SFX stage ever fails
  there, consider a runner-scoped Defender exclusion for the build/output
  dir — do NOT widen it beyond the build tree.
- **Pre-existing gap found:** the README documents `-df`/`-dr`/`-dw` for
  the add path, but the CLI never wired them (`a -df` warns as an unknown
  switch; only the `m` command deletes sources). cv parses `-df` for itself
  (verify-before-delete). Wiring `-df` for `a` via the existing
  PreparedAdd::delete_source is a small, UNRESOLVED follow-up (docs/code
  drift to fix in a stabilization patch or the next arc).
- **cv Phase-1 link policy:** TAR symlinks/hardlinks are read and modeled
  (REDIR semantics at reader level, tested) but cv SKIPS them with a report
  — the staging pipeline cannot express REDIR records without touching the
  mutator's prepare internals, which the §0 no-emission-hunks claim
  forbids. A later arc may add `prepare_add_symlink_from_memory` behind its
  own Gate 0.
- **cv `-s` refused (plan amendment):** solid output requires the
  CompressPlan chain-membership machinery (which entries join the solid
  run); Phase 1 refuses `-s`/`-cdc` with usage 7 instead of half-wiring it.
