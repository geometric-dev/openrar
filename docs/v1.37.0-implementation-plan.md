# v1.37.0 Implementation Plan — Intra-Entry Parallel Decode Driver

Gate 0: `docs/v1.37.0-pre-analysis.md` (window-half answered; design revised
per the Gate 0 review — shared pre-transform output buffer, wait-on-producer;
directives D1–D10 applied). Measurement protocol: v1.34 §3.

## Review round 2 — 🟢 APPROVED, implementation pins (normative)

- **P1** Frontier publication under the range mutex with `notify_all`;
  predicate re-checked under the same mutex. No lock-free publication.
- **P2** Per-range state (mutex/CV/frontier) cache-line padded (64 B).
- **P3** No self-wait: distance validation uses the global position
  (`dist ≤ p`); own-range references never consult frontiers (sequential
  decode already guarantees `q < p` inside a range).
- **P4** Producers publish frontiers at least every 64 KiB of progress and
  at range completion (bounded waiter stall, bounded sync cost).
- **P5** Every worker clamps writes at `dest_size`; overshoot fails the
  entry fail-closed (not just the last range).
- **P6** Solid-chain carried window is read-only static during the entry's
  decode; cross-entry references read it without synchronization.
- **P7** A range starting on a bit-7-clear block initializes its decode
  tables from the pre-scan timeline's resolved code lengths (identical to
  what `read_tables` would build).
- **P8** G5 budget covers `pack_size + dest_size` (the packed stream is
  held in RAM; the mmap engine is normatively not an extraction input).

## Coordinate frame (normative — review directive 2)

ALL positions in this arc are **absolute pre-transform output positions**
of the entry: byte 0 = the entry's first pre-filter byte (solid carry
included in the cross-entry window, NOT in this buffer). The shared decode
buffer, recorded filter applications, and merge logic live in this frame.
`FilterEntry.block_start` (existing struct) is documented as file-linear
output index and maps onto this frame; the post-transform stream exists
only at the final consumer boundary (callback emission after filters run).
Conversions happen nowhere else.

## M1 — Pre-scan (parse-only block walk)

Files: `src/compress/decompressor50.{hpp,cpp}` — new `BlockScan` utility
reusing the decoder's header reader and a parse-only table-description
path.

1. Walk the packed stream byte-aligned (block-header framing per spec 03)
   with the same caps the decoder applies. Record per block: packed byte
   range, has_description (bit 7), final-byte bit count. For bit-7-set
   blocks parse the description (Huffman lengths, no tokens) → the table
   timeline `tables_in_force_at(block_i)`.
2. Fail-closed: any framing anomaly, checksum mismatch, description parse
   error, or size inconsistency → scan failure → sequential fallback (F1).
3. The scan reads the packed stream ONCE from memory handed to it (packed
   bytes are read once per entry by the caller and shared with workers —
   no per-worker disk re-reads).

Tests: scan boundaries vs `tools/scan_table_reuse.py` on corpus members;
table timeline vs an instrumented sequential decode; F1 rows on
truncated/hostile members.

## M2 — Range decode extensions in Decompressor50

Files: `src/compress/decompressor50.{hpp,cpp}`.

1. **Shared-buffer range decode entry point**: decode blocks [i..j)
   starting from a recorded table state, writing pre-transform bytes into
   the caller-owned absolute buffer at the range's output start, RECORDING
   filter applications instead of applying them (workers never transform).
   A match copy at absolute p with distance d first ensures
   `p − d < frontier(producer range)` — condition-variable wait on that
   range's frontier, woken by progress and by the cancel flag (D7).
   Deadlock-freedom is structural (strictly backward references, ordered
   producers) — stated as a normative invariant with a debug-mode wait
   assertion.
2. **The final range** stops at `dest_size` (the entry's unpacked size from
   the file header); earlier ranges decode whole blocks. Per-range output
   lengths are emergent (D4).
3. **Filter application post-join**: the existing transform
   implementations run over the buffer in recorded order (adjacent and
   multiple regions included), producing the post-transform stream for the
   consumer.
4. **Sequential equivalence invariant (the arc's core gate)**: for any
   stream, sequential decode ≡ (range decode + post-join filters)
   byte-for-byte, including the v1.21.1 cross-boundary filter corpus,
   adjacent/multiple filter regions, and a filter spanning a range
   boundary in both directions (D8).

## M3 — The driver

Files: `src/compress/parallel_decode.{hpp,cpp}`; wired through ONE decision
function `should_use_parallel_decode(entry, options)` consumed by the CLI
extraction/verify paths and the DLL decode path (D5). WASM/ILP32 builds
compile the driver out and the function answers false unconditionally (G6);
the DLL conformance row documents engagement or explicit CLI-only status
(D5).

1. Gate evaluation G1–G6 (pre-analysis §1), including the `-mt` default and
   kill-switch decision (D9: default threads on decode = 2 for the driver
   when `-mt` is unset on this host; `OPENRAR_NO_PARALLEL_DECODE=1` forces
   the sequential path, the v1.25 `--no-mmap` precedent). Every gate
   failure → sequential.
2. Range split: R = clamp(threads, 2, 8); ≥ 4 MiB packed per range;
   boundaries at block edges; last range absorbs the remainder and is
   bounded by `dest_size` (D4).
3. Shared buffer: `min(dest_size, PARALLEL_DECODE_BUDGET)` bytes
   (budget 1 GiB native; G5 fallback above it). Extraction byte-caps debit
   unchanged — the buffer counts toward the caps at commit, not allocation
   (the sequential path's behavior preserved).
4. Workers: R − 1 pool threads + the caller on one range; each returns
   {bytes_written, filters recorded, error}. Join → apply filters in
   order → validate total == dest_size (D4) → emit post-transform via the
   existing callback → CRC32/BLAKE2sp exactly as sequential.
5. Fail-closed: any worker error, exception, or validation failure fails
   the entry with the sequential error taxonomy; no partial output reaches
   the consumer (F2/F3). Cancellation (consumer abort): cancel flag set →
   all waiters wake → workers join → nothing committed (F8, D7).

3. Performance claims per v1.34 §3 (paired deltas, min-statistic, wiped
