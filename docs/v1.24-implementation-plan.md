# v1.24.0 Implementation Plan — Extraction Containment & Integrity

**Status:** governing plan for the v1.24.0 arc. This document supersedes the
product owner's Deep Research Analysis (Revision 8): everything useful from
that analysis is incorporated below in full detail; everything wrong or
needless is dropped (§0 records the verdicts for traceability). Normative
inputs: `docs/SECURITY_ARCHITECTURE.md` §3 (policy), §4 (extraction
boundaries), §7.1 (sanitizer); `docs/ROADMAP.md` §v1.24.0.

**Why this release exists:** v1.23.0 added a SFX directive engine whose
programs run contained; v1.24.0 turns to the extraction pipeline itself —
the surface every crafted-archive attack actually hits. The charter is
*provably correct extraction*: syscall-level path containment, atomic file
writes with journal-based cleanup, archive-internal collision rejection, a
machine-readable per-entry security report, and metadata fidelity.
Risk Register item 2 warns this is the largest refactor of the arc: the
write-through-handle pattern touches every write path. Budget accordingly.

### Gaps found beyond the pre-analysis

1. **Rename-leaf TOCTOU is closed by design**: `FileRenameInformationEx` with
   POSIX semantics replaces the destination leaf *without following*
   it — a planted symlink at the destination is replaced, not traversed;
   POSIX `renameat2(RENAME_NOREPLACE)` anchored to the parent `dirfd`
   behaves the same. Documented as a designed property, tested in gate 1.
2. **Containment-walk performance**: per-file component-by-component opens
   cost O(depth) per file. A bounded LRU cache of verified directory handles
   (64 entries default; re-anchor from the pinned root on eviction) makes
   that amortized. Under FD pressure the cache is evicted first — it is a
   cache, not an invariant.
3. **Unicode table budget**: generated tables are committed (target ≤ ~200
   KiB total), the generator script is checked in, and the Unicode version
   (15.1) appears in the collision-detector header and the JSON summary.
4. **Service headers are excluded from collision detection** — CMT/QO/RR
   entries never collide with user-visible entries; the detector runs on the
   final merged entry list with services filtered.
5. **`openat2` availability probing** is cached per process; the WSL1 CI leg
   exercises the fallback by construction (WSL1 lacks openat2).
6. **Forged-journal defense (found in M1)**: a sweep that replays any
   unlocked journal in a directory is itself an attack vector — a local
   attacker with write access there could plant a journal naming a victim
   file. M1 closes it two ways: journals are **per directory** (a journal
   only vouches for temps in its own directory, so the attacker must already
   have write access to the directory holding the victim) and every replayed
   record must match this build's exact temp shape
   (`<name>.<32 lowercase hex>.tmp`), so a journal can never name a file
   this code would not have created itself. Records are checksummed; torn or
   garbage tails stop replay and the journal is left unlinked.
7. **`renameat2` syscall plumbing (found in M1)**: called via
   `syscall(SYS_renameat2, ...)` with per-arch slot fallbacks (x86_64/aarch64/
   i386/arm) for glibc that predates the `SYS_renameat2` define; WSL1 — which
   returns ENOSYS — exercises the `link()`+`unlink()` cascade in CI by
   construction. `FILE_RENAME_FLAG_IGNORE_READONLY_ATTRIBUTE` is deliberately
   NOT set anywhere: a READONLY destination must fail the commit (plan §10
   test 14, matrix row R), matching the pre-atomic `CreateAlways` behavior.
8. **kernel32/NT class split (found in M2)**: `SetFileInformationByHandle`
   rejects handles it did not create (an NtCreateFile-produced handle fails
   with ERROR_INVALID_PARAMETER), so the containment commit calls
   `NtSetInformationFile` directly — where the NT information class is
   **65 (FileRenameInformationEx)**. The kernel32 class value 13 means
   `FileRenameInfoEx` there but `FileDispositionInformation` on the NT side:
   passing it silently deletes the source file. Anchored journal creation
   and the no-follow symlink unlink use NT class 64
   (`FileDispositionInformationEx`, POSIX semantics) for the same reason.
9. **Symlink-leaf replace quirk (found in M2)**: NTFS's POSIX-semantics
   rename reports SUCCESS without replacing when the target leaf is a
   reparse point whose target exists — the source temp is consumed and the
   link stays. The commit therefore checks the leaf (anchored, no-follow)
   and unlinks the link object itself (class 64 POSIX delete) before the
   rename; NoClobber treats an existing link as a clean collision. Gate-1
   tests 1 and 4 pin the outcome.
10. **Root attachment (M2 revision of §1.3)**: the CLI attaches its
    destination explicitly (`set_extraction_root`); readers without an
    explicit root infer it by popping the entry's own sanitized directory
    components off the destination's parent chain (works for full-path and
    `-e` flat layouts). The walk's relative directory is always derived from
    the destination relative to the canonical root (the caller's layout),
    never from the archive name directly. A missing root is created
    (the destination directory is caller-owned input); a destination outside
    the canonical root rejects. `has_symlink_parent` is retained as the
    shipped B3/M9 policy on top of containment.

## 1. Path containment (§4.1) — the core refactor

String sanitization (`../` stripping, DOS-device rejection, ADS/colon
rejection — all existing) is defense-in-depth only. Primary containment is
OS-level, and the file is written through the same handle that was verified:
there is no window between check and write.

### 1.1 Windows

1. **Open-once traversal**: the entry's directory path is opened
   component-by-component from the pinned root handle. Every component is
   opened with `FILE_FLAG_OPEN_REPARSE_POINT` and checked with
   `GetFileInformationByHandle` — any reparse point (symlink, junction,
   mount point) is rejected. This defeats mid-path planting.
2. **`GetFinalPathNameByHandleW` assertion**: after the final open, the
   resolved path must be inside the extraction root. Both the resolved path
   and the root are canonicalized to `\\?\` syntax first
   (`GetFinalPathNameByHandleW` returns NT/Win32 device syntax —
   `\\?\`, `\\?\UNC\`, or `\\?\Volume{GUID}\` — and skipping this
   canonicalization produces false-positive rejections).
3. **Write through the verified handle**: the containment-asserted handle IS
   the write handle (`CreateFile` with `GENERIC_WRITE` at the end of the
   walk). No path is ever re-resolved after verification.
4. **Directory components**: created via the traversal (`CreateDirectoryW`
   anchored to the parent handle) and immediately reopened +
   `GetFileInformationByHandle`-verified as a real directory (no reparse
   attributes) before becoming the anchor for children.
5. **Namespace traps** added to the existing path_util rejections:
   8.3-alias-shaped components (`NAME~X.ext` shape), drive-relative paths,
   UNC/`\\.\` device paths. Pre-existing behavior (trailing dot/space
   handling, colon/ADS rejection, DOS device names) unchanged.

### 1.2 POSIX

1. **`openat2` primary path** (Linux 5.6+): a single
   `openat2(root_fd, path, &open_how)` with
   `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS` resolves and opens atomically —
   any escaping component or traversed symlink fails the call. Called via
   `syscall(SYS_openat2, ...)` directly (glibc wrappers landed in 2.36; CI
   and WSL run older glibc). Availability is probed once per process and
   cached.
2. **Fallback** (pre-5.6 kernels, macOS, FreeBSD): `openat()` walk anchored
   to the pinned root `dirfd`, `O_NOFOLLOW` on every component. Residual
   gap: between opening parent N and opening N+1, a local attacker can
   replace N with a symlink. Mitigation: after the walk,
   `readlinkat` on `/proc/self/fd/<fd>` yields the kernel-resolved absolute
   path; it must be a prefix-path of the root's own `/proc/self/fd` path.
   Prefix check on kernel-resolved paths (not inode comparison — bind mounts
   share the prefix correctly). Weaker than openat2; documented as residual
   risk on pre-5.6 kernels. The WSL1 CI leg exercises this fallback.
   macOS uses `fcntl(F_GETPATH)` for the fd-to-path step.
3. **Directory creation races**: `mkdirat` anchored to the verified parent
   `dirfd`; the new directory is immediately opened and `fstat`-verified as
   a directory (not a planted symlink) before use. The verified dirfd is the
   anchor for children — paths are never re-resolved from the root.
4. **Pinned root**: the extraction root `dirfd` is opened once per
   extraction session and never closed until the session ends.

### 1.3 Destination handling

The extraction destination is caller-chosen (user) — containment is
*relative to it*. A relative destination is canonicalized once against the
process CWD at session start; the canonical absolute form is the
containment reference for the whole session.

### 1.4 Performance

Per-file component opens are O(depth); a bounded LRU cache (default 64
entries) of verified directory handles keyed by relative directory path
amortizes repeated files in the same tree. Under FD pressure the cache
evicts (re-anchoring from the root is always correct). Cache hit paths skip
the walk but never skip the final-handle containment assertion.

## 2. Atomic extraction (§3.3)

1. **Temp-in-destination**: every file is written to
   `<name>.<crypto-random>.tmp` created in the destination directory (same
   volume — required for atomic rename). Names are 128-bit random hex via
   the platform CSPRNG.
2. **Atomic commit**:
   - Windows NTFS (1709+): `FileRenameInformationEx` with
     `FILE_RENAME_FLAG_POSIX_SEMANTICS` (+ `REPLACE_IF_EXISTS` when the
     caller consented to overwrite) — true atomic replace, the POSIX-semantics
     rename replaces a planted symlink leaf rather than following it, and the
     missing `IGNORE_READONLY_ATTRIBUTE` keeps READONLY destinations
     respected. The new name is anchored to the destination's parent
     directory handle; M2's walk supplies that handle from the verified
     parent. Implementation: `FileStream::commit_rename` (DELETE access is
     requested only for `CreateNew` temps — wider DELETE on other write
     modes conflicts with read streams' share modes, found by
     `test_compressor50_truncated_source`).
   - Windows fallback (FAT32/exFAT, SMB, pre-1709): `MoveFileExW` with
     `MOVEFILE_REPLACE_EXISTING`. Not truly atomic — a crash between
     delete-old and rename-new loses the file. Documented per-volume:
     support probed via the `SetFileInformationByHandle` error class and
     fallen back per call.
   - Linux 4.11+: `renameat2(RENAME_NOREPLACE)` for no-clobber commits
     (direct syscall, arch-slot fallbacks — gap 7).
   - macOS 10.12+: `renamex_np(RENAME_EXCL)`.
   - POSIX fallback: `link(temp, dest)` + `unlink(temp)` — `link` fails
     atomically if the destination exists (no-clobber); filesystems without
     hardlink support (FAT) fall back to `rename()` with a pre-check (small
     TOCTOU window documented for no-clobber on those platforms).
   - Overwrite commits on POSIX pre-check `faccessat(W_OK)` so a READONLY
     destination fails the commit exactly as Windows does (test 14).
3. **Journal manifest**: `FILE_FLAG_DELETE_ON_CLOSE` prevents atomic rename,
   so abandoned temps are cleaned via a per-run journal:
   - **One journal per destination directory** (M1 revision of the
     single-root design): `.openrar_journal_<pid>_<timestamp>_<nonce>.tmp`
     lives in every directory the run writes temps into, held under an
     exclusive advisory lock for the run's lifetime (`flock(LOCK_EX)` on
     POSIX — conflicts across open file descriptions even in-process;
     share-mode-0 open on Windows). Journals close + unlink as soon as no
     temp is in flight in that directory, so descriptor use is bounded by
     extraction parallelism, not tree size, and the sweep coverage is exact:
     each directory's orphans are discovered in that directory, regardless
     of who knew the extraction "root" (fixes the DLL per-call surface, which
     has no root concept).
   - Append-only; fsynced before each temp is created (durable-first: a
     crash can never leave an unreferenced orphan); records every temp's
     absolute path with a per-record CRC32.
   - Startup sweep: run once per directory before that directory's first
     journal opens. Discovers journals by exact name prefix, attempts to
     lock each; locked journals (live concurrent extractors) are skipped;
     unlocked journals (dead processes) are replayed — referenced temps
     deleted — and the journal is then unlinked. Records are validated
     against the forging attack (gap 6 above): same directory + temp shape +
     checksum. Never pattern-matched sweeps (§3.3).
4. **FD accounting**: a bounded LRU dir-handle cache (§1.4) plus explicit
   close-on-ascend keeps descriptor usage bounded regardless of tree depth.

## 3. Collision detection (§3.2)

Archive-internal collisions are integrity failures: the extraction aborts
before writing anything (exit 2), because the archive itself is lying about
its own structure.

1. **Detector input**: the final merged entry list after `open()` (the
   reader already assembles all volumes, split-merged, at scan time — no
   pipeline change), service headers (CMT/QO/RR/ACL/STM) filtered out.
2. **Classes**, each compared after the §4 trimming pipeline:
   - Duplicate-identical: byte-exact name match.
   - Case-insensitive: Unicode Simple Case Folding (locale-independent;
     avoids the Turkish İ/i trap).
   - NFC vs NFD: compare after NFC canonical composition (most archives
     store NFC; APFS compares normalization-insensitively, so an NFD twin
     of an NFC name collides on disk — NFC comparison catches it).
   - File-vs-directory: `foo` (file) vs `foo/bar` (directory) prefix match
     after normalization.
3. **Unicode tables**: generated from the pinned Unicode 15.1 data files by
   a checked-in generator script; committed tables target ≤ ~200 KiB total;
   the Unicode version is a named constant surfaced in the JSON summary.
4. **Detection timing**: post-scan, pre-extraction — nothing is written when
   a collision exists. On the WASM surface the detector runs identically
   (structural property; no filesystem involved).

## 4. Encoding, trimming, UI invariant (§4.4)

1. Trailing-space/dot trimming is applied before BOTH UI rendering and path
   evaluation — the displayed name always matches the evaluated path.
2. **Displayed ≡ extracted invariant** (CVE-2023-38831 mitigation): the name
   in listing/extraction output is exactly the on-disk name. Explicitly
   tested.
3. **Lossless escaping**: undecodable names (invalid UTF-8) are
   percent-encoded (`%XX` per invalid byte) and the escaped name IS the
   filename. Reversible, filesystem-safe, shell-convention-consistent;
   reported in the JSON summary.
4. Timestamp clamping: absurd mtimes clamp to parameterized bounds;
   clamping feeds skip-with-report.

## 5. Exit policy + JSON summary (§3.1)

1. Exit codes stay in the WinRAR/unrar taxonomy pinned by interop stage 15
   (2 fatal, 3 CRC, 10 no-files, 11 bad-password, 13 bad-archive, 255
   user-break). Path traversal and structural failures → 2 (13 when
   unparseable). No new codes.
2. **JSON summary**: `--json-summary[=path]`. With the flag and no path,
   ALL human-readable output (banner, progress, warnings, password prompts)
   routes to stderr; stdout carries only valid JSON. Schema (versioned):

```json
{
  "schema_version": 1,
  "archive": "path/to/archive.rar",
  "exit_code": 0,
  "entries": [
    { "name": "file.txt", "status": "extracted", "reason": null,
      "security_flags": [] },
    { "name": "evil.txt", "status": "skipped", "reason": "path traversal",
      "security_flags": ["traversal_attempt"] }
  ],
  "aborted": false,
  "abort_reason": null
}
```

3. `status`: extracted | modified | skipped | failed | unprocessed.
   `security_flags`: machine-readable tags (`traversal_attempt`,
   `collision_case`, `timestamp_clamped`, `name_escaped`, ...). Consumers
   ignore unknown fields; breaking changes bump schema_version.
4. Abort semantics: entries processed before an abort keep their real
   status; the rest appear as `unprocessed` / `"extraction aborted"`;
   `aborted: true` + `abort_reason` set. The entry list is always complete.

## 6. Entry semantics — links (§4.2)

1. Default deny: symlinks, hardlinks, junctions are never extracted unless
   link extraction is explicitly enabled.
2. Opt-in is decoupled from path resolution: even with links enabled,
   absolute links and links escaping the root are rejected, and every
   regular-file write still goes through the §1 no-follow containment walk.
3. Hardlinks: session-scoped — targets must be files created in the SAME
   extraction session (one `extract_all` / one CLI `x`|`e` invocation; a
   multi-volume set is one session). A `SessionLinkRegistry` (inode/path set)
   is created at session start and destroyed at session end; DLL/WASM
   extraction calls are separate sessions.

## 7. Metadata fidelity + deferred restoration

1. **SUID/SGID/sticky masking** (POSIX): archived `st_mode` has 07000 bits
   masked unless an explicit `--preserve-suid` admin flag is given; modes
   are bounded by the process umask.
2. **Hardlink fallback**: `FHEXTRA_REDIR` hardlink extraction falling back
   to a full copy on `EXDEV` / `ERROR_NOT_SAME_DEVICE` debits every copied
   byte against `ExtractionLimits::max_total_bytes`; excess aborts. Verified
   via link-count oracles.
3. **Unknown-extra preservation**: `header_reader` captures raw bytes of
   unrecognized extra records into `FileHeader::unknown_extras`;
   `header_writer` re-serializes them during mutation.
4. **Deferred directory metadata**: directories are created permissive
   (0700-equivalent) with default timestamps; (path, desired mode, desired
   mtime) entries stack during extraction and are applied bottom-up
   (deepest first) after all writes complete — `futimens`/`SetFileTime` +
   `fchmod`/`SetFileAttributesW`. This preserves directory mtimes (children
   would clobber them) and lets read-only directories receive children.

## 10. Negative-Test Plan (named — deterministic)

1. `toctou_symlink_target_race` — symlink pre-planted at the write target;
   the containment assertion catches it (gate 1).
2. `toctou_midpath_junction` — junction planted at an intermediate
   component; open-once walk rejects (Windows), openat2 rejects (POSIX).
3. `toctou_journal_sweep_race` — two concurrent extractors; the sweep skips
   locked journals and never deletes live temps.
4. `toctou_rename_leaf_symlink` — symlink at the rename destination is
   replaced (not followed) under POSIX-semantics rename.
5. `openat2_unavailable_falls_back` — probe-forced fallback passes the same
   containment suite (WSL1 leg).
6. `alias_83_rejected` — `PROGRA~1/x`-style components refused with reports.
7. `collision_duplicate_identical_abort` — exit 2, atomic no-partial state.
8. `collision_case_folded_abort` — `Readme` + `README` = abort.
9. `collision_nfc_nfd_abort` — NFC + NFD `café` = abort.
10. `collision_file_vs_dir_abort` — `foo` + `foo/` = abort.
11. `collision_service_headers_exempt` — CMT/QO never trigger.
12. `collision_multivolume_span` — collision split across volumes caught.
13. `overwrite_no_clobber_default` — existing target + no flag = skip+report.
14. `overwrite_readonly_respected` — READONLY target never clobbered.
15. `json_stdout_purity` — `--json-summary` routes every human byte to stderr.
16. `displayed_equals_extracted` — trimmed/escaped display name == disk name.
17. `percent_encoded_undecodable` — invalid-UTF-8 name = lossless `%XX` name
    on disk + report.
18. `suid_sgid_stripped` — archived 04755 extracts 0755, umask-bounded.
19. `hardlink_fallback_byte_cap` — fallback copies debit the byte cap;
    excess aborts.
20. `dir_metadata_deferred` — read-only dir + restored mtime after children.
21. `unknown_extras_roundtrip` — unknown extra records survive mutation.
22. `journal_orphan_cleanup` — killed run leaves temps; next run sweeps only
    journal-referenced files.
