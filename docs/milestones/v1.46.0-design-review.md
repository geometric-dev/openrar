## 1. Executive Summary & Core Posture

The re-scoping of v1.46 is structurally sound and adheres to the v1.43 attribution verdict: dictionary reach is **off-axis for closing the ratio gap**, and therefore re-chartering `-md=auto` around memory bounding, cache efficiency, and consumer-side window optimization (OPT-D01) is the correct architectural choice. Establishing Invariant G-3 (cross-host byte-identity with zero dependency on host RAM sensing) is vital for determinism.

However, moving from pre-analysis to implementation exposed four technical vulnerabilities that required resolution before code could be written:
1. **C++ Standard Compatibility:** The initial proposal cited `std::make_unique_for_overwrite` (C++20), whereas OpenRAR builds under **C++17** (`CMAKE_CXX_STANDARD 17`). Resolved by specifying a C++17 `default_init_allocator<core::byte>` for `WindowBuffer`.
2. **`ALLOC_LIMIT` Security Bypass:** If `alloc_win_` replaces `engine_.win_size_` in `Decompressor50` before validating against `ALLOC_LIMIT`, a hostile archive declaring a 128 GiB dictionary on a 10 KB file would bypass the dictionary ceiling check. Resolved by requiring unconditional verification of `declared_win > ALLOC_LIMIT` upon entry.
3. **Parallel Concurrency Throttling:** Batch thread throttling (`main.cpp:1392`) computes per-thread memory before inspecting individual file sizes. Resolved by inspecting the maximum resolved auto-dictionary across the actual `queue` items rather than relying on a static ceiling.
4. **File Size TOCTOU:** An active file growing between plan-time `stat` and pack-time read could result in an encoder window exceeding the header window. Resolved by strictly clamping the compressor window to the header window.

The Failure-Mode Matrix (FMM-46, 10 rows) and Negative-Test Plan (6 named suites) are present, satisfying the Pillar-7 gate check.

## 2. 🚨 Critical Red Flags & Fatal Flaws

- **Red Flag 1: C++20 Primitive in a C++17 Codebase (`make_unique_for_overwrite`)**  
  *Mechanism:* In C++17, `std::make_unique_for_overwrite` does not exist and would cause compilation failure across all toolchains.  
  *Remediation:* Adopted a C++17-conforming `default_init_allocator<core::byte>` for `std::vector` in `WindowBuffer`, which eliminates value-initialization zeroing without violating the codebase's C++17 standard or ARCHITECTURE §4 raw `new` restrictions.

- **Red Flag 2: Malformed Header `ALLOC_LIMIT` Bypass in Decompressor**  
  *Mechanism:* In `decompressor50.cpp:324`, `if (engine_.win_size_ > ALLOC_LIMIT)` rejects spec-invalid or hostile dictionaries (>64 GiB on 64-bit, >1 GiB on 32-bit/WASM). Clamping `win_size_` to $W_{alloc} = 128\text{ KiB}$ before this check would allow illegal dictionaries to be accepted.  
  *Remediation:* `Decompressor50` validates `declared_win > ALLOC_LIMIT` unconditionally before computing or applying `alloc_win`.

- **Red Flag 3: Encoder / Header Window Divergence (TOCTOU)**  
  *Mechanism:* If a file expands between `stat` and `prepare_add_file`, an encoder expanding beyond the header's declared window creates a corrupt archive (violating Invariant §7).  
  *Remediation:* The compressor window is capped strictly by the snapped header window. If input exceeds the plan-time size, the encoder sliding window wraps at the header window.

## 3. ⚠️ Weak Assumptions & Fragile Invariants

- **Fragile Dynamic Thread Throttling (`main.cpp:1392`):**  
  Evaluating `eff_dict` at the method ceiling (e.g. 64 MiB for m3) before inspecting the batch queue would unnecessarily throttle a batch of small files down to 1–2 workers. The plan now specifies scanning the `queue` for the peak actual auto-dictionary.
- **Solid Chain Boundary Fragility (Invariant I-6):**  
  Evaluating `-md=auto` per-file inside a solid run would break history carry. The plan confirms that solid batches compute `run_bytes = sum(file_sizes)` up-front, with all chain members inheriting the chain's aggregate auto-window.

## 5. ⚡ High-Performance & Mechanical Sympathy Gaps

- **Double Zero-Fill Elimination (M5a):**  
  `WindowBuffer::grow_to` calling `vec_.resize(n)` touches memory cache lines during allocation. Using `default_init_allocator` avoids touching memory during allocation, deferring physical page faults until actual decode writes occur.
- **FCI Snapping Redundancy:**  
  `resolve_auto_dict` returns the already-snapped value, avoiding repeated calls to `snap_window_to_fci_grid`.

## 6. 🔍 Omissions, Edge Cases & Recovery Gaps

- **Delimiter Handling in CLI:**  
  `-md=auto`, `-md:auto`, and `-mdauto` are normalized case-insensitively before numeric parsing.
- **WASM Diagnostics:**  
  WASM engine clamps dictionaries to `window_log2 in [1, 4]`, and records diagnostic disclosures if auto-sizing requested a larger window.
