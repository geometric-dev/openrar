# ARCHITECTURAL SUMMARY

Traversal and Principal Architect interrogation of the OpenRAR compression, decompression, filter, CLI pipeline, and recovery subsystems (`v1.40.0`) identified **29 verified optimization and correctness items** across 11 source files, organized into a **two-phase execution contract** to preserve the repository's byte-identity regression gates:

1. **Phase A — Bitstream-Identical Optimizations (Zero Wire Change):**
   - **Eliminating Unused Multi-Megabyte Window Allocations (`OPT-06`):** `Compressor50::begin_archive()` unconditionally allocates and zero-faults `buf_` (`win_size_ + 5 MiB`, i.e., `13 MiB` at `-m3` and `69 MiB` at `-m5`) even when `set_external_buffer()` or `set_seeded_external_buffer()` is called immediately afterward, leaving `buf_` 100% unused across all in-memory and multithreaded chunked compression paths and causing severe kernel VM lock contention and TLB shootdowns.
   - **Synchronous 4-Wide Batched Match-Body Hashing (`OPT-08`):** `Compressor50::process_available()` contains a 4-wide batched hash-insertion loop (`lines 1368–1387`) that is dead during normal compression because match bodies (`lines 1541–1546`) are hashed 1 byte at a time via scalar `insert_position(cur_)` calls. Running the 4-wide batch loop directly over `[cur_, end)` inside the match-emission branch activates 4-wide hashing for all matches of length $\ge 4$ while preserving the synchronous `unhashed_pos_ == cur_` invariant at all loop exits and `slide_window()` boundaries.
   - **Fixing Broken `unhashed_pos_` Source-CRC32 Aliasing (`OPT-03`):** `unhashed_pos_` was aliased between `consume_source(unhashed_pos_, cur_)` and the LZ hash catch-up cursor, causing `consume_source` to always see `from == to` and `Compressor50::get_unpacked_crc32()` to permanently return `0`.
   - **Eliminating Dead 256 KiB `pending_` Buffer in `CdcStreamChunker` (`OPT-25`):** `CdcStreamChunker` zero-initializes a 256 KiB `pending_` array on construction and writes every input byte into it during `feed()`, but `pending_` is never read anywhere in the codebase.
   - **Eliminating Hot-Loop Dispatch, Bit-Reversal, and Allocation Bottlenecks (`OPT-01`, `OPT-10`, `OPT-11`, `OPT-16`, `OPT-18`, `OPT-19`, `OPT-20`, `OPT-23`, `OPT-26`, `OPT-27`):** Removes the double-buffering in `BitOutput`, the scalar memory-reload loop in `match_length_neon`, the per-call static guard in `match_length_simd`, the duplicate `unp_ptr_` cursor in `Decompressor50::ApplyEngine`, the per-region heap allocation in `ApplyEngine::flush_pending` (bounded to $\le 1\text{ MiB}$ to honor `docs/invariants.md` §2), the per-symbol 9-iteration `reverse_bits` loop in `Inflate::next_symbol`, the $O(N^2)$ `in_queue_.erase()` shift in `StreamDecoder`, and the per-instance `1.25 MiB` GF table allocations in `ReedSolomon16`.
   - *(Note: The previously proposed single-`peek_bits(15)` fusion in `HuffmanDecoder::decode` was **descoped** per `docs/v1.38.0-pre-analysis.md` §0 Gate-0 measurements showing `VFused` is 6–10% slower than the shipped 10-bit quick table.)*

2. **Phase B — Wire-Format / Chunk-Topology Improvements (Requires Cross-Extractor Hash Gate):**
   - **Fixing Inverted Kraft Length-Limiting in `HuffmanBuilder::build_lengths` (`OPT-04`):** When a Huffman tree exceeds `max_bits = 15`, `build_lengths` currently searches *upwards* from `d = 1` (demoting the single most frequent symbol in the block and leaving the Kraft tree up to 25% under-complete). Searching *downwards* from `d = max_bits - 1` and splitting one node at `d` into two leaves at `d + 1` while promoting one leaf from `max_bits` (`bl_count[d]--; bl_count[d + 1] += 2; bl_count[max_bits]--; kraft_sum -= 1;`) restores optimal length-limited prefix codes and closes the compression-ratio gap against WinRAR.
   - **Removing Stale 16 MiB `REUSE_CHUNK_FLOOR` and CLI Multi-File Thread Starvation (`OPT-14`, `OPT-28`, `OPT-29`):** Table reuse was disabled in `v1.40.0`, yet `ParallelBlockPipeline::compress_stream` still enforces a 16 MiB chunk floor, and `src/cli/main.cpp:1576` hardcodes `threads = 1` per file on multi-file batches (starving cores whenever `queue.size() < threads`, such as on the 3-file 128 MB canonical and 1 GB corpora).

### ISSUE: OPT-01 - 64-Bit Accumulator Packing and Elimination of Intermediate `BitOutput::buf_` Copy
* **Vector:** 4: Algorithmic
* **Severity:** High
* **Location:** `BitOutput::put_bits`, `BitOutput::flush_buf`, `BitOutput::align_byte`, `BitOutput::reset_for_block` (Lines `16`–`138`)
* **Root Cause:**
  1. `BitOutput` maintains an internal `256 KiB` staging vector `buf_` even when `mem_dest_` is non-null (`write_block()` always passes `&block_mem_`). Every compressed block is written into `local_out_.buf_`, copied into `block_mem_` via `flush_buf()`, and then copied into `mem_out_` (or written to `dest_file_`) after the 3–5 byte RAR5 block header is constructed (`compressor50.cpp:1162–1168`).
  2. `put_bits` flushes 32 bits at a time (`if (acc_bits_ >= 32)`), executing `buf_.size()`, a capacity check, `buf_.resize(sz + 4)`, a 4-byte `std::memcpy`, and `if (buf_.size() >= OUTBUF_SIZE) flush_buf()` on every 32 bits emitted.
  3. In `align_byte()` (Lines `87`–`99`), when `acc_bits_` is a non-zero multiple of 8 (e.g., `8`, `16`, `24`), the `while (acc_bits_ >= 8)` loop reduces `acc_bits_` to `0` and skips the `if (acc_bits_ > 0)` branch without zeroing `acc_`, leaving stale high bits in `acc_`.
* **Proposed Fix:**
  1. When `mem_dest_ != nullptr` (the `reset_for_block(&block_mem_)` path), write directly into `mem_dest_` (`block_mem_`, pre-reserved to `512 KiB` + 64 bytes slack) rather than staging through `BitOutput::buf_` and copying into `block_mem_`. Retain `buf_` only for direct `dest_file_` streaming.
  2. In `put_bits`, append into `target_vec` by pre-reserving capacity and writing 32-bit big-endian words via `std::memcpy`, checking for `OUTBUF_SIZE` flushes only when `dest_file_ != nullptr`.
  3. Unconditionally set `acc_ = 0; acc_bits_ = 0;` at the end of `align_byte()`.
* **Verification Strategy:** Phase A (bit-exact). Run `compress_tests` and `stream_encoder_tests` under `-fsanitize=address,undefined`, add `test_bit_output_unaligned_block_bits` covering `block_bit_size` 1..8 and `acc_bits_ % 8 == 0`, and verify 100% byte-identical output on the canonical corpus.

### ISSUE: OPT-02 - Branchless Unsigned Modular Distance in `Compressor50::reconstruct_pos`
* **Vector:** 1: Bit-Level/UB
* **Severity:** Medium
* **Location:** `Compressor50::reconstruct_pos` (Lines `426`–`434`)
* **Root Cause:** `reconstruct_pos` reconstructs a 64-bit position from a 32-bit hash entry `trunc` via signed `core::int64 cand = (pos & ~0xffffffffULL) | trunc; if (static_cast<core::uint64>(cand) > pos) cand -= 0x100000000LL; if (pos - static_cast<core::uint64>(cand) > max_dist_) return -1;`. If `pos < 0x100000000ULL` and `trunc > pos`, `cand` becomes negative, and casting `cand` back to `core::uint64` wraps modulo $2^{64}$ so `pos - static_cast<core::uint64>(cand)` evaluates to a small positive number $\le \text{max\_dist\_}$, returning a negative candidate index other than `-1`.
* **Proposed Fix:** Compute the 32-bit modular distance directly in unsigned arithmetic:
  `if (trunc == 0xFFFFFFFFu) return -1; core::uint32 dist32 = static_cast<core::uint32>(pos) - trunc; if (dist32 > max_dist_ || dist32 > pos) return -1; return static_cast<core::int64>(pos - dist32);`.
* **Verification Strategy:** Phase A (bit-exact). Add `test_reconstruct_pos_4gib_boundary` in `tests/unit/compress_tests.cpp` testing `pos` around `0`, `0xFFFFFFFF`, and `0x100000005` under `-fsanitize=undefined`.

### ISSUE: OPT-03 - Broken Source-CRC32 Cursor Aliasing with `unhashed_pos_`
* **Vector:** 4: Algorithmic
* **Severity:** High
* **Location:** `Compressor50::consume_source`, `Compressor50::get_unpacked_crc32` (Lines `390`, `498`–`512`, `624`; `src/compress/compressor50.cpp` Lines `389`, `1339`, `1361`, `1404`, `1496`, `1517`, `1546`, `1560`)
* **Root Cause:** `unhashed_pos_` is used both as the start offset for `consume_source(unhashed_pos_, cur_)` (to update `hash_crc32_`) and as the LZ hash-table catch-up cursor in `process_available()`. Because `process_available()` sets `unhashed_pos_ = cur_` after every literal and match (`compressor50.cpp:1361, 1404, 1496, 1517, 1546`), `unhashed_pos_` is always equal to `cur_` when `consume_source(unhashed_pos_, cur_)` is called at `need_flush()`, `finish_stream()`, and `compress()`. Advance `crc_pos_` via `consume_source(crc_pos_, ...)` *before* in-place filter transformation in `process_available()`, before `slide_window()`, and at `finish_stream()` / `compress()`.
* **Verification Strategy:** Phase A (bit-exact). Add `test_compressor50_unpacked_crc32_filtered_and_plain` in `tests/unit/compress_tests.cpp` verifying `packer.get_unpacked_crc32()` matches `crypto::crc32()` across plain, seeded, and E8/Delta-filtered inputs.

### ISSUE: OPT-04 - Inverted Kraft Length-Limiting Search Direction in `HuffmanBuilder::build_lengths`
* **Vector:** 4: Algorithmic
* **Severity:** Critical
* **Location:** `HuffmanBuilder::build_lengths` (Lines `134`–`186`)
* **Root Cause:** When `max_depth > max_bits` (15), lines `142`–`147` clamp all leaves with `d > max_bits` to `max_bits`, causing `kraft_sum` ($\sum_{d=1}^{\text{max\_bits}} \text{bl\_count}[d] \cdot 2^{\text{max\_bits}-d}$, where $\sum \text{bl\_count}[d] == \text{used}$) to exceed `kraft_limit` ($2^{15} = 32768$). Lines `157`–`165` then resolve the overflow via:
  `core::uint32 d = 1; while (d < max_bits && bl_count[d] == 0) d++; bl_count[d]--; bl_count[d + 1]++; kraft_sum -= (1u << (max_bits - d - 1));`
  Searching from `d = 1` *upwards* demotes the shortest, highest-frequency symbol in the entire block (e.g., lengthening a 1-bit or 2-bit symbol that occurs 15,000 times to fix a 1-unit overflow from depth-16 leaves) and subtracts $2^{\text{max\_bits}-d-1}$ without redistributing leaves from `bl_count[max_bits]`, leaving the Kraft sum severely under-complete (wasting up to 25% of the prefix-code space).
* **Proposed Fix:** Replace the upward loop at lines `157`–`165` with the exact Kraft-preserving downward split:
  1. While `kraft_sum > kraft_limit`: find the deepest level `d` in `max_bits - 1` down to `1` such that `bl_count[d] > 0` (if `d == 0` or `bl_count[max_bits] == 0`, break).
  2. Replace one leaf at depth `d` and one overflowed leaf at `max_bits` with two leaves at `d + 1`:
     `bl_count[d]--; bl_count[d + 1] += 2; bl_count[max_bits]--; kraft_sum -= 1;`
     Because $-2^{\text{max\_bits}-d} + 2 \cdot 2^{\text{max\_bits}-(d+1)} - 2^0 = -1$ and $-1 + 2 - 1 = 0$, every iteration preserves $\sum \text{bl\_count}[d] == \text{used}$ and reduces `kraft_sum` by **exactly `1`**, terminating at `kraft_sum == kraft_limit` ($32768$) with the shortest codes untouched.
* **Verification Strategy:** **Phase B (Wire-Format Ratio Improvement).** Add `test_huffman_builder_kraft_exactness` in `tests/unit/compress_tests.cpp` verifying `kraft_sum == 32768` on Fibonacci and skewed distributions, run the 24-stage WinRAR/UnRAR cross-extraction gate, and measure compression ratio improvement on the 128 MB canonical corpus.

### ISSUE: OPT-26 - Static Shared GF(65536) Tables (`uint32` Log / `uint16` Exp) and x86 SSSE3/AVX2 Nibble-LUT Kernel

* **Severity:** High
