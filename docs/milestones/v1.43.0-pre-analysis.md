## 0. Gate 0 statement

**Claim under test:** the residual `-m1`/`-m3` ratio gap to the reference
encoder is recoverable *without* surrendering the speed lead — i.e. a token
selection that is strictly more ratio-frugal than greedy+lazy, but no more
finder-expensive.

**Why this is the only live direction.** Two cheaper-looking levers are already
closed by measurement (§1). The v1.32 structural finding (§2) is that the gap
lives in the **finder's candidate set**, not in the parse, and that the binding
constraint is **time, not ratio**. So any new ratio arc must be justified
time-first, ratio-second.

**Bounds (blocking, carried from the standing gates):**
- `m3` ratio non-regression (`docs/invariants.md` §7 wire rules still hold; the
  24-stage cross-extractor interop gate is the legality proof);
- the `-m5` speed lead and the zeros win must not regress (the v1.31 bound);
- T9's pure-addition assertion (`compress_tests`, "suppressed-257 output drifted
  from the v1.30.4 reference bytes") is **structurally incompatible with any
  `-m3` token-selection change** and must be settled as a test-design question —
  not by refreshing hashes — before this arc lands (§2, disposition note).

## 1. Candidates already closed — do not re-attempt as written

### 1.1 `HuffmanDecoder` single-`peek_bits(15)` fusion — measured negative

The v1.41.1 review's "descoped fusion" is not merely deferred; it was measured
slower in `docs/v1.38.0-pre-analysis.md` §0 (hash-verified, same session):

| variant (symbol stage, ms/16 MiB) | text m3 | text m1 | exelike m3 | random m3 |
|---|--:|--:|--:|--:|
| VQuick (shipped 10-bit quick table, replica) | **94.1** | **108.9** | **142.3** | **123.6** |
| VFused (single `peek(15)`) | 99.5 | 114.9 | 151.7 | 136.5 |

The shipped structure keeps its hot data in ~4 KiB per alphabet (L1-resident);
every wider single-lookup variant trades the rare L1-hot canonical walk for a
colder primary table. **Side effect:** v1.42.0 still shipped the *safe* part of
that neighbourhood — `Inflate`'s (DEFLATE) pre-reversed root LUT (`OPT-22`),
which is a different decoder with a different structure — so no further
`HuffmanDecoder` (`Decompressor50`) change is warranted here.

### 1.2 Optimal cost-model parse — built, failed the gates, removed

`docs/ROADMAP.md` §"Descoped: v1.32.0 optimal parse" records the full result:
the rolling forward DP over `{literal, match, rep0..3, 257}` was implemented,
round-tripped byte-exact on every corpus, and then **failed the gates on the
canonical corpus at m3** — `code -1.9%`, `text -1.2%`, `random tie`,
**`zeros +28%` (T1)** and **`3.9x` time (T6, budget 1.42x)**. At 3.9x, m3 would
go from ~2x faster than WinRAR to ~2x slower — surrendering the project's
headline position to buy ~2% ratio. The engine is parked (`arc/v1.32.0-optimal-parse-parked`),
**not for merge**. Do not re-tackle a DP parse replacement.

## 2. The structural finding that scopes what is left

From the v1.32 disposition (the part explicitly marked "worth keeping"):

> A cost-model parse over this match finder must relax an edge out of *every*
> position, so it spends ~4x the finder budget that greedy/lazy parsing spends.
> Greedy is … *finder-frugal*, searching only at token starts because a match
> skips its own body. … **the time gate, not the ratio gate, is the binding
> constraint** for any future parse work.

Two independent measurements (v1.31-M2's binary tree; the v1.32 DP) now show the
`m1`/`m3` ratio gap is **structural in the finder**, not the parse. The same
disposition names the only under-explored levers:

> … attack the candidate source first (**a match cache shared with the greedy
> scan**, or **restricting the relax to token-start candidates**) and re-measure
> time before ratio.

That is the entire scope of this arc: **do not add a second full search pass;
make the existing token-start search remember more.** Greedy already pays for a
candidate walk at each token start; the gap is that it throws the walk away.

Supporting facts already in the tree (no new measurement):
- The finder is chain-based (`find_match`, per-method depth/nice/`lazy_tests_`;
  `init_match_params`) and the rep scan re-walks `old_dist_[0..3]` separately.
- The `-m3`/`-m5` ladder is a known time/ratio knee (`m4` depth 128→64 bought
  −38% time for +0.89% size; `m5` knee confirmed at 128) — headroom exists but
  is bought with time, which is why **finder-frugal** is the constraint.

## 3. Proposed Gate-0 experiment (measure, then decide)

**Hypothesis H1 (match cache).** Reuse the candidate walk greedy already
performs: at each token start, before selecting, cache the *k* best
`(candidate, length)` pairs the chain walk found (they are already visited to
compute `best` and the lazy `cur_+1` re-search). Let the *next* few positions'
decisions consult that cache instead of re-walking, and let the emitter keep the
existing greedy/lazy selection rule unless the cache proves a strictly longer
match at the same-or-lower distance that greedy skipped. This is **not** a DP:
no per-position relax, no back-pointers, no emission-path change beyond the
existing `add_match`/`add_rep` calls — it only changes *which already-legal
token* is chosen, so the wire format is untouched.

**Protocol (v1.34 §3 — paired deltas, min-of-N, alternating order, wiped
configure dirs, single session on a fresh Release build):**
1. Implement behind a compile-time flag; keep the shipped path byte-identical
   when off (gate: `compress_tests` T9 unchanged with the flag off).
2. **Time first:** measure `-m3` wall time on the canonical corpus. **Reject the
   arc** if the paired delta exceeds the v1.32 time budget (the failed DP was
   3.9x; the standing budget is 1.42x). A finder-frugal cache must be
   **≤ ~1.1x** to be worth discussing.
3. **Ratio second:** only if (2) passes, measure `-m1`/`-m3` size vs greedy on
   `code`/`text`/`random`/`zeros`. Reject on any `zeros` regression (the DP's
   T1 failure mode is run-heavy input — price/candidate handling of dist-1 runs)
   and on any `text`/`code` regression.
4. **Legality:** the 24-stage cross-extractor interop gate (UnRAR 7.20 + WinRAR
   7.20) is the standing proof; plus the repo roundtrip + solid/filter suites.
5. **Test-design precondition:** resolve the T9 "structurally incompatible with
   any m3 token-selection change" item first — a token-selection change must be
   expressible in a way T9's invariant can still pin (or T9 must be split into a
   "no-257" reference and a "selection" reference). Do this before code, not
   after a red CI.

**Kill criteria (any one ends the arc):** time > ~1.1x on `m3`; any `zeros`
size regression; any `m1`/`m3` size regression; T9 cannot be made to pin the new
path without weakening its invariant.

## 4. Fallback: the v1.39–v1.43 discovery pool

If H1 is rejected on the time gate (the likely outcome, given two prior
structural negatives), the arc pivots to the roadmap's unsequenced discovery
pool (`docs/ROADMAP.md` §"v1.39 – v1.43 — discovery pool"), which is
expansion/robustness work rather than ratio work and carries far less gate
risk:

- **Parallel CDC fingerprint pass** — the v1.26 fingerprint (`CdcStreamChunker`,
  `OPT-24`-refreshed) is the packer's ordering heuristic; a parallel version
  targets wall-clock on large `-cdc` batches, ratio-neutral.
- **Multi-volume no-data-area entries** — format completeness for split
  service/redir entries, oracle-gated.
- **WASM streaming encode** — the browser product surface still lacks the
  streaming encoder the native CLI has; additive, gate-light.
- **Dictionary auto-sizing** — pick the window from input statistics instead of
  the per-method default table (`resolve_dict_window_size`); ratio/memory
  trade-off, measurable like the M3 sweeps.
- **MSan/fuzz depth growth** — robustness, no wire change.

Each of these is independently Gate-0-able and none touches the compressed
wire format, so the cross-extractor gate is satisfied by construction.

## 5. Recommendation

1. **Close the two named candidates explicitly** (§1): the `HuffmanDecoder`
   fusion is measured-negative (v1.38 §0) and the DP parse failed the gates
   (v1.32) — record both as non-goals so they are not re-derived.
2. **Run H1 (§3) as a time-first Gate-0 spike.** It is the one lever the v1.32
   disposition left open that attacks the *finder* cheaply, and it is
   wire-neutral. Expect it to fail the time gate; the value is the measurement,
   which either re-confirms the structural wall with a third independent number
   or opens a real ratio path.
3. **If H1 fails, take the discovery pool** (§4) for v1.43.0 — with
   **dictionary auto-sizing** as the first pick (it is the only pool item with a
   ratio/memory dimension and a ready measurement harness), falling back to
   **parallel CDC fingerprint** and **WASM streaming encode** as gate-light
   additive wins.
