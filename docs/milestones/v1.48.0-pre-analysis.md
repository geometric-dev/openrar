## 1. M0 — Symlink Read-Link Legality & Link Matrix

### 1.1 Current State

`prepare_add_symlink_from_memory` (`archive_mutator.cpp:1883-1914`) accepts
a target string verbatim. It currently performs **zero validation** on the
link target — no absolute-path check, no `..` traversal check, no UNC/ADS
screening. All safety is deferred to extraction-time in `ArchiveReader`:

- `archive_reader.cpp:2566+`: case-fold collision detection
- `archive_reader.cpp:2598+`: hardlink/FILECOPY source containment
- `archive_reader.cpp:2615+`: H3 source-stays-inside-root check

**The `a` command path** (`main.cpp:1987`) uses `std::filesystem::read_symlink`
which reads the link target without traversing it — correct for TOCTOU closure.
The foreign transcode path (`foreign_transcode.cpp:302-316`) passes the
foreign-entry `link_target` directly from parsed metadata.

### 1.2 Link Matrix (Attack Surfaces)

The roadmap specifies the full matrix. Current coverage:

| Vector | Create-side check | Extract-side check | Gap |
|--------|-------------------|-------------------|-----|
| Absolute target (`/etc/passwd`, `C:\Windows`) | ❌ None | ✅ Spec-07 skip | **M0 adds create-side** |
| UNC path (`\\server\share`) | ❌ None | ✅ Blocked | **M0 adds create-side** |
| `..` traversal (`../../etc/shadow`) | ❌ None | ✅ Blocked by containment | **M0 adds create-side** |
| ADS (`file:stream`) | ❌ None | ✅ NTFS ADS policy | **M0 adds create-side** |
| Case-fold collision (`Readme` vs `README`) | N/A at create | ✅ CollisionDetector | None |
| NFC-NFD collision | N/A at create | ✅ CollisionDetector | None |
| Reserved DOS names (`CON`, `PRN`, `NUL`) | ❌ None | ✅ Blocked | **M0 adds create-side** |
| Dangling target | ✅ (stat fails) | ✅ (skip) | None |

### 1.3 TOCTOU Closure

**The rule:** `prepare_add_symlink` uses **read-link semantics — never
traverse targets.** `std::filesystem::read_symlink` returns the target string
without opening/following the target. This is already correct in `main.cpp:1987`.

**Remaining TOCTOU surface:** Between `read_symlink()` and
`prepare_add_symlink()`, a racing process could replace the symlink itself.
Mitigation: the link target is captured atomically by `read_symlink` (a single
`readlink(2)` syscall). The symlink _identity_ can race, but the captured
_target string_ is the one that gets archived. This is acceptable — an attacker
who can replace symlinks in the source tree can replace regular files too, and
the latter is explicitly out of scope (§2.3).

### 1.4 Implementation Approach

Add a static validation function to `ArchiveMutator`:

```cpp
struct SymlinkLegality {
    bool valid{false};
    std::string rejection_reason;  // empty when valid
};

static SymlinkLegality validate_symlink_target(
    const std::string& arc_entry_name,
    const std::string& target);
```

Checks:
1. **Absolute path** — starts with `/`, `\`, or drive letter → reject
2. **UNC path** — starts with `\\` or `//` → reject
3. **Traversal** — any component is `..` → reject
4. **ADS** — contains `:` after the first path component → reject
5. **Reserved DOS names** — any component matches `CON|PRN|AUX|NUL|COM[0-9]|LPT[0-9]` (case-insensitive) → reject
6. **Empty target** — reject
7. **Null bytes** — reject

Call sites:
- `main.cpp` `add_to_archive` symlink path (line ~1987)
- `foreign_transcode.cpp` symlink migration (line ~304)

Rejected symlinks: skip + report `symlink_dropped` with reason in JSON.

### 1.5 macOS Non-Equivalence Contract

On macOS without Seatbelt (pre-v1.47 builds, or runtime sandbox failure):
- `WARN_SYMLINK_CONTAINMENT_UNAVAILABLE` diagnostic
- Non-zero exit (exit code 2)
- `symlink_dropped` in JSON report
- Published note: "extraction equivalence is not claimed when symlink
  containment is unavailable"

This is gated on `OM-1`: the Seatbelt shipped in v1.47 satisfies it.

## 2. M1 — `-s`/`-v<size>`/`-ts` on Transcode

### 2.1 Current State

The `cv` command dispatch (`main.cpp:4318-4337`) currently refuses these
switches explicitly:

```
Line 4330-4333: if (no_dir_records || max_versions >= 0 || want_sfx ||
    want_lock || want_rv || want_ams || want_symlinks || want_hardlinks ||
    want_stm || want_acl || want_xattr || want_og) {
    std::cerr << "Error: switch not supported by cv\n";
    return EXIT_USAGE;
}
```

The `TranscodeOptions` struct (`foreign_transcode.hpp:18-33`) already has:
- `bool solid = false;` — `-s` support already wired
- `unsigned threads = 1;` — `-mt` already wired
- No `vol_size` field — `-v` missing
- No `-ts` (timestamp precision) field — missing

### 2.2 Implementation Approach

**`-s` (solid):** Already plumbed through `TranscodeOptions::solid` and
forwarded to `write_batch_add`. The cv dispatch at line 4330 currently blocks
it (`want_solid` is in the refusal list... wait, checking: `solid` is NOT in
the refusal list). Let me verify:

The `convert_archive` function signature (`main.cpp:3284`) does not accept
a `solid` parameter. The cv dispatch (`main.cpp:4335`) does not pass `solid`.
So `-s` is silently ignored for `cv`, not refused. **Fix:** wire the parsed
`solid` flag through the dispatch to `convert_archive`.

**`-v<size>` (volume splitting):** The transcode output is a single archive.
Volume splitting requires `write_batch_add_ex` to produce multi-volume output.
The shipped `write_batch_add_ex` (`archive_mutator.cpp:1996+`) writes a single
file. Multi-volume creation is a **new capability** that doesn't exist in the
writer. **Decision:** `-v` is out of scope for v1.48 — the writer doesn't
support volume creation yet. Keep the refusal. Add a specific error message.

**`-ts` (timestamp precision):** The `times_mask` parameter controls which
timestamps (mtime/ctime/atime) are preserved. The transcode path currently
uses the default `time_flags::MTIME`. `-ts` should enable full timestamp
preservation:
- `-tsm` — mtime (default, already done)
- `-tsc` — ctime
- `-tsa` — atime
- `-ts` — all three

The `prepare_add_*_from_memory` functions already accept `times_mask`.
Foreign entries carry `mtime_sec`/`mtime_nsec`. ZIP and TAR can carry
mtime; creation/access times are format-dependent (ZIP extra fields,
PAX `atime`/`ctime`).

**Implementation:** Pass the parsed `times_mask` through to
`convert_archive`, then to `TranscodeOptions`, then to each
`prepare_add_*_from_memory` call. Foreign readers need to expose
ctime/atime where available.

### 2.3 Scope Decision

| Switch | Action | Rationale |
|--------|--------|-----------|
| `-s` | **Wire through** | Infrastructure exists; simple plumbing |
| `-v<size>` | **Keep refused** | Writer doesn't support volumes; out of scope |
| `-ts` | **Wire through** | `times_mask` plumbing exists end-to-end |

## 3. M2 — FILECOPY Default-Materialization on `cv`

### 3.1 Current State

FILECOPY (redir_type 5) is the in-archive deduplication mechanism:
byte-identical files get a FILECOPY reference pointing to their master.

The `cv` path (`foreign_transcode.cpp`) currently does **not** emit FILECOPY
references for duplicate files in the source archive. Every file is individually
staged and compressed, even if the foreign archive contains exact duplicates.

The `a` command path (`main.cpp:2166+`) performs hash-based duplicate
detection and emits FILECOPY references via `prepare_add_filecopy`.

### 3.2 Implementation Approach

Add duplicate detection to the transcode loop:

1. During the stage-and-hash loop (`foreign_transcode.cpp:280+`), maintain
   a `std::unordered_map<Blake2sp_hash, string>` mapping content hash →
   first-seen archive entry name.
2. On hash match, skip staging and emit a FILECOPY reference via
   `prepare_add_filecopy` (or a from-memory variant that doesn't require
   a filesystem path, since foreign entries are staged to temp).
3. The `source_hashes` vector used for roundtrip verify must still include
   the FILECOPY entries (they point to an already-verified master).

**Edge case:** FILECOPY references must appear **after** their master in
the entry vector. The foreign entry order preserves this if we only emit
FILECOPY for entries whose master has already been processed.

### 3.3 Verification

The roundtrip verify loop (`foreign_transcode.cpp:496+`) must handle
FILECOPY entries. Currently it skips entries with `pack_size < 0`
(directory records). FILECOPY records have `pack_size = 0` but
`redir_type = 5`. The verify must either:
- Extract FILECOPY entries (they resolve to the master's content) and
  compare against the source hash, or
- Skip FILECOPY in the verify count and adjust `payload_indices`.

## 4. M3 — ZipCrypto Weak-Crypto Posture Note

### 4.1 Current State

ZipCrypto-encrypted entries in foreign ZIP archives are refused by policy
(`foreign_reader.hpp:43`: `EncryptedRefused = 9`). The refusal is correct
but undocumented in `SECURITY_ARCHITECTURE.md`.

### 4.2 Implementation

Add a section to `docs/SECURITY_ARCHITECTURE.md` (after §5.3 or in a new
§5.4):

```markdown
### 5.4. Weak Cryptography Posture

OpenRAR does not implement ZipCrypto (PKZIP traditional encryption).
ZipCrypto is a known-plaintext-vulnerable stream cipher with a 96-bit
key space that can be brute-forced in hours on commodity hardware. Foreign
archives containing ZipCrypto-encrypted entries are transcoded with those
entries skipped (`encrypted_refused` status, per-entry report) and the
conversion exit code elevated to 11 (bad-password class) when at least
one such entry is present.

AES-ZIP (WinZip AES) decryption is also not implemented in Phase 1.
Both are per-entry refusals; unencrypted entries in the same archive
migrate normally.

This is a deliberate design decision, not a missing feature. Implementing
ZipCrypto would extend the attack surface with a cipher that provides no
meaningful confidentiality.
```

## 5. Commit Protocol (New Destructive Surface)

### 5.1 Current Commit Model

`write_batch_add_ex` (`archive_mutator.cpp:1996+`) already implements
temp-then-rename:

1. Writes to `mutation_temp_path(arc_path, "app_tmp")` via `TempFileCleanupGuard`
2. On success: `atomic_rename_commit(tmp_path, arc_path)`
3. On failure: `TempFileCleanupGuard` destructor removes the temp

This is a **single-file atomic commit** for creating/replacing one archive.

### 5.2 cv Commit Protocol

The `cv` command creates a new archive (never appends). The commit path is:

1. `write_batch_add` writes to temp
2. Temp is atomically renamed to `dest`
3. On failure: temp is cleaned up; source is untouched

**The roadmap requires a batch rename protocol** for multi-file operations:
"temp names → validate the set (count, CRCs, header chain) → rename batch.
Any failure unlinks temps and leaves source and any prior destination
untouched. Mid-set crash → sweep on next open."

**For v1.48 cv specifically:** The operation is source → single dest. The
batch protocol is relevant for **future archive mutation** (updating entries
in an existing archive, which requires preserving the original until the
replacement is validated). The cv path is already fail-safe: it never touches
the source until roundtrip verify succeeds.

### 5.3 Implementation for v1.48

The existing single-file commit protocol is sufficient for cv's use case.
Document the crash-recovery sweep shape:

- On startup, sweep `temp_directory_path()` for `openrar-cv-*` staging dirs
  (the `StagingGuard` pattern at `foreign_transcode.cpp:51-59`)
- On startup, sweep the archive directory for `*.app_tmp` mutation temps
  (the `TempFileCleanupGuard` pattern)

Both sweeps must be **name-shaped only** — never pattern-match user paths
(the §3.3 forged-journal lesson from `foreign_transcode.cpp:29`).

## 8. Risk Assessment

| Risk | Impact | Mitigation |
|------|--------|------------|
| Symlink validation too aggressive (rejects valid relative targets) | Functional regression | Matrix tests cover relative, nested relative; validation only blocks known-bad patterns |
| FILECOPY hash collision (Blake2sp) | Silent data corruption | Blake2sp collision probability is negligible (2⁻²⁵⁶); matches the `a` command's duplicate detection |
| `-v` users confused by continued refusal | UX friction | Clear error message: "cv does not support multi-volume output (-v); use the a command" |
| Foreign mtime→ctime/atime mapping inconsistency | Timestamp noise | Only preserve timestamps the source format actually provides; missing fields get epoch-0 |
