## 1. Architectural Stress Test

### Pillar 1: Correctness & Invariants
- **Preservation of Reserved Slots (−8 and −10):** The addition of new error codes `RAR_ERR_PASSWORD_TIMEOUT` (−16), `RAR_ERR_CONTAINMENT_BREACH` (−17), `RAR_ERR_DECRYPT` (−18), and `RAR_ERR_RESOURCE_EXHAUSTION` (−19) strictly respects the binary layout rules. Negative error codes extend monotonically below −15 without backfilling −8 or −10.
- **Fail-Closed Semantics:** Any unexpected termination of the worker process must immediately transition the broker phase to `Phase::Closed` and close parent channel descriptors to prevent pipe leaks or hung read loops.

### Pillar 2: Mechanical Sympathy & Performance
- **Deterministic Work Bound:** Bounding PBKDF2 iterations by `MAX_PBKDF2_LG2 = 24` is a vital defense against algorithmic complexity attacks. Calculating $2^{24} = 16,777,216$ iterations consumes ~1.2s on modern AVX2 cores; larger values cause unacceptable latency and potential watchdog timeouts. Immediate rejection prevents worker exhaustion.
- **Volatile Key Hygiene:** Zeroing key buffers using `crypto::secure_wipe` prevents compiler dead-store elimination from leaving key material in memory dumps.

### Pillar 3: Failure Modes & Adversarial Analysis (FMM-51 Matrix)
- **FMM-51-3 Crash vs Security Breach:** A worker crash (e.g. out-of-bounds memory access or abort in decompression) must be classified as `RAR_ERR_CONTAINMENT_BREACH` (−17). This indicates that the sandboxed worker took the fault safely inside the isolation bubble, preventing host compromise.
- **FMM-51-6 Forgery Protection:** Even if a compromised worker attempts to report success without emitting valid data, the broker independently computes the CRC over streamed chunks. Any discrepancy aborts with `RAR_ERR_CRC_MISMATCH` (−4).

### Pillar 4: Platform Realities (Windows / POSIX)
- On Windows, worker termination utilizes `TerminateProcess` and reaps the handle; on POSIX, `SIGKILL` and `waitpid` ensure no zombie workers are left.
- Channel handles marked non-inheritable on the broker side guarantee clean EOF delivery when either peer exits.

### Pillar 5: API / ABI Stability & Interface Hygiene
- `include/openrar/openrar_dll.h` and `src/archive/rar_errors.hpp` must match identically.
- `abi_layout_tests` must be updated to check the extended enum boundaries and ensure zero ABI drift.
