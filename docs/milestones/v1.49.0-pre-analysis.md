## 1. M0 — Memory Accounting & Binary Divergence Disposition

### 1.1 Memory Accounting Classification
WASM memory consumption operates within constrained 32-bit linear address spaces. To guarantee bounded execution without uncontrolled heap growth, memory is partitioned into three formal tiers:

| Class | Contents | Allocation Rule | WASM Budget Ceiling |
|---|---|---|---|
| **Static** | Codec tables, Huffman structures, ring buffer | Fixed at load / module instantiation | $\le 512$ KiB block / $\le 1.5$ MiB archive |
| **Dynamic — Caller** | Input files, output chunks | Managed by host JS runtime (transferred / copied) | Excluded from engine accounting |
| **Dynamic — Engine** | LZ match window ($\le 5 \times 2^{\text{window\_log2}}$), scratch buffers | Bounded by caller's chosen window size | Default method 3, `window_log2` 4: peak measured $\approx 5$ MiB |

- **Default Peak:** With default method 3 and `window_log2` 4 (1 MiB window), the native compressor engine footprint is $5 \times 1\text{ MiB} = 5\text{ MiB}$ (per invariant I-7).
- **Static Boundary Verification:** Static allocations are bounded by build-time presets (`-s INITIAL_MEMORY=16MB -s ALLOW_MEMORY_GROWTH=1`).

### 1.2 Binary Divergence Trace Disposition
The roadmap (§7.7 Hardening ①) requires forcing the divergence trace across `createArchive` $\times$ `createArchiveStream` $\times$ block `compressStream` $\times$ the bespoke `Archive` class to a binary outcome:
- The bespoke `Archive` class was removed in commit `e13c5f3` and superseded by `createArchive` and `extractAll` in `openrar-archive.js`.
- **Decision:** Rather than reviving the dead `Archive` class to add streaming, [`docs/wasm-limitations.md`](../wasm-limitations.md) §4.3 gains a dated entry:
  - Status: `deferred: post-v1.52`
  - Owner: `geometric-dev`
  - Rationale: Real RAR5 streaming is provided by `createArchiveStream`. The bespoke object wrapper remains dropped.

## 2. M1 & M2 — Streaming Archive Encode API & Hardening

### 2.1 API Surface & Types
In [`wasm/js/openrar-archive.js`](../../wasm/js/openrar-archive.js) and [`wasm/js/openrar-archive.d.ts`](../../wasm/js/openrar-archive.d.ts):
```typescript
export function createArchiveStream(
  files: CreateArchiveInput[] | Iterable<CreateArchiveInput> | AsyncIterable<CreateArchiveInput>,
  opts?: CreateArchiveOptions & { chunkSize?: number }
): ReadableStream<Uint8Array>;
```
The stream exposes an asynchronous iterator (`stream[Symbol.asyncIterator]()`) to allow direct consumption via `for await (const chunk of stream)`.

### 2.2 Parity Rule (I-3)
Byte-identity is an absolute invariant. Concatenating all chunks produced by `createArchiveStream(files, opts)` must yield byte-for-byte identical output to `await createArchive(files, opts)` for identical inputs.
- Format structure: Signature (8 bytes) $\rightarrow$ Main Archive Header $\rightarrow$ File Headers + Payloads $\rightarrow$ End Block.
- Because RAR5 files without solid flags are compressed independently, sequential emission of file blocks maintains 100% byte equivalence.

### 2.3 Hardening Invariants
1. **Fail-Closed Streams:** If processing aborts (via `opts.signal`) or runs out of memory, the `ReadableStream` controller MUST be errored (`controller.error(err)`). It MUST NEVER cleanly close (`controller.close()`). An aborted or partial stream must never masquerade as a complete archive.
2. **OOM Handling:** Out of memory conditions must be mapped to `RarError('NOMEM', '...', -5)`. The instance state is unrolled; no uncaught `WebAssembly.RuntimeError` or raw panic crosses to the host.
3. **Chunk Ownership:** Engine memory is never retained or freed by the host. Chunks yielded to the consumer are JS-owned copies (`safeRead` / `Uint8Array.prototype.slice()`). Engine buffers are released deterministically in `finally` blocks.

## 3. M3 — Vacuous-Pass Vector 1 (V-1) & G-9 Compliance

### 3.1 Defect Analysis
Currently, all four WASM test suites (`wasm/js/archive.test.mjs`, `helpers.test.mjs`, `test.mjs`, `worker.test.mjs`) begin with:
```javascript
if (!existsSync(distJs)) {
  test('... missing ...', { skip: true }, () => {});
} else { ... }
```
When running native CI builds where Emscripten (`wasm/js/dist/`) is not compiled, 100% of the tests self-skip. CI reports a green pass with 0 executed tests. This violates Governance rule G-9 ("No vacuous passes").

### 3.2 Node-Only Mock Architecture
- Implement [`wasm/js/mock_module.js`](../../wasm/js/mock_module.js) (~100 LOC) simulating the minimal Emscripten runtime:
  - Linear memory buffer (`HEAPU8`, `HEAPU32`).
  - Allocator (`_malloc`, `_free`, `_openrar_alloc`, `_openrar_free`).
  - String utilities (`UTF8ToString`).
  - Dynamic function dispatch (`addFunction`, `removeFunction`).
  - C ABI emulation for block codec and archive operations (`openrar_version`, `openrar_archive_create2`, `openrar_archive_open`, `openrar_archive_handle_list`, `openrar_archive_handle_extract`, etc.).
- Auto-provisioning: If `wasm/js/dist/` is absent, the mock harness provisions stub loaders in `wasm/js/dist/` (which is already gitignored).
- Test execution: All test suites run and assert an executed test count $> 0$.

## 4. M5 — 32-Bit Bit-Position Width (§10 OPT-D02)

### 4.1 Mechanism & Failure Mode
In [`src/compress/decompressor50.hpp`](../../src/compress/decompressor50.hpp):
- `consumed_`, `size_`, `fetched_` in `BitReader` are declared as `size_t`.
- `bit_pos()` and `bits_remaining()` return `size_t`.
On wasm32 and ILP32 platforms (such as 32-bit ARM), `size_t` is a 32-bit unsigned integer (`uint32_t`).
When packed input exceeds $2^{29}$ bytes (512 MiB), bit-position quantities exceed $2^{29} \times 8 = 2^{32}$ bits.
On 32-bit `size_t`, `bits_remaining()`:
```cpp
size_t BitReader::bits_remaining() const {
    size_t rem_bytes = (end_ - p_) + (size_ - fetched_);
    return rem_bytes * 8 + n_;
}
```
multiplies `rem_bytes * 8`, which overflows $2^{32}-1$ and wraps to 0. A packed input of exactly 512 MiB reads as 0 bits remaining, terminating decode or misinterpreting headers mid-payload, defeating the v1.41.1 `int64 block_start` fix.

Furthermore, in [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp) at lines 979 and 1474:
```cpp
size_t end_bit = block_end_bit(header);
```
`block_end_bit` returns `core::uint64`, but it is narrowed to `size_t end_bit`.

### 4.2 Remediation
1. Change `BitReader::consumed_`, `size_`, `fetched_` to `core::uint64`.
2. Change `BitReader::bit_pos()` and `BitReader::bits_remaining()` return types to `core::uint64`.
3. Update `BitReader(InputCallback, size)` to accept `core::uint64 size`.
4. Widen `end_bit`, `cur_bit`, and call sites in `decompressor50.cpp` to `core::uint64`.
5. Zero-allocation boundary test in [`tests/unit/bitreader_stream_tests.cpp`](../../tests/unit/bitreader_stream_tests.cpp):
   Construct `BitReader` with declared sizes $2^{29}-1$, $2^{29}$, and $2^{29}+1$. Assert `bits_remaining() == 8 * declared` before any reads.

## 5. Failure Mode Matrix (FMM-49)

| ID | Trigger | Symptom | Remediation / Verification |
|---|---|---|---|
| **FMM-49-1** | Stream aborted mid-encode via `AbortSignal` | Controller cleanly closes or hangs | `controller.error(err)` on abort; assert stream rejection |
| **FMM-49-2** | Memory allocation failure in WASM engine | `WebAssembly.RuntimeError` escapes to host | Catch allocation errors, map to `RarError('NOMEM', ..., -5)` |
| **FMM-49-3** | Host consumer retains engine chunk pointer | Use-after-free or data corruption on heap reuse | Yield decoupled JS copies (`safeRead`) |
| **FMM-49-4** | Streaming encode differs from one-shot | Archive fails parity check or extraction fails | Assert byte-for-byte identity against `createArchive` |
| **FMM-49-5** | Packed input reaches 512 MiB on wasm32/ILP32 | Bit counter wraps to 0; premature EOF or stream desync | Widen bit counters to `core::uint64` |
| **FMM-49-6** | `dist/` missing in CI environment | JS test suites self-skip; vacuous pass | Node-only mock executes test suites; assert count $> 0$ |
