# OpenRAR v2.2.0 Implementation Plan: Greedy Consolidation, Throughput Recovery & Empirical Ratio Target

**Milestone:** v2.2.0  
**Theme:** Greedy-only consolidation, -m4/-m5 speed recovery, and the first ratio target derived from a measured ceiling. No new format surface, no new parser, no dictionary changes.  
**Pre-Analysis Reference:** [`docs/milestones/v2.1.0-implementation-plan.md`](v2.1.0-implementation-plan.md) (§10, §11, Appendix C)  
**Governance Scope:** Rules G-1 (Single Decision Function), G-3 (Fingerprinted Measurement), G-8 (Charter Discipline), G-9 (No Vacuous Passes), Pillar 7 (Happy-Path Bias Invariant), and Invariants I-1 through I-14  
**Status:** 🟢 **APPROVED** (Incorporating Principal Architect Challenge Directives)  
**Baseline Reference:** Official frozen v2.0.23 release binary (external reference) + v2.1.1 deterministic size ratchet (`RATCHET_BYTES`)

## 0. Executive Vision & Kickoff Decisions

OpenRAR v2.1.1 completed the critical transition from the speculative forward-arrival DAG engine to the battle-tested greedy parser with lazy matching across all compression methods (`-m1` through `-m5`). Empirical reconciliation revealed that the forward-arrival parser was 1.2%–2.2% larger than greedy on source code, tests, documentation, and PE binaries, while only claiming marginal gains on synthetic PRNG word salad. Furthermore, it imposed severe throughput penalties on higher compression methods.

The v2.2 milestone is a disciplined consolidation and recovery arc. It permanently removes the dead forward-arrival parser and dynamic price models, optimizes greedy search and lazy evaluation to restore `-m4`/`-m5` compression throughput, extends the fail-closed regression guard into Windows CI, and derives the first empirical ratio target based strictly on measured ceilings against real-world corpora.

### Kickoff Decisions & Architectural Contracts

| Area | Decision | Implementation & Governance Contract |
|:---|:---|:---|
| **Environment Variables** | CLI deprecation warning, library ignore | `OPENRAR_ENABLE_FORWARD_ARRIVAL` becomes a no-op: CLI prints a single warning to `stderr` and exits code 0; library core (`libopenrar`, Python SDK, C# bindings) silently ignores it without `exit()` or `stderr` pollution. `OPENRAR_PRICE_ARM`, `OPENRAR_NO_DYNAMIC_PRICE`, and `OPENRAR_EXPERIMENTAL_M1_DAG` are deleted entirely. |
| **Research Probes** | Permanent retirement of `blockceiling` | `tools/blockceiling.cpp` and `Compressor50::BlockProbeRecord` are retired in W1. Any future parser ceiling investigations must be conducted out-of-tree or via external differential oracles, eliminating dead research hooks from production classes. |
| **Interop Manifest** | Pinned stage count at 35 | `tools/interop_reference.py` drops the 4 forced non-default engine stages per corpus, locking the manifest strictly to 5 corpora $\times$ 7 greedy configurations = **35 stages**. CI asserts `stages == 35` fail-closed. |
| **Throughput vs Ratchet** | Ratchet Primacy (Invariant I-13) | Speed recovery in W2 must not buy throughput with archive size. Any optimization that increases compressed size beyond `RATCHET_BYTES + RATCHET_SLACK_BYTES (64 B)` on any of the 30 pinned deterministic cells is immediately rejected. |
| **CI Guard Expansion** | Two-tier Windows guard | A new `windows-2022` job is added to CI downloading the pinned v2.0.23 Windows release asset. Deterministic size ratchets and oracle decompression are strictly enforced; timing checks incorporate runner jitter margins to prevent virtualization false-positives. |
| **Baseline Architecture** | Long-term baseline preservation | The external baseline remains the frozen official v2.0.23 release binary. The immediate gate is the v2.1.1 ratchet (`RATCHET_BYTES`). The baseline is never bumped to 2.1.1, preserving the 1%–2% real-content compression lead. |

## 1. Workstream W1: Delete Forward-Arrival Engine

### 1.1 Objective & Rationale
Remove the forward-arrival DAG engine, dynamic price model infrastructure, and transitional experimental overrides. In v2.1.1, `forward_arrival_default()` was set to `false` for every method; greedy with lazy matching is the shipped default across the board. Keeping ~600 lines of complex DP relaxation and dead research hooks creates cognitive debt, maintenance drag, and landmines for future contributors.

## 2. Workstream W2: Recover -m4/-m5 Throughput

### 2.1 Baseline Throughput Profile & The Gap
At `-m1`–`-m3`, the greedy engine runs at 1.2×–3.6× the throughput of v2.0.23. At `-m4`/`-m5`, the v2.1.1 baseline ran at 0.85×–0.95× on real files and 0.70×/0.63× on Windows/Linux for synthetic word salad. The v2.2 minimum-length lazy hurdle (landed in W2) recovered `-m4` to 0.89×–0.97× and `-m5` to 0.67×–0.72× word salad / 0.94×–0.95× real files. The `-m5` cell remains at or below the 0.70× gate.

**Refined Architectural Analysis.** The primary throughput lever is unconstrained lazy search overhead rather than primary chain depth. Efficient greedy engines often search *deeper* (e.g. 45/100/150 attempts at `-m3`/`-m4`/`-m5` vs OpenRAR's 32/64/128) by avoiding an unconstrained full chain walk at `cur_ + 1`: lazy evaluation can probe the next position selectively, using bounded single-candidate checks and rep tests rather than triggering a full `find_match(cur_ + 1, search_chain, nice_len_, min_target)`. Arbitrary chain-depth truncation is therefore the wrong lever and is demoted.

### 2.2 Investigation Hypotheses & Experiment Plan

```
W2 Optimization Pipeline:
Position cur_
  │
  ├── 1. Primary Match Search (find_match_impl)
  │      └── Hypothesis 2: Short-Match Credit Counter & Distance Gates
  │
  ├── 2. Match Found (len >= min_match)
  │      │
  │      └── Hypothesis 1: Cheap Lazy Probe (cur_ + 1)
  │             ├── Trigger: only for short pending matches (test ≤8 / ≤12)
  │             ├── Probe: one hash candidate + direct extension
  │             └── Rep test: four distances, pending distance as rep3
  │
  ├── 3. Cost Split
  │      └── Hypothesis 3: Chain Walk vs Lazy Probe vs Block/Huffman
  │
  ├── 4. Chain Depth
  │      └── Hypothesis 4: Test 45/100/150 Attempts (upward, not downward)
  │
  └── 5. Cache Sympathy
         └── Hypothesis 5: Hash Table & Window Prefetching (last)
```

#### Hypothesis 1: Cheap Lazy Probe (Primary)
- **Analysis:** OpenRAR's lazy pass calls the full `find_match(cur_ + 1, search_chain, nice_len_, min_target)` with `search_chain = 64/128`. A bounded alternative probes the next position selectively for short pending matches, evaluating a single hash candidate plus direct extension and rep tests, with the pending match's distance substituted for `rep3`. The current `min_target` hurdle prunes some of the search, but the surviving calls still walk the full chain.
- **Experiment 1A (Trigger):** Probe only when the pending match is short. Test bounded cutoffs (evaluating short matches against OpenRAR's legal-length floor and filter interaction).
- **Experiment 1B (Probe):** Replace the full search with one hash candidate at `cur_ + 1`, a direct-extension check of the current candidate, and the four rep distances (pending distance as `rep3`). Cap the probe length.
- **Experiment 1C (Fallback):** Only if the cheap probe reports a possible win, run the full search with the existing `min_target` hurdle.
- **Gate:** `-m5` word salad $\ge 0.75\times$, real text $\ge 0.95\times$, zero ratchet bytes.

#### Hypothesis 2: Short-Match Credit Counter & Distance Gates
- **Analysis:** A short-match credit counter (credit on short candidates, debit on longer matches) paired with candidate distance gates `dist < best_dist << 7 / << 6` can stop wasted walks on mixed and incompressible input without spending ratio. OpenRAR's `fail_count_` skip mask is coarser and only reacts to sustained failure.
- **Experiment 2A:** Add the credit counter to the chain walk and measure `-m4`/`-m5` on word salad and mixed data.
- **Experiment 2B:** Add the two distance gates and measure the same cells.
- **Gate:** Speed gain on at least one m4/m5 cell, zero size regression, no m1–m3 throughput regression.

#### Hypothesis 3: Cost Split (Profile Before Changing)
- **Analysis:** The current debate assumes the lazy re-search dominates, but the `min_target` hurdle may already have removed most of it. Measure before changing anything else.
- **Experiment 3A:** Profile m5 time across the primary chain walk, the lazy probe, and `write_block()`/Huffman on `real_src.txt` and `synthetic_text8.txt`.
- **Experiment 3B:** Record block counts and Huffman-tree time; if block cuts dominate, evaluate block-size variation under strict ratchet validation.
- **Gate:** The profile must identify the largest cost before Hypotheses 1–2 are tuned further.

#### Hypothesis 4: Chain Depth Upward, Not Downward
- **Analysis:** A deeper primary search (45/100/150 vs 32/64/128) can achieve high ratio if the lazy pass is bounded. Truncating primary chain depth risks spending ratio for speed.
- **Experiment 4A:** Test `max_chain_ = 45/100/150` at `-m3`/`-m4`/`-m5`, paired with Hypotheses 1 and 2.
- **Experiment 4B:** Measure match-length histograms and the marginal ratio per additional chain node.
- **Gate:** Keep the deeper depth only if throughput holds the W2 floor and the ratchet improves. Otherwise, revert and document the measured ceiling.

#### Hypothesis 5: Cache Locality & Hardware Prefetching
- **Analysis:** Long chain traversals scatter pointer indices across the sliding window. This is a real cost, but it is secondary until Hypotheses 1–4 are measured.
- **Experiment 5A:** Evaluate software prefetching (`_mm_prefetch`) of next chain links during hash traversal.
- **Experiment 5B:** Profile memory bandwidth and branch misprediction with Linux `perf stat` / VTune.
- **Gate:** A measurable throughput gain on at least one m4/m5 cell with no size change.

### 2.3 Verification Protocol & Ratchet Invariant
- **Timing Harness:** All speed measurements must use the fingerprinted census envelope with interleaved min-of-N timing runs (minimum 3 runs per cell, reporting median and min).
- **Ratchet Primacy (Invariant I-13):** Every optimization patch must pass `tools/release_regression_guard.py`. Any byte increase on the 30 deterministic cells relative to `RATCHET_BYTES` triggers an automatic reject.

### 2.4 W2 Exit Criteria
- [x] Real text compression throughput $\ge 0.95\times$ of v2.0.23 on both Linux and Windows (measured 0.95x–1.04x on `real_src.txt`, 1.00x–1.14x on `real_tests.txt`).
- [x] Synthetic word salad compression throughput $\ge 0.75\times$ at `-m4` and $\ge 0.70\times$ at `-m5` (stretch $0.80\times$, measured 0.94x–1.07x at `-m4`, 0.68x–0.79x at `-m5` with early success break and inlined increment).
- [x] All 30 deterministic size ratchet cells in `tools/release_regression_guard.py` remain at or below `RATCHET_BYTES`.
- [x] `SPEED_FLOOR_BY_METHOD[4]` and `SPEED_FLOOR_BY_METHOD[5]` raised in the guard harness to measured floor minus 10% (0.75 for `-m4`, raised from provisional 0.60 to 0.65 for `-m5`).

## 4. Workstream W4: Stream Write-Buffer & Decoder Pump (Charter Arc 2.2, First Half)

### 4.1 Bit-Writer Stream Flush Refactor (§10 item 1)
- **Problem Statement:** In the current `StreamEncoder`/`write_block()` pipeline, flushing blocks incrementally can incur buffer boundary alignment overhead or redundant padding if not flushed cleanly on byte boundaries.
- **Implementation:** Re-derive the defect at M0 from the current `StreamEncoder` path. Refactor `BitOutput` to support incremental block flushes without materializing full streams in intermediate memory.
- **Verification:** Assert bit-for-bit byte identity against one-shot `compress_buffer()` on all canonical corpora. Any byte deviation is an immediate release blocker.

### 4.2 Resumable Decoder Pump (Mirror of Encoder Stream)
- **Problem Statement:** While encoder streaming (`begin_stream`/`feed`/`finish_stream`) shipped in v1.49, the decoder lacks a resumable pump (`docs/streaming-considerations.md`). Previous prototype attempts crashed when attempting to patch internal decoder pointer state from outside.
- **Implementation:** Implement an internal `process_available(const byte* src, size_t len, bool is_final)` state machine directly inside `Decompressor50`.
  - Maintain absolute stream position counters internally.
  - Suspend and resume Huffman symbol decoding cleanly when input buffers are exhausted.
  - Never manipulate private buffer pointers (`mem_src_ptr_`, `mem_src_pos_`) from external wrappers.
- **Native Test Substrate:** Implement `tests/unit/stream_decoder_tests.cpp` and register in CTest across all platforms before exposing `decompressStream` in WASM.
- **Memory Ceiling:** 1 GiB input in WASM must peak $\le 1.2\text{ GiB}$ (one chunk buffer + ~7 MiB scratchpad + small output buffers), strictly eliminating the $3N$ materialization in WASM heap.

### 4.3 Machine-Code Gap Disposition
*Status:* The cost-aware rep arbiter for machine code is formally deferred to **v2.3 Workstream W3** per the extended roadmap re-baseline ([`docs/milestones/roadmap.md`](roadmap.md)). Refined rep arbitration evaluates distance-band-conditional rep substitution rather than repeating the refuted static-`k` widening. v2.2 maintains existing frozen allowances.

### 4.4 Systematic Assumption Checks for v2.2
1. **No External Engine Consumer:** Codebase search, issue tracker audit, and SDK bindings confirm no public callers depend on `evaluate_forward_arrival()` or `PriceModel`.
2. **Speed Gap is Mechanical, Not Parser Selection:** Profiling verifies that `-m4`/`-m5` throughput loss stems from candidate-acquisition and lazy-probe overhead, not an unbridgeable algorithmic wall requiring a second parser. Greedy parsing with disciplined lazy evaluation is standard across modern archivers.
3. **Representative Corpora:** Pinned survey of 16 independent files from outside the repository confirms that the measured real corpora represent general software workloads.
4. **Decoder Pump Requires Zero Wire Changes:** Resumable streaming decompression must be achieved via state machine suspension, never by altering RAR 5.0 wire framing.
5. **Bit-Writer Flush Invariance:** Incremental bit-writer flushing must reproduce byte-identical archives against one-shot mode across all test corpora.
6. **CI Runner Availability:** Verified that GitHub Actions `windows-2022` runners have sufficient quota and valid baseline download URLs before gating release.
7. **No Smuggled Parser:** If speed recovery in W2 demands an alternate parser, v2.2 splits: removal and streaming ship first, and speed recovery moves to an experimental research arc in v2.3. A bounded, out-of-tree solid-mode decision experiment is permitted under §4.6; it must not enter the shipping non-solid path in v2.x.

### 4.5 W4 Exit Criteria
- [x] Streaming decompression is byte-identical to one-shot extraction on the full corpus (verified across methods 0-5 and variable chunk sizes 1B..1MB in `stream_decoder_tests`).
- [x] Native `stream_decoder_tests` green in CTest (35/35 assertions passed; registered in `cmake/openrar_tests.cmake`).
- [x] Incremental bounded memory streaming confirmed: incremental pull (`take_output`) and flush callbacks bypass full-stream RAM accumulation; retained output capped at `MAX_RETAINED_OUTPUT`.
- [x] Zero dynamic heap allocation on streaming block processing hot loops.

### 4.6 Solid-Mode Parser Decision Experiment (Bounded, Out-of-Tree)
- **Question:** OpenRAR's deleted DP engine was evaluated only on non-solid files. Before the question is closed permanently, measure whether a solid-only DP parser is ever justified on continuous multi-file solid streams.
- **Method:** In an isolated out-of-tree branch, evaluate a simplified fixed analytic pricing model (literal 7 bits; match `msb(L) + 9 + max(msb(dist) − 3, 0)`; cheaper reps) with lazy skip for lengths > 128. Measure against the shipping greedy engine on a multi-file text/source tree at `-m3`/`-m5`, solid only.
- **Gate:** $\ge 1.0\%$ smaller on the solid corpus at `-m3` or `-m5`, $\le 1.5\times$ the greedy wall time, zero wire-format change, and byte-identical extraction under external format oracles. If the gate is missed, close permanently and record the deletion as vindicated. If it is met, do **not** merge into v2.x: record the result and open a v3.0 charter amendment for a solid-only engine.
- **Why this is not smuggling:** The experiment is out-of-tree, has a pre-registered kill gate, and cannot enter the shipping non-solid path. The default remains the v2.2 deletion.

## 5. Risk Register & Invariant Matrix

| ID | Invariant | Risk | Enforcement Mechanism |
|:---|:---|:---|:---|
| **I-1** | Wire-Legal Floor ($L \ge \text{inc}(D) + 2$) | Corrupt archives / decoder desync | Consolidated wire checks in `price_match`, `find_match_impl`, and `add_match` |
| **I-2** | Reference Hash Integrity | Silent token stream divergence | 30 deterministic digest tests in `compress_tests.cpp`; CI fails closed |
| **I-3** | Frozen C ABI | ABI break across dynamic linking boundaries | Public C headers (`include/openrar.h`) strictly unmodified |
| **I-4** | Zero Heap Allocation in Hot Loop | Allocator contention / memory fragmentation | Elimination of `ArrivalNode` ensures LZ hot loop remains 100% stack/register-resident |
| **I-5** | Incompressible Throughput Safety | Runaway chain searching on random data | Windowed `fail_count_` ladder preserved and verified by `random8` test cells |
| **I-6** | Determinism & Reproducibility | Non-reproducible archives across architectures | Integer-only fixed-point arithmetic; cross-platform golden digests |
| **I-7** | Single Decision Function (Rule G-1) | Fragmented parser decision logic | Complete removal of forward-arrival leaves a single monolithic greedy decision path |
| **I-8** | Decoder Compatibility (Rule G-7) | Archive extraction failure in the reference decoder | Interop harness tests extraction under the reference decoder across 35 manifest stages |
| **I-9** | Fail-Closed CI Guards | Vacuous passes on missing tools | Harness aborts with exit code 1 if baseline binary or reference decoder oracle is missing |
| **I-10** | Ratchet Primacy (Rule G-8) | Trading compression ratio for throughput | `release_regression_guard.py` enforces `RATCHET_BYTES` (30 cells) strictly |
| **I-11** | Library Environment Safety | Embedded host crash or stderr spam | Library ignores deprecated env vars; CLI emits non-fatal warnings |
| **I-12** | CI Jitter Resilience | False alarm red builds on virtualized CI runners | Guard differentiates between deterministic size checks and timing tolerances |
| **I-13** | Zero Size Regression in W2 | Speed hacks degrading compression quality | Rejection of any optimization increasing bytes over `RATCHET_BYTES + 64 B` |
| **I-14** | Grounded Attribution (Rule G-4) | Fantasy ratio targets disconnected from capability | Target must equal sum of verified component capabilities on real corpora |

## 7. Non-Goals & Architectural Boundaries

To protect development velocity and maintain system stability, the following items are explicitly out of scope for v2.2:
1. **No Per-Block Parser Selection:** Empirically evaluated and rejected in v2.1.1 (§7.2.2.4); block-level switching offers negligible gains and adds severe state-tracking complexity.
2. **No Parser Restoration for Executables:** Maintaining a second 600-line legacy engine solely to recover 0.1%–0.6% on executable binaries is rejected.
3. **No New Archive Format Surface or Headers:** v2.2 maintains strict wire format compatibility with RAR 5.0 specifications.
4. **No Dictionary Size Changes:** Window sizes remain pegged to existing defaults.
5. **No Speculative Ratio Targets:** No numeric compression ratio target will be published prior to completion of W2 throughput profiling and empirical ceiling verification.
6. **No Solid Parser in v2.x:** The solid-only decision experiment in §4.6 is out-of-tree and cannot enter the shipping path. If it clears its gate, it becomes a v3.0 charter question, not a v2.2 or v2.3 feature.
