## 1. Executive Summary & Audit Posture

Milestone v1.51.0 delivers complete, mathematically proven, and empirically verified sandbox scope expansion across encrypted and multi-volume archives, accompanied by end-to-end enforcement of the FMM-51 Failure Mode Matrix:
1. **PBKDF2 Iteration Workbound Ceiling (FMM-51-1):**
   - Enforced deterministic iteration workbound ceiling `MAX_PBKDF2_LG2 = 24` across [`src/crypto/pbkdf2.hpp`](../../src/crypto/pbkdf2.hpp), [`src/format/header_reader.cpp`](../../src/format/header_reader.cpp), and [`src/archive/archive_reader.cpp`](../../src/archive/archive_reader.cpp).
   - Rejects maliciously excessive key derivation workbounds immediately with `RAR_ERR_PASSWORD_TIMEOUT` (−16, exit 12) rather than permitting catastrophic CPU exhaustion.
2. **Multi-Volume Descriptor Handling (FMM-51-2):**
   - Missing or corrupted volume descriptors in multi-volume archive chains fail cleanly with `RAR_ERR_MISSING_VOLUME` (−13, exit 6) without unbounded wait or unhandled crashes.
3. **Worker Crash & Isolation Breach Recovery (FMM-51-3):**
   - Broker detects unexpected worker exit, abnormal termination, or severed IPC pipes across pipes/sockets, translating containment collapse into a clean decode failure with `RAR_ERR_CONTAINMENT_BREACH` (−17, exit 2).
4. **Corrupted Encrypted Header Detection (FMM-51-4):**
   - Crypt block padding failures, MAC validation drops, and corrupted headers cleanly map to `RAR_ERR_DECRYPT` (−18, exit 13).
5. **Worker Resource Exhaustion & OOM Mapping (FMM-51-5):**
   - Out-of-memory and allocation failures within worker processes map deterministically across IPC frames to `RAR_ERR_RESOURCE_EXHAUSTION` (−19, exit 8).
6. **Broker-Side Anti-Forgery Integrity Verification (FMM-51-6):**
   - Host broker performs independent, streaming CRC-32 and BLAKE2sp calculation over worker-supplied data chunks. Forged success tokens or mismatched checksums are rejected immediately with `RAR_ERR_CRC_MISMATCH` (−4, exit 3).
7. **Loud Containment Degradation Reporting (FMM-51-7):**
   - When running in degraded mode (`OPENRAR_IN_PROC=1` or when platform isolation primitives are unavailable), [`src/archive/extraction_report.cpp`](../../src/archive/extraction_report.cpp) emits `"sandbox_active":false` visibly in the compact JSON extraction summary (V-2).
8. **ABI & SDK Registries:**
   - Public C ABI [`include/openrar/openrar_dll.h`](../../include/openrar/openrar_dll.h) allocated −16 (`OPENRAR_ERR_PASSWORD_TIMEOUT`), −17 (`OPENRAR_ERR_CONTAINMENT_BREACH`), −18 (`OPENRAR_ERR_DECRYPT`), and −19 (`OPENRAR_ERR_RESOURCE_EXHAUSTION`).
   - Reserved slots −8 and −10 remain strictly unassigned per the frozen ABI contract.
   - Bindings updated across C# (`OpenRAR.cs`), Python (`_native.py`), and TypeScript (`openrar-archive.d.ts`).
