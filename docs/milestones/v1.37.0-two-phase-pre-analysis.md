## 0. The statelessness question — answered

**The question.** Phase 1 workers must decode symbol spans concurrently. That
is only sound if the token stream's bit layout is a pure function of the
tables in force — no token's bits may depend on rep state, last length, or
output position — and if the operation records carry everything the applier
needs. The original Gate 0's window-half question is thereby REPLACED: the
applier is sequential and resolves every cross-range reference against its
own window; no worker ever waits on another.

**Verified structurally** (independent format verification; each finding
re-checked against our decoder and our spec 03): per token class —
literal (LD < 256), filter (256), repeat-last-length (257), rep0..3
(258–261 + RD length symbol), fresh match (≥ 262: length extra bits, DD
distance slot, raw extra distance bits, LDD low nibble iff d_bits ≥ 4) —
no field's WIDTH depends on anything but the tables. Two semantic
dependencies exist and both are applier-side by design: the filter start
delta is relative to the output position at the token (stored as-read,
resolved at apply), and the fresh-match length increments (+1 > 0x100,
+1 > 0x2000, +1 > 0x40000) key on the resolved distance — resolvable in
phase 1, where the distance is already decoded, and applied there exactly
once (the record carries the ADJUSTED length; rep lengths carry no
increments, matching our decoder).

**Verified empirically**: the parked scout — a symbol-only sequential pass
whose recorded per-block state (rep distances, tables, output spans) was
validated 141/141 block-by-block against the sequential decoder — is exactly
the statement "sequential state is a function of the symbol stream alone",
on real members. A phase-1 worker is the scout restricted to a span of
blocks.

**Verified against the black-box scaling record** (original Gate 0 §0): the
reference's 1.29–1.50x on text vs 1.07x on zeros and 0.95x on 4-block
members is consistent with parallelizing ONLY the symbol stage — our probe
(§1) measures the same shape from our side.

**One deliberate divergence hazard, decided here**: filter types 4–7.
Outside analysis reports one reference decoder DROPS such regions from the
output entirely; our decoder (and spec 04) passes them through raw — bytes
kept, region emitted untransformed. This is a hostile-stream behavioral
difference only (no legitimate encoder emits them); we KEEP our documented
behavior. Both phases inherit the sequential decoder's checks verbatim —
see §4.

α = scout / sequential (both in-kernel, null callback): the symbol-decode
fraction of the coupled decode. Record estimate = tagged-varint encoding
(literal 1 B, fresh ~8 B, rep ~3 B, 257 1 B, filter ~13 B).

Findings:

1. **α is 0.53–0.74 on real data** — the symbol stage is the MAJORITY of
   decode and it parallelizes. The unpipelined shape (all symbols, then all
   apply — the wall model `R/(1+(R−1)α)`) caps at 1.24–1.54x at R=4,
   matching the reference's measured 1.29–1.50x; **pipelining the applier
   with the symbol workers** (apply span k while span k+1 decodes) moves the
   floor to the apply stage: wall ≈ max(α·seq/R, (1−α)·seq) → 2.1–3.8x
   kernel ceiling at R=4 on these corpora. THE design lever of this arc.
2. **Record volume is bounded in practice**: 1.0–1.25x output on real
   corpora, 0.0002x on run-heavy data; worst legal case (all literals) is
   1x output, and pathological match-dense streams are bounded by ~2x output
   (a minimum match spends ≥ 1 packed byte to emit ≤ ~6 record bytes).
   Per-SPAN chunked records (§2) make resident record memory O(span), not
   O(member) — the design-wall hazard "record memory scales with member
   size / spill for very large members" DISSOLVES: no spill mechanism, ever.
3. **Zeros/overhead-bound members stay sequential by gating** (α = 0.10;
   parallelism there is pure overhead — the reference's own 1.07x confirms
   the shape). The amortization floor must key on PACKED size, and the
   span count on block availability (a 3-block member has nothing to
   split — the reference's 0.95x on 4 blocks is the same admission).

## 2. The design (ours)

Two phases, one member, pipelined:

- **Phase 0 — pre-scan** (sequential, cheap): walk block headers
  byte-aligned (spec 03 framing: flags/check/size, bits 2:0 of flags =
  last-byte bit count − 1), parse table descriptions where bit 7 is set,
  and produce the block timeline (per block: header bit position, payload
  end bit, description in force) and the table timeline. Blocks with bit 7
  clear carry the previous table set. Cost ≈ header walk + one
  description parse per table block (~7 µs each — the v1.31 measurement);
  ~1 ms on a 128-block member. Reuses the decoder's header reader and
  description parser verbatim. This generalizes the parked scout: the
  scout ALSO walked all tokens; the pre-scan does not need to.
- **Phase 1 — parallel symbol decode** (R workers, R = clamp(threads, 2, 8)):
  workers claim contiguous block spans (static split at block boundaries
  nearest an even PACKED-byte split; a worker needs only the timeline's bit
  positions and the parsed tables in force at its first block). Each worker
  decodes its span's tokens and appends OPERATION RECORDS — no window, no
  writes, no rep-state dependencies:
  - `LIT` — 1 byte.
  - `MATCH` — varint length (adjusted: the +1/+1/+1 distance-band ladder
    applied here, exactly once), varint64 distance (fully resolved; slot-64+
    distances need 64 bits on > 4 GiB windows).
  - `REP` — varint index 0..3, varint length (RD-decoded, no ladder).
  - `R257` — no payload; the applier re-emits (old_dist[0], last_length)
    from its own state, no-op when last_length = 0.
  - `FILTER` — raw start delta (as-read 1..4-byte vint), length (post-clamp:
    > 0x400000 records as 0), type, channels. All semantic checks that need
    positions stay in the applier (§4).
  Position-free validity checks (dist = 0, dist > win_size) fail the worker
  early; everything position-dependent fails at the applier with sequential
  semantics (§4).
- **Phase 2 — the applier** (sequential, one thread): a record-driven clone
  of `decompress_internal`'s apply path — same ring window, same
  `copy_match` semantics (zero-fill past the written prefix, wildcopy RLE
  rules, `dist == win_size` advance case), same filter queue lifecycle and
  out-of-place transforms, same flush triggers (64 KiB cadence + filter
  completion) so the emitted byte AND chunk sequence is bit-identical to the
  sequential decoder's. It consumes spans strictly in order, maintaining
  old_dist[4]/last_length/output position itself; the filter start delta
  resolves against its running position.
- **The pipeline**: the applier consumes span k while phase-1 workers decode
  spans k+1..; a bounded in-flight window (default 2 spans ahead of the
  applier) bounds resident record memory; a worker finishing further ahead
  parks on a semaphore. Cancellation and worker failure propagate through
  the same flags (§4).

Why the parked designs failed and this does not: designs 1–3 coupled the LZ
chain into every worker (wait-on-producer → serialized; overlap → poisoned
ring; from-zero → O(member) each). Here NO worker touches the window — the
LZ chain lives entirely in the single applier, where it is inherently
serial, and everything else (the majority of the time, per α) is parallel.

## 3. Gating rules (all must hold; else sequential — bit-identical, unchanged)

- G1 `-mtN` with N ≥ 2 (default 2 when unset — D9 of the original review),
  kill switch `OPENRAR_NO_PARALLEL_DECODE=1`; single-file member, not split
  across volumes. **Solid chains stay sequential this arc** (see §8).
- G2 algorithm version 0, method 1–5; stored members stay on the stored
  path.
- G3 amortization: packed size ≥ workers × 4 MiB AND ≥ 2 usable spans
  (block count and the ≥ 0x20001-Byte oversized-block rule: a member of one
  giant block has nothing to claim — sequential).
- G4 pre-scan completes cleanly (every header checksum-verified,
  descriptions parse, chain ends where the scan says); any anomaly →
  sequential. The pre-scan is a READER, never a trust boundary.
- G5 record-pool bound: a span's record bytes are capped at
  `max(4 MiB, 4 × span packed bytes)`; a worker that would overflow
  aborts its span → SEQUENTIAL fallback (fail-safe-identical: the sequential
  path re-decodes from scratch and owns the verdict). Replaces the old G5
  dest-size budget — there is no dest-sized buffer in this design.
- G6 WASM/ILP32 builds never engage (compile the driver out; the decision
  function answers false unconditionally).

## 4. Security posture (normative)

- **Fail-safe-identical rule**: ANY anomaly on the parallel path — pre-scan
  anomaly, worker parse failure, record overflow, applier check failure,
  worker exception, OOM, cancellation — fails the entry exactly as the
  sequential decoder would fail it, or (where the parallel path cannot
  reproduce the verdict) falls back to a full sequential decode whose
  verdict IS the answer. No partial output ever reaches the consumer; the
  sequential error taxonomy is unchanged.
- The applier runs the sequential decoder's checks verbatim, in the same
  order, on the same values: rep-distance sentinel/window validation,
  filter length > window rejection, disjoint-and-ordered region rejection
  (overlap/backward regions), aggregate filter budget
  (`filters_total_len ≤ dest_size + win_size`), region count cap (65536),
  dest_size clamping with the sequential truncation semantics
  (LastBlock-below-dest accepted; otherwise truncated → failure). Phase 1
  performs position-free checks only and never decides acceptance.
- The pre-scan is parse-only over untrusted bytes with the existing header
  caps (vint bounds, 2 MiB header ceiling); it allocates O(blocks +
  table-sets), bounded by the same per-block bounds.
- Worker record buffers are pre-bounded (G5); the in-flight window bounds
  aggregate record memory regardless of member size; adversarial streams
  can only waste bounded memory and fall back.
- Fuzz/attack corpus gates every step (CVE-2025-8088/2023-38831/2023-40477
  classes, bombs, hostile vints, hostile tables), plus MT-vs-ST byte-identity
  fuzzing on everything the fuzzer generates, plus the new records↔bytes
  equivalence fuzz (§6).

## 6. Named tests (expanded in the implementation plan)

- T-UNIT-1: MT/ST byte-identity across the interop + fuzz corpora (the
  parked identity harness, retargeted: parallel records → applier vs
  sequential decode, bytes AND callback chunk boundaries).
- T-UNIT-2: records↔bytes equivalence — sequential scout records → applier
  ≡ sequential decode, single-threaded (isolates the applier from the MT
  machinery).
- T-UNIT-3: span-records identity — for every member, phase-1 workers'
  per-span records ≡ the sequential scout's records for the same blocks
  (isolates the span workers).
- T-UNIT-4: gating matrix (each rule individually forces sequential,
  observed via the decision function/diag), F1/F2/F8 rows.
- T-ORACLE: reference archives (Rar 7.20: solid, multivolume, RR, filters,
  -mt-produced) extract byte-identical under `-mtN` N∈{1..8} vs sequential.

## 7. Measurement plan and the arc's prediction

Protocol: v1.34 §3 (paired deltas, min-statistic, alternating order, wiped
`build/rel`, single session). Rows: decode-bound 64 MiB text at `-mt4`/`-mt8`
vs our sequential and vs UnRAR `-mt`; honest no-regression rows (2 MiB
member, 4-block member, stored, multivolume, zeros, `-mt1`, budget-fallback,
hostile fallback).

**Prediction (stated up front, per the arc standard):** pipelined two-phase
lands **1.5–2.2x** over our decode-bound single-member extraction at `-mt4`
on 64 MiB text (kernel ceiling 3.4x at α=0.708; end-to-end shrinkage from
CRC/callback/I/O), with the floor claim **≥ 1.29x = reference parity** and
no-regression everywhere else. α > 0.74 corpora (random: 0.93) scale better;
zeros/overhead-bound stay ~1.0x by gating. Compounding with v1.38 (flat
tables/SIMD) is additive on α, not on the apply floor.

## 8. Scope

Decoder-side: pre-scan, span workers, records, applier, pipeline driver,
gating, tests, docs. NOT in scope: encoder changes; v1.38 kernel work;
solid-chain parallel decode (stays sequential — §9); stored path; durability;

## 9. Open questions parked for a future solid arc

Recorded during this Gate 0's format verification, all solid-only, none
blocking the non-solid scope above:

1. **Phase-2 continuity across members**: a solid chain's window, rep
   state, last length, and table timeline carry across member boundaries;
   only the pending-filter queue resets per member. A future parallel solid
   design must hand phase 2 a continuous record stream across members and
   seed member N's opening flag-clear blocks from member N−1's final
   tables.
2. **E8/ARM position base on solid members — PROMOTED TO A BUG, fixed in
   1.36.x.** What began as a spec/behavior discrepancy was probed against
   the oracle during this Gate 0: a Rar 7.20-made solid archive of four
   members (real DLLs engaging 78 E8 + 28 E8E9 filter tokens) extracts
   byte-divergent from our decoder on members 3–4 (CRC-rejected, exit 2;
   non-solid control of the same members is byte-exact). Root cause:
   `fe.file_offset` (the E8/ARM transform base) was seeded from
   `base_at_entry` — the accumulated solid-chain position — while the
   reference resets the transform base per member even in solid mode
   (oracle-confirmed: patching the decoder to the per-member base makes
   all four members byte-exact). Never triggered by our own archives
   (encoder scopes filters to chain heads) and not silent (CRC32 catches
   it), but it is an interop-breaking decoder defect. Fix + regression
   land as the 1.36.x patch preceding this arc; the two-phase applier
   inherits the per-member semantics (the parked scout already recorded
   per-member offsets).
