## 1. Architectural Strategy & Design

### 1.1 M0: Profiling Gate & Encoder Memory (OPT-P01)
1. **Core Allocator Factoring:**
   - Create [`src/core/default_init_allocator.hpp`](../../src/core/default_init_allocator.hpp) providing `core::default_init_allocator<T>` standard C++17 allocator.
   - Refactor [`src/compress/decompressor50.hpp`](../../src/compress/decompressor50.hpp) to use this shared header.
2. **OPT-P01 in Compressor50:**
   - Update `prev_` and `prev64_` in [`src/compress/compressor50.hpp`](../../src/compress/compressor50.hpp) to use `default_init_allocator`.
   - In [`src/compress/compressor50.cpp`](../../src/compress/compressor50.cpp), replace `prev_.assign(win_size_, -1)` and `prev64_.assign(win_size_, -1)` with `.resize(win_size_)`, eliminating multi-megabyte page filling per session/MT chunk.
3. **M0 Profile Measurement:**
   - Run integrated profiling on heterogeneous test corpus to measure CDC fingerprint time vs pack wall-clock.

### 1.2 M1: Candidate-then-Stitch Parallel Chunker
1. **Shared Cut Rule Factoring:**
   - Factor state transitions so both sequential `feed()` and the parallel stitcher evaluate the exact same rules.
   - Correct the struck halo comment in [`src/compress/cdc_chunker.hpp:30-37`](../../src/compress/cdc_chunker.hpp#L30-L37).
2. **Phase 1 Parallel Scanning:**
   - Divide input buffer into slices overlapping by 63 bytes.
   - Warm up the 64-byte rolling Gear hash over the 63 overlap bytes.
   - Scan for candidate offsets satisfying `mask_strict` and/or `mask_light`.
   - Compress consecutive matches into `CandidateInterval` `(start_off, count, flags)`.
   - Cap entries per slice at `slice_len / 1024`. On overflow, flag the slice to fall back to sequential chunking with diagnostics reported.
3. **Phase 2 Serial Stitcher:**
   - Replay sequential cut selection over intervals:
     - Strict band $[16\text{ KiB}-1, 64\text{ KiB}-1)$: take first strict candidate.
     - Light band $[64\text{ KiB}-1, 256\text{ KiB})$: take first light candidate.
     - Fallback: forced MAX cut at $256\text{ KiB}$, recomputing hash from the 64 bytes ending at the cut.
     - Tail $< 64$ bytes: compute hash using `hash_range`.

### 1.3 M2: Cut-Set Identity Gate & Fallback Verification
1. Add `cdc_parallel_cutset_equals_sequential` in [`tests/unit/cdc_chunker_tests.cpp`](../../tests/unit/cdc_chunker_tests.cpp):
   - Test 5 named corpora:
     - Constant run failing masks ($\ge 1$ MiB).
     - Constant run satisfying mask ($\ge 1$ MiB, exercises interval encoding).
     - 2-byte periodic run (`\xAA\x55`).
     - Pseudo-random data.
     - Structured real-world binary sample.
   - Split boundaries covering all 16 residues mod 16 KiB.
2. Add negative test demonstrating that a 256 KiB restart-halo fails on constant runs.
3. Add candidate-cap overflow test asserting sequential fallback is triggered and reported.

### 1.4 M3: Cut-Rule & Hash Corrections (OPT-K02, OPT-K01)
1. **OPT-K02 FastCDC Normalisation:**
   - Update `mask_strict` (17 bits) and `mask_light` (15 bits) in `cdc_chunker.cpp`.
   - Re-derive and publish effective coverage of `cdc_fingerprint_cap`.
2. **OPT-K01 Whole-Chunk Content Hash:**
   - Evaluate whole-chunk content hash vs last-64-byte window hash under the constraint `sizeof(CdcStreamChunker) <= 64`.
