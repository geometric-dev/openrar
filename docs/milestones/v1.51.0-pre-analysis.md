## 1. Executive Summary & Problem Statement

OpenRAR v1.30 introduced the sandboxed worker architecture (`openrar_worker`) across Windows AppContainer, Linux seccomp-BPF, and macOS Seatbelt (`spawn.cpp`, `worker_broker.cpp`, `worker_main.cpp`). However, v1.30 deliberately restricted worker scope:
1. **Encrypted Archives:** Entries with passwords or encrypted headers fell back entirely in-process (`test_archive_worker` in `main.cpp:854`, `worker_main.cpp:32`).
2. **Multi-Volume Archives:** Multi-volume sets encountered `RAR_ERR_MISSING_VOLUME` in worker scan and forced in-process fallback (`worker_main.cpp:314`).
3. **Error & Exit Taxonomy Ambiguities (U-7 / Appendix A):** New sandbox failure modes (worker crashes, PBKDF2 compute exhaustion, header decryption corruption) had no dedicated error codes in `include/openrar/openrar_dll.h` and lacked definitive CLI exit mappings.

v1.51 expands sandbox coverage and formalizes the failure matrix under the non-negotiable architectural constraints of Invariant I-4 (Contract Registry Stability), G-4 (Verification Precedes Delivery), and V-2 (No Undisclosed Containment Degradation).

## 2. Appendix A: Error & Exit Mapping Authority (U-7 Resolution)

### 2.1 Oracle Analysis of Unused CLI Exits (9 and 12)
Reference CLI exit taxonomy defines:
- `0: Success`
- `1: Warning (non-fatal error)`
- `2: Fatal error`
- `3: CRC / integrity error`
- `4: Attempted modify locked archive`
- `5: Disk write error`
- `6: Open file error`
- `7: Command-line user error`
- `8: Memory allocation error`
- `9: Create file error`
- `10: No files matching pattern`
- `11: Bad password`
- `13: Corrupt or invalid archive`
- `255: User break / cancellation`

In OpenRAR `main.cpp:107-119`, slots **9** and **12** were marked unused.
- **Exit 12:** Unassigned across both WinRAR and OpenRAR. We designate **`EXIT_PASSWORD_TIMEOUT = 12`** for PBKDF2 work-bound exhaustion, strictly distinguishing denial-of-service password traps from wrong passwords (`EXIT_BAD_PASSWORD = 11`).
- **Exit 2 (`EXIT_FATAL`):** Worker crashes represent container breaches / execution failures (`RAR_ERR_CONTAINMENT_BREACH`), which are fatal decode errors rather than security events.

### 2.2 Complete Error & Exit Code Authority Table

| Error Symbol | Numeric Value | Status | CLI Exit Code | Trigger / Cause |
|---|:---:|:---:|:---:|---|
| `RAR_ERR_CRC_MISMATCH` | −4 | Existing | `3` (`EXIT_CRC`) | Payload corruption or forged HMAC token (FMM-51-6) |
| `RAR_ERR_NOMEM` | −5 | Existing | `8` (`EXIT_MEMORY`) | Host / local process OOM |
| `RAR_ERR_BAD_PASSWORD` | −7 | Existing | `11` (`EXIT_BAD_PASSWORD`) | Key derivation succeeds but `PswCheck` mismatch |
| `RAR_ERR_MISSING_VOLUME`| −13 | Existing | `6` (`EXIT_OPEN`) | Split-entry volume missing or descriptor missing (FMM-51-2) |
| `RAR_ERR_LIMIT_EXCEEDED`| −15 | Existing | `8` (`EXIT_MEMORY`) | Caller budget / extraction limit reached |
| `RAR_ERR_PASSWORD_TIMEOUT` | **−16** | **NEW** | `12` (`EXIT_PASSWORD_TIMEOUT`)| PBKDF2 count exceeds deterministic work bound (FMM-51-1) |
| `RAR_ERR_CONTAINMENT_BREACH` | **−17** | **NEW** | `2` (`EXIT_FATAL`) | Worker process unexpected termination/SIGKILL/crash (FMM-51-3) |
| `RAR_ERR_DECRYPT` | **−18** | **NEW** | `13` (`EXIT_BAD_ARCHIVE`) | Corrupted encrypted header / malformed crypt block (FMM-51-4) |
| `RAR_ERR_RESOURCE_EXHAUSTION` | **−19** | **NEW** | `8` (`EXIT_MEMORY`) | Sandboxed worker OOM rejection / memory floor reached (FMM-51-5) |

> [!IMPORTANT]
> Slots **−8** and **−10** remain intentionally unassigned per Invariant I-4 to preserve binary compatibility with consumers range-checking known error codes.

## 3. Deep Dive: FMM-51 Failure Modes & Mitigations

### 3.1 FMM-51-1: PBKDF2 Work-Bound Protection (`test_sandbox_pbkdf2_workbound_rejected`)
- **Vulnerability:** Attacker crafts a RAR5 archive specifying an enormous PBKDF2 iteration count (e.g. `lg2_count = 31` $\rightarrow 2^{31}$ iterations), causing denial of service and CPU starvation.
- **Mitigation:**
  - Enforce a deterministic count ceiling: `MAX_PBKDF2_LG2 = 24` (i.e. $16,777,216$ iterations) in `Pbkdf2Rar5` and `ArchiveReader`.
  - When `crypt.lg2_count > MAX_PBKDF2_LG2`, fail immediately with `RAR_ERR_PASSWORD_TIMEOUT` (−16) without spinning CPU cycles.
  - CLI maps this to exit code `12`.

### 3.2 FMM-51-2: Volume Descriptor Handling (`test_sandbox_multivol_descriptor_failure`)
- **Behavior:** In multi-volume archives, when a split entry's continuation extent volume is absent or its descriptor cannot be located:
  - Fail closed with `RAR_ERR_MISSING_VOLUME` (−13).
  - CLI maps to `EXIT_OPEN` (6).

### 3.3 FMM-51-3: Worker Crash Recovery (`test_sandbox_worker_crash_recovery`)
- **Principle:** A sandboxed worker crash (e.g., SEGV, SIGKILL, memory exhaustion abort) is a **decode failure, not a security breach**.
- **Mitigation:**
  - Broker's `read_frames` detects broken-pipe/EOF.
  - Broker marks phase `Closed`, invokes `kill()` to reap process handles cleanly without deadlock, and returns `RAR_ERR_CONTAINMENT_BREACH` (−17).
  - CLI maps to `EXIT_FATAL` (2).

### 3.4 FMM-51-4: Corrupted Encrypted Header (`test_sandbox_encrypted_header_corrupt`)
- **Behavior:** If a `HEAD_CRYPT` block contains invalid salt length, corrupted payload padding, or unsupported crypt version $\ne 0$:
  - Emit `RAR_ERR_DECRYPT` (−18).
  - CLI maps to `EXIT_BAD_ARCHIVE` (13).

### 3.5 FMM-51-5: Worker OOM Rejection (`test_sandbox_worker_oom_rejection`)
- **Behavior:** When the worker hits memory limits during decompression:
  - Worker notifies broker via `FrameType::Error` with `RAR_ERR_RESOURCE_EXHAUSTION` (−19).
  - CLI maps to `EXIT_MEMORY` (8).

### 3.6 FMM-51-6: Broker-Held Token Authentication (`test_sandbox_fail_open_forgery_denied_hmac`)
- **Threat Model:** A compromised worker attempts to forge extraction success or bypass integrity validation by emitting an artificial `EntryResult`.
- **Mitigation:**
  - The broker computes a running hash of chunks received from the worker.
  - If the worker's reported status or CRC contradicts the broker's independently computed CRC, broker rejects with `RAR_ERR_CRC_MISMATCH` (−4) $\rightarrow$ `EXIT_CRC` (3).

### 3.7 FMM-51-7: Loud Containment Degradation (`test_sandbox_degraded_mode_is_loud`, V-2)
- **Invariant:** When containment is degraded via `OPENRAR_IN_PROC=1`, `--in-proc`, or unavailable platform sandbox model:
  - Operation may succeed, exit code remains unchanged.
  - JSON summary MUST carry `"sandbox_active": false`.
  - Console prints a loud warning (`W: sandboxed worker unavailable...`).

### 3.8 Zero Key Material in Broker Dumps
- All `Rar5Keys` and password strings in the broker are wiped using volatile-zero (`crypto::secure_wipe`) upon completion or error.
