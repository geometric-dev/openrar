# OpenRAR v2.1.0 Track E Phase M2: Dynamic Shannon Entropy PriceModel Proposal

## 1. Overview
In OpenRAR v2.1.0 Track E, Phase M0 established the baseline census and Phase M1 established the forward-arrival DAG engine with sub-length relaxation and span-aware bit-density selection.
Phase M2 addresses the core pricing oracle that guides the forward-arrival graph parser: the **PriceModel**.

Currently, the price model has two major limitations:
1. **Block 0 Cold-Start Blindness:** For the entire first block (up to 512 KiB, which is 100% of files under 512 KiB), `price_model_` uses static hardcoded constants:
   - All 256 literals are priced at 8.0 bits ($8 \times 256 = 2048$).
   - Distance slots are crudely partitioned into 4, 8, 14 bits.
   - Length slots are partitioned into 5 or 7 bits.
   Because literals are priced uniformly at 8 bits, common characters like ' ' (space, ~2.5 bits in text) or 0x00 (~3 bits in PE binaries) appear 3x more expensive to the parser than they actually are on the wire. The parser therefore aggressively emits low-quality, distant matches (e.g. 4-byte match at 500 KB distance costing 34 bits) instead of emitting 4 common literals (which cost only 12–16 bits on the wire).
2. **Mid-Block Adaptation Stagnation:**
   In multi-block archives, `update_price_model()` is only invoked when `write_block()` runs (every 32,768 tokens or 512 KiB). As statistics shift inside a 512 KiB block, the price model never adapts until the entire block has been committed.

## 2. Proposed Technical Design

### A. Pre-Flight Input Sampling for Block 0 Empirical Prior
Before the first block begins processing (in `begin_archive` / `compress`):
- Take a fast 4 KiB sample of `buf_data_[cur_ ... cur_ + 4096]` (which is already loaded in L1/L2 cache).
- Compute a 256-element byte histogram.
- For each byte $b \in [0, 255]$:
  $$\text{cost}(b) = \min\left(15 \times 256, \max\left(2 \times 256, \text{round}\left(256 \times \log_2\left(\frac{N_{\text{sample}}}{f(b) + 1}\right)\right)\right)\right)$$
- If byte $b$ was not observed, assign the unused symbol penalty: $15 \times 256 = 3840$.
- For distance and length slots, seed the prior based on an empirical power-law distribution ($1/d$ distribution typical of LZ77 offsets).

### B. Fixed-Point Shannon Log2 Lookup Table
- Precompute a 256-element lookup table for $\log_2(x)$ in 8.8 fixed point:
  `kLog2Table[256]` mapping $[1 \dots 256] \to [0 \dots 8 \times 256]$.
- Compute $\log_2(N / f)$ in $O(1)$ without floating point:
  $$\log_2(N) - \log_2(f) = \text{clz}(f) - \text{clz}(N) + \text{mantissa\_lookup}$$
- Guarantees 100% bit-exact determinism across all platforms (x86_64, ARM64, WASM).

### C. Periodic Mid-Block Price Refresh
- Maintain a running token counter `tokens_since_price_update_`.
- When `tokens_since_price_update_ >= 4096`:
  - Recalculate `price_model_.lit_cost`, `price_model_.len_cost`, and `price_model_.dist_cost` from `freq_ld_`, `freq_dd_`, `freq_rd_`.
  - Smooth the running estimate with the previous block's canonical lengths using an exponential moving average:
    $$\text{cost}_{\text{eff}} = \frac{3 \cdot \text{cost}_{\text{running}} + \text{cost}_{\text{prior}}}{4}$$
  - Reset `tokens_since_price_update_ = 0`.
  - Overhead: 500 fixed-point operations every 4,096 tokens ($< 0.05\%$ CPU).

### D. Anti-Finding A-4 (Unused Symbol Penalty)
- Strictly enforce $15 \times 256 = 3840$ for symbols with 0 frequency.
- Never assign `DP_INF` to unobserved literals (any byte may appear).
- Assign `DP_INF` only to wire-inadmissible match parameters.
