# OpenRAR v1.60.0 Implementation Plan: Parallel CDC Multi-Core Fingerprinting & Chunking Engine

**Milestone:** v1.60.0 (Architecture Arc 2.4 — Multi-Core Scalability & CDC Engine)  
**Governance Scope:** Governed by Rule G-1 (Single Decision Function), G-3 (Fingerprinted Measurement), G-8 (Charter Discipline), Invariant I-2 (Bitstream Invariance / Golden Reference), and `architect-challenge`  
**Status:** In Progress / Draft  

---

## 1. Executive Summary & Problem Formulation

In OpenRAR v1.50.0, we introduced parallel Content-Defined Chunking (`CdcChunker::chunk_parallel`) via a candidate-then-stitch mechanism, resolving the unbounded cut-phase flaw in fixed restart halos (S-15) and proving exact cut-set identity.

However, the archive creation pipeline in `src/cli/main.cpp` currently fingerprints file batches serially:
```cpp
for (size_t i = 0; i < queue.size(); ++i) {
    ...
    const CdcFingerprintResult fp_result = fingerprint_file_cdc(
        item.src_path, chunker, hashes[i], fp_cap - total_chunks, file_chunks, threads);
    ...
}
```
Under multi-core execution (`-mt=N`), this single-threaded loop over `queue` creates a severe CPU serialization bottleneck:
1. Files smaller than 512 KiB are fingerprinted sequentially on a single core, leaving all other worker threads completely idle.
2. Even for files $\ge 512\text{ KiB}$, file reading is serialized on the calling thread before slicing.
3. Every invocation of `CdcChunker::chunk_parallel` allocates and tears down a `core::ThreadPool` object, causing unnecessary thread creation and destruction syscall overhead.

Milestone v1.60.0 resolves these bottlenecks by parallelizing the file fingerprint pass across `queue`, introducing pool-reuse in `chunk_parallel`, and strictly preserving deterministic cut sets and fingerprint-index cap discipline (Invariant G-3).

## 2. Technical Specifications

### Specification 1: Concurrent Multi-File Fingerprinting Dispatch

1. **Parallel Task Dispatch:**
   When `threads > 1` and `queue.size() > 1`:
   - Initialize a shared `core::ThreadPool pool(threads);`.
   - Distribute the reading and CDC fingerprinting of pending files across worker threads using `parallel_for` or task submission.
   - Each worker operates with its own `CdcChunker` (or thread-safe const instance) and stream buffer, populating `hashes[i]`, `file_chunks[i]`, and `file_results[i]`.

2. **Deterministic Index-Cap Discipline (Invariant G-3):**
   - In a multi-threaded run, files may finish out of order.
   - However, the hard fingerprint cap `fp_cap` (default 2,000,000 chunks = 32 MiB) is an explicit contract: files that exceed the cap must keep their original order, reported per directive 5.
   - To guarantee bit-exact determinism across any thread count (1, 2, 4, 8, 16):
     After all file fingerprint tasks complete, the main thread performs a deterministic serial scan in queue order $i = 0 \dots N-1$:
     ```cpp
     size_t total_chunks = 0;
     size_t first_unfingerprinted = queue.size();
     for (size_t i = 0; i < queue.size(); ++i) {
         if (queue[i].is_dir || queue[i].is_symlink || queue[i].is_hardlink || queue[i].is_filecopy) continue;
         if (file_results[i] == CdcFingerprintResult::Unreadable) continue;
         if (total_chunks + file_chunks[i] > fp_cap || file_results[i] == CdcFingerprintResult::OverCap) {
             cdc_cap_hit = true;
             first_unfingerprinted = i;
             break;
         }
         total_chunks += file_chunks[i];
     }
     if (cdc_cap_hit) {
         for (size_t i = first_unfingerprinted; i < queue.size(); ++i) {
             hashes[i].clear();
             if (!queue[i].is_dir && !queue[i].is_symlink && !queue[i].is_hardlink && !queue[i].is_filecopy)
                 ++cdc_cap_fallback_files;
         }
     }
     ```
   - This ensures that the exact same files are fingerprinted, the cap fires on the exact same file index, and `plan_cdc_order` receives identical input whether run with `-mt=1` or `-mt=16`.

### Specification 2: Thread Pool Reuse in `CdcChunker::chunk_parallel`

- Extend `CdcChunker::chunk_parallel` signature to optionally accept a pointer to an existing `core::ThreadPool* pool = nullptr`.
- When `pool` is provided, submit phase 1 slicing jobs directly to the existing pool rather than instantiating a local `ThreadPool`.
- Retain backward compatibility: if `pool == nullptr`, construct local pool as before.

## 3. Risk Assessment & Invariant Guardrails

| Risk | Mitigation |
| :--- | :--- |
| **Non-Deterministic File Order** | Prefix evaluation of `fp_cap` in natural queue order $i = 0 \dots N-1$ ensures bit-exact parity across 1..64 threads. |
| **High Memory Concurrency** | Limit concurrency of simultaneous in-memory file buffers via workspace gating (`core::PreparationWorkspaceGate`). |
| **I/O Contention** | Read files using sequential chunk streaming or mapped reads. |
