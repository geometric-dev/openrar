## 1. Executive Vision & Strategic Purpose

OpenRAR v1.56.0 introduced the first working version of the Cost-Aware Forward-Arrival Graph Parser & Symbol Arbiter, achieving substantial compression ratio improvements (up to 5.53:1 on text at m5) and neutralizing the zero-run regression (422 bytes for 8 MiB zeros). However, initial throughput profiling revealed an algorithmic bottleneck on incompressible and binary data due to unpruned forward-arrival horizon evaluations when no valid match candidates exist.

The objective of this release is to deliver the **Complete Forward-Arrival DAG Engine & Match-Finder Modernization (Pillar 1 of the v2.0 Charter)**:
1. **Fast Uncontested Literal Bypass:** Mathematically bypasses 16-node horizon evaluation when no fresh match or repeat match meets the wire admission floor (`min_match_ >= 3`), achieving a >7x throughput increase on incompressible streams and 1.7x on binary streams with 100% bit-exact bitstream invariance.
2. **Method-Adaptive Lookahead & Frugal Search Pruning:** Adaptively scale chain lookahead depth at offset 1 according to the compression method (`m1` vs `m3` vs `m5`), and prune offset-1 searches when offset 0 already holds a dominant candidate (e.g. rep0 match or long low-distance match).
3. **Distance-Costed Chain Pruning in `find_match_impl`:** Accelerate deep hash-chain walks (`m3` and `m5`) by pruning match candidates whose distance base cost mathematically precludes beating the current best candidate.
4. **Multi-Threaded Scaling & Verification (`-mt`):** Verify that chunk-parallel compression (`ParallelBlockPipeline` / `compress_buffer_parallel`) scales linearly without thread contention or state pollution.
5. **Architectural Evaluation & Gate for v2.0 vs v1.57:** Conduct comprehensive benchmarking across text, code, binary, random, and zero-byte corpora. If throughput and ratio deliver the requisite step-change leap across all axes, graduate the release to `v1.57.0`; otherwise, designate as `v1.57.0`.

## 2. Technical Architecture & Components

```mermaid
graph TD
    Input[Input Stream at cur_] --> RunGuard{Run / Zero Guard<br>4+ identical bytes?}
    RunGuard -- Yes --> RunFastPath[Emit Rep0 / Dist 1 Match<br>Advance Span & Skip Horizon]
    RunGuard -- No --> MatchFind[Query Hash Chain & Rep Matches<br>cur_]
    
    MatchFind --> MatchFloor{best.len >= min_match ||<br>rep_len >= min_match?}
    MatchFloor -- No --> FastBypass[Fast Uncontested Literal Bypass<br>Emit Literal, Advance cur_, Continue]
    MatchFloor -- Yes --> Horizon[Evaluate Forward-Arrival Horizon<br>H = 16 bytes, Fixed Stack State]
    
    subgraph "Forward-Arrival Horizon Engine"
        Horizon --> Node0[Offset 0 Candidates<br>Lit, Rep0..3, Slot 257, Match]
        Node0 --> DomCheck{Offset 0 Dominant?<br>rep0 >= 8 or match >= nice/2}
        DomCheck -- Yes --> SkipOff1[Skip Offset 1 Fresh Match Search]
        DomCheck -- No --> CheckMethod{method >= 3 or lazy_tests > 0?}
        CheckMethod -- Yes --> Off1Search[Offset 1 Fresh Search<br>chain bounded by method]
        CheckMethod -- No --> SkipOff1
        Off1Search --> RelaxEdges[Relax All Edges over Horizon]
        SkipOff1 --> RelaxEdges
        RelaxEdges --> TerminalPad[Terminal Horizon Padding to h_eff]
        TerminalPad --> ShortestPath[Trace Back First Token on Optimal Path]
    end
    
    FastBypass --> EmitLiteral[Emit Literal Byte]
    ShortestPath --> CommitToken[Commit Optimal Token]
```

### Component 1: Fast Uncontested Literal Bypass
- **Invariant:** When `best.length < min_match_ && rep_best_len < min_match_`, no match or repeat match can legally start at offset 0.
- Any valid path traversing the horizon from offset 0 MUST emit a literal at offset 0.
- **Action:** Increment `fail_count_`, emit literal `buf_data_[cur_ - pos_base_]`, insert position into hash table, advance `cur_++`, and continue.
- **Complexity:** O(1) instead of O(H * (chain + rep_checks)).

### Component 2: Method-Adaptive Lookahead & Contested Search Throttling
- In `evaluate_forward_arrival()` at offset 1:
  - If offset 0 already found `rep_best_len >= 8` (especially `rep_idx == 0`) or `match_len >= nice_len_ / 2`, offset 1 fresh match search is mathematically incapable of beating offset 0. Prune offset 1 search immediately.
  - Scale offset 1 search chain depth: `std::min<core::uint32>(max_chain_, 16)`. For `m1` (`max_chain_ == 4`), only walk 4 links.

### Component 3: Distance-Costed Early Chain Pruning
- In `find_match_impl()`:
  - During the chain traversal, if `best.length >= 4`, any new candidate must match at least `best.length + 1` bytes to be strictly better by length.
  - Furthermore, if candidate distance `d` has length increment `inc = length_increment(d)` such that `best.length + 1 < inc + 2`, candidate is wire-illegal and skipped.
  - For deep chains, if `cand_dist > 0x40000` and `best.length >= nice_len_ / 2`, break early as distance coding overhead dominates marginal length gains.

### Component 4: Multi-Threaded Compression Scaling Verification
- Verify thread safety of `Compressor50` instances across worker threads in `ParallelBlockPipeline`.
- Assert zero cross-thread cache thrashing on `ArrivalNode` or `PriceModel`.

## 3. Guardrail Compliance & Falsification Ledger

| Guardrail ID | Description & Requirement | Implementation Compliance Strategy |
|---|---|---|
| **A-4** | Unbounded DP prohibited | Bounded lookahead horizon $H = 16$ bytes on fixed stack array. No multi-kilobyte DP buffers. |
| **A-5** | Length-2 match admission on standard chains prohibited | Standard chain matches strictly require $len \ge 3$. Length 2 allowed only on rep matches where distance is already in `old_dist_`. |
| **A-6** | Unpriced candidate source expansion prohibited | Every candidate priced through 24.8 fixed-point `PriceModel`. No uncosted candidate generation. |
| **A-7** | Lazy length->distance ring refuted | Strict forward DAG traversal; no reverse ring rescans. |
| **A-8 / R-M1** | Integrated validation required | All ratio and throughput measurements validated on integrated multi-block compression roundtrips. |
| **ABI Freeze** | C ABI invariance | Zero changes to `openrar_dll.h`, ABI version 1 maintained. |

## 4. Verification & Acceptance Criteria

1. **Byte-Exact Roundtrip Parity:** All archives generated with forward-arrival optimizations decompress byte-exact across OpenRAR and UnRAR 7.20.
2. **CTest Suite Clean Pass:** 100% pass across all 49 CTest test suites (0 failures).
3. **Throughput Target:**
   - Incompressible data throughput $\ge 15$ MB/s (vs 2.15 MB/s unpruned, >7x speedup).
   - Binary data throughput $\ge 3.5$ MB/s (vs 2.13 MB/s unpruned, >1.6x speedup).
   - Zero-run hygiene: 8 MiB zeros $\le 500$ bytes.
4. **Multi-Threaded Scaling:** `-mt=4` throughput on large buffers scales $\ge 2.8\times$ vs single-threaded.
5. **Version Gate Decision:**
   - If ratio improvement on text/code is preserved and throughput meets all targets: present the census to determine `v1.57.0` vs `v1.57.0`.
