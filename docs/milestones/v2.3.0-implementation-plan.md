## 0. Executive Vision & Kickoff Decisions

Milestone v2.2 successfully consolidated the compression engine into a pure greedy-with-lazy pipeline, recovered `-m4`/`-m5` throughput via bounded lazy probing, and established the resumable decoder pump (`process_available`).

Milestone v2.3 is the **mechanical-sympathy and high-performance engineering release**. It tackles the second half of Charter Arc 2.2 and Arc 2.3:
1. **Zero-Allocation Decompression Hot Path:** Completely eliminate all dynamic heap allocations (`malloc`, `operator new`, dynamic vector resizes) from the decompression hot loop (`process_available`, `copy_match`, `write_literal`, filter queues), strictly proving zero-allocation compliance via an instrumented tracking allocator in debug builds.
2. **Chunk-First Circular Window Architecture:** Implement page-pinned circular buffers ensuring an exact $O(\text{window})$ physical memory envelope, eliminating the memory spike when unpacking large files across native, server, and WebAssembly targets.
3. **ISA Recovery Completion & Refutation Protocol:** Re-derive the mathematical mechanism for GFNI half-width RS16 folding, evaluate against the strict 2.0% throughput hurdle, audit 512-bit register usage, evaluate NEON `pmull` vs. nibble lookup tables, and advance the microarchitectural SIMD research track (H-09..H-12).
4. **Greedy Quality Completion:** Systematically evaluate the bounded greedy-quality agenda (split emission, saved-head short matches, EWMA effort switching, and distance-band rep3 substitution) without introducing speculative parsers or violating the size ratchet.

### Kickoff Decisions & Architectural Contracts

| Area | Decision | Implementation & Governance Contract |
|:---|:---|:---|
| **Memory Allocation** | Zero Dynamic Alloc in Hot Loop | Decompression hot path must issue **0 heap allocations** per block/member. Verified fail-closed by an instrumented `TrackingAllocator` during CTest. |
| **Window Buffering** | Pinned Circular Geometry | Pre-allocated circular ring buffer bounded at `min(declared_window, MAX_WINDOW)`. Zero dynamic reallocations during match decoding. |
| **ISA Recovery Gate** | 2.0% End-to-End Hurdle | If GFNI half-width fold or NEON `pmull` yields $< 2.0\%$ throughput improvement over existing v1.22 kernels, close permanently as refuted. |
| **Microarchitectural SIMD** | Intrinsics in `src/compress/arch/` | Implement H-09 (LZ wildcopy pattern doubling) and H-10 (AVX2 batch hashing) using compiler intrinsics with runtime CPU dispatch. Zero standalone `.asm` files unless register spilling forces it. |
| **Greedy Quality** | Isolated Mechanism Evaluation | Each greedy optimization (split emission, saved heads, EWMA effort, rep3 substitution) is evaluated individually against the 4-binary gate and 30 ratchet cells. No bundling. |
| **Digest Invariance** | Strict Determinism (Invariant I-1) | All 30 deterministic ratchet cells in `tools/release_regression_guard.py` must produce bit-for-bit identical digests or shrink without byte regressions. |

## 1. Workstream W1: Chunk-First Memory & Zero-Allocation Decompression

### 1.1 Objective & Rationale
Currently, [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp) dynamically grows its dictionary window via `WindowBuffer::grow(n)` during literal and match emission, and allocates dynamic memory for `filters_`, `filter_scratch_`, and `delta_scratch_`. In WebAssembly and embedded environments, heap growth induces memory fragmentation and risks exceeding the 1.5 MiB WASM memory budget.

### 1.2 Chunk-First Circular Buffers
- **Pre-Allocated Ring Window:** Instead of growing the window geometrically from 256 KiB up to the declared size during decoding, allocate the required circular ring buffer up front (`min(win_size, 64 MiB)`).
- **Safety Padding Margin (Invariant I-15):** Circular window storage must allocate a trailing 64-byte padding zone beyond `win_size`. This guarantees that unaligned 16-byte and 32-byte SIMD stores (wildcopy overshoots in H-09) never write into uncommitted virtual pages or corrupt adjacent heap allocations.
- **Page-Pinned Native VM:** On 64-bit platforms, reserve the virtual address space and commit pages on-demand in 64 KiB page granules, maintaining a true $O(\text{window})$ envelope without intermediate copies or reallocations.
- **Embedded & WASM Budget:** On 32-bit/WASM targets, clamp the dictionary to the declared size or 1 GiB safety limit, utilizing a static pre-allocated buffer pool.

### 1.3 Zero Dynamic Allocation in Decompression Hot Loop
- **Static Scratchpads & Fixed-Capacity Filter Queue:**
  - Replace `std::vector<FilterEntry> filters_` with a fixed-capacity ring buffer (`MAX_PENDING_FILTERS = 256`). Pathological archives declaring $> 256$ concurrent pending filters must **fail-closed immediately** with `DecompressErrorCode::CorruptedArchive`, preventing unbounded allocation and memory exhaustion attacks.
  - Pre-allocate `filter_scratch_` and `delta_scratch_` during decompressor initialization up to `MAX_FILTER_BLOCK_SIZE` (1 MiB), eliminating heap churn during filter execution.
- **Instrumented Scoped Tracking Allocator (`tests/unit/tracking_allocator.hpp`):**
  - Implement a thread-local scoped allocator monitor (`ScopedAllocTracker`) that hooks global `operator new`, `malloc`, and custom allocators.
  - Test suite `stream_decoder_tests` and `decompress_tests` will assert `tracker.alloc_count() == 0` strictly during the span of `process_available()`, avoiding noise from test runner harness setup.

### 1.4 W1 Exit Criteria
- [ ] 0 dynamic heap allocations observed during active decompression loops across all 5 compression methods.
- [ ] Circular ring window operates strictly in-place with zero reallocation copies.
- [ ] WASM heap footprint verified $\le 1.2\text{ GiB}$ on 1 GiB input streams.
- [ ] CTest `stream_decoder_tests` and tracking allocator unit tests pass 100%.

## 2. Workstream W2: ISA Recovery Completion & Microarchitectural Research

### 2.1 GFNI Half-Width RS16 Fold Kernel (§10 item 6)
- **Mathematical Mechanism:**
  GFNI instructions (`_mm512_gf2p8affine_epi64_epi8`) evaluate an $8 \times 8$ affine transformation over $\text{GF}(2)$ for each byte. For half-width GF(2¹⁶) symbols where the upper 8 bits are zero (common in sparse error locations), the $m[2]$ and $m[3]$ matrix multiplications can be folded or bypassed, reducing instruction count from 4 affine evaluations to 2 affine evaluations per 64 bytes.
- **Hard Stop Condition:**
  Evaluate via standalone microbenchmark and integrated archive recovery pipeline. If the end-to-end throughput gain is $< 2.0\%$, formally close the item as refuted and do not ship the complexity.

### 2.2 AVX-512 & NEON Audit
- **AVX-512 Audit:** Verify that `rs16_gfni.cpp` utilizes full 512-bit ZMM registers on capable CPUs (confirmed in v1.22 baseline).
- **NEON `pmull` Evaluation:** Benchmark ARMv8 NEON `pmull` against the existing 16-entry nibble lookup tables (`vqtbl1q_u8`). Design notes in `src/recovery/rs16.cpp` indicate nibble table lookups require fewer instructions per byte than degree-15 polynomial modular reduction; benchmark on Apple Silicon (M-series) and ARM64 Linux to confirm or close.

### 2.3 Microarchitectural SIMD Optimization Track (H-09 .. H-12)
Per [`docs/milestones/v2.x-low-level-simd-assembly-research.md`](v2.x-low-level-simd-assembly-research.md):
- **H-09 (Fast Overlapping LZ Wildcopy & Pattern Doubling):**
  Implement pattern-doubling vector copy (`vpbroadcastb/w/d`, `pshufb`, unaligned 16/32-byte SIMD stores) in `Decompressor50::copy_match`. Eliminates store-forwarding stalls for `dist < length`. Gate: $\ge 15\%$ decompression throughput gain.
- **H-10 (Vectorized Batch Hashing in `Compressor50::hash_range`):**
  Implement AVX2 8-way parallel multiplicative hashing using `_mm256_mullo_epi32` (`vpmulld`) and `_mm256_srli_epi32`. Gate: $\ge 3\%$ end-to-end compression speedup on text/source corpora with zero ratchet drift.
- **H-11 (BMI2 Bitfield Extraction & Branchless Huffman):**
  Implement `_bextr_u64` and branchless 2-level lookup tables in `BitReader` / `HuffmanDecoder`. Gate: $\ge 10\%$ branch miss reduction.
- **H-12 (Dual-Track Match Finding Prefetch):**
  Evaluate `_mm_prefetch` for candidate $N+1$ and interleaved 2-way chain walks. Gate: $\ge 4\%$ gain at `-m5` with `-md16m`.

### 2.4 W2 Exit Criteria
- [ ] GFNI half-width fold evaluated; closed with data or integrated if $\ge 2.0\%$ faster.
- [ ] NEON `pmull` vs. table lookup evaluated on ARM64; disposition recorded.
- [ ] H-09 (Overlapping LZ Wildcopy) implemented and verified in `Decompressor50`.
- [ ] H-10 (AVX2 Batch Hash) evaluated against ratchet in `Compressor50`.
- [ ] Recovery throughput benchmark integrated into CI.

## 3. Workstream W3: Greedy Quality Completion

### 3.1 Bounded Greedy-Quality Agenda
Evaluate the four pre-registered greedy quality mechanisms individually against real corpora and the deterministic ratchet:
1. **Split Emission (H-04):** At match commit time, search for split point $j$ where a shorter-distance match exists at $\text{pos} + j$. Emits literal prefix plus smaller distance code.
2. **Saved-Head Candidates (H-05):** Exploit per-position saved heads for 2/3/4-byte candidates at distances $\le 0x100 / 0x2000 / 0x40000$.
3. **EWMA Effort Switching (H-06):** Dynamically modulate hash probe depth based on running literal-cost exponentially weighted moving average.
4. **Distance-Band Rep3 Substitution (H-07):** In the lazy/rep test, substitute the pending match's distance for `rep3` under strict distance-band gates.

### 3.2 Machine-Code Cost-Aware Arbiter
- Evaluate the cost-aware rep arbiter across all four reference binaries (Windows PE, Linux ELF, two DLLs) with zero static distance concessions ($k$).
- **Gate:** Must win on $\ge 3$ binaries and lose $\le 0.10\%$ on the fourth without regressing `-m1`/`-m2` throughput. Otherwise, close permanently.

### 3.3 W3 Exit Criteria
- [ ] All four greedy mechanisms evaluated independently.
- [ ] Machine-code arbiter passes 4-binary gate or is permanently closed.
- [ ] Zero size regressions across all 30 deterministic ratchet cells.
- [ ] Updated `RATCHET_BYTES` reflecting any compressed size reductions.

## 6. Principal Solution Architect Challenge & Review Verdict

```markdown
# 🏛️ Principal Architect Challenge & Review

**Plan Reviewed:** OpenRAR v2.3.0 Implementation Plan: Zero-Copy Completion, Zero-Allocation Decompression & Mechanical Sympathy  
**Architect Verdict:** 🟢 APPROVED WITH MANDATORY DIRECTIVES

---

### 1. Executive Summary & Core Posture
Following the complete delivery of v2.2 (which retired ~600 lines of dead forward-arrival parser code and restored -m4/-m5 compression speed), Milestone v2.3 focuses on modern mechanical sympathy: zero dynamic allocation on decompression hot paths, streamable circular ring buffers, and microarchitectural hardware acceleration.

The initial technical concept had three critical engineering risks that would have caused runtime corruptions and security failures if unaddressed:
1. **Wildcopy Buffer Overrun Hazard:** SIMD 16/32-byte pattern-doubling stores overshoot match ends. Without an explicit safety padding margin on the circular buffer, vector stores will write into uncommitted virtual memory or corrupt adjacent heap allocations.
2. **Fixed-Capacity Filter Queue DoS Hazard:** Replacing dynamic filter vectors with a fixed 256-element queue creates an overflow vulnerability if hostile RAR archives declare > 256 pending filters.
3. **Flaky Allocator Tracking:** Global allocator hooking without thread-local call scoping captures harness setup overhead rather than decompressor execution.

All three hazards have been systematically mitigated in the revised plan.

---

### 2. 🚨 Critical Red Flags & Fatal Flaws (Resolved)
- **Wildcopy Memory Overrun Hazard:** Resolved. Added mandatory Invariant I-15 requiring a minimum 64-byte trailing safety margin beyond `win_size` for all `WindowBuffer` allocations, ensuring unaligned 16-byte/32-byte SIMD wildcopy stores never write out of bounds.
- **Pathological Filter DoS Attack Surface:** Resolved. Fixed-capacity filter queue enforces strict fail-closed rejection: any archive presenting $> 256$ concurrent pending filters is immediately aborted with `DecompressErrorCode::CorruptedArchive`.

---

### 3. ⚠️ Weak Assumptions & Fragile Invariants (Resolved)
- **Allocator Hooking Noise:** Resolved. Replaced global allocator grep with a thread-local, scoped monitor (`ScopedAllocTracker`) active strictly between `process_available()` entry and exit.
- **Solid Archive Continuity:** Resolved. Circular ring window reset mechanics explicitly distinguish between non-solid members (retaining buffer capacity while clearing cursor) and solid members (preserving full dictionary history across file boundaries).

---

### 4. ⚡ High-Performance & Mechanical Sympathy Gaps (Addressed)
- **Store-Forwarding Stalls in Match Copy:** Addressed. H-09 pattern doubling (`vpbroadcast`, `pshufb`, unaligned vector stores) directly solves the store-forwarding bottleneck for overlapping small-distance copies (`dist < 16`).
- **Memory Latency vs. ALU Discipline:** Addressed. Pipelined dual-chain prefetching (`_mm_prefetch`) in H-12 ensures memory stall latency is hidden under useful SIMD execution.

---

### 5. 🛠️ Actionable Implementation Directives
1. *Enforce 64-Byte Buffer Tail Margin:* All `WindowBuffer` implementations across native VM and fallback vector allocators must append a 64-byte tail margin to protect against vector overshoots.
2. *Strict 2.0% Gate for GFNI/NEON:* If half-width GFNI folding or NEON `pmull` yields $< 2.0\%$ end-to-end throughput gain on reference benchmarks, close permanently as refuted. Do not ship speculative complexity.
3. *Intrinsics-Only Discipline:* All microarchitectural acceleration in `src/compress/arch/` must use C++ intrinsics with runtime CPU feature dispatch; no standalone `.asm` files unless register pressure forces it.
4. *Zero Ratchet Degradation:* Maintain 100% adherence to Invariant I-13 across all 30 deterministic ratchet cells.
```
