## 0. Executive Summary & Architectural Context

### 0.1 High-Level Vision
Following the successful completion of Milestone v2.2 (which permanently excised ~600 lines of dead forward-arrival parser code, restored `-m4`/`-m5` compression throughput via bounded lazy probing, and delivered the resumable decoder pump), Milestone v2.3 is the **mechanical-sympathy and high-performance engineering release**.

Milestone v2.3 fulfills the second half of the OpenRAR v2.0 Charter across two major arcs:
1. **Charter Arc 2.2 (Completion):** Streamable chunk-first memory architecture, circular page-pinned sliding buffers, and true **zero dynamic allocation on the decompression hot path**.
2. **Charter Arc 2.3 (Completion & Re-Baseline):** Mathematical closure and refutation protocols for Reed-Solomon RS16 hardware acceleration (GFNI half-width folding and NEON `pmull`), paired with microarchitectural SIMD optimizations (overlapping LZ wildcopy pattern doubling, AVX2 batch hashing, and BMI2 bitstream acceleration).
3. **Greedy Quality Completion:** Systematic evaluation of the four pre-registered greedy quality mechanisms (split emission, saved-head short matches, EWMA effort switching, and distance-band rep3 substitution) without introducing speculative secondary parsers.

### 0.2 RAR 5.0 Technical & Wire Format Primer (For External Reviewers)
To evaluate this plan without external code access, reviewers must understand the four architectural pillars of RAR 5.0:

1. **Sliding Window Dictionary Geometry:**
   - The LZ77 sliding window dictionary is declared in the archive file header as an integer power-of-two or arbitrary size bounded from 64 KiB up to 64 MiB (or 1 GiB in 64-bit modes).
   - In circular sliding dictionaries, match distances $D$ point back into previously decoded output:
     $$\text{src\_pos} = (\text{win\_pos} - D) \pmod{\text{win\_size}}$$
   - When distance $D$ is smaller than match length $L$ ($D < L$), the copy region **overlaps itself**. For example, $D = 1$ denotes a Run-Length Encoded (RLE) sequence of identical bytes.
2. **Repeat Distance Registers:**
   - The codec maintains four historical distance registers: `rep0`, `rep1`, `rep2`, and `rep3`. Emitting a repeat distance token references one of these registers with minimal bit cost instead of encoding a full multi-bit distance descriptor.
3. **Canonical Prefix Huffman Bitstream:**
   - Compressed tokens (literals, matches, repeat lengths, table lengths) are encoded via canonical Huffman prefix trees. A 64-bit sliding accumulator reads bits MSB-first. Direct table lookups decode symbols up to 10 bits in a single cycle; longer codes fall back to multi-level canonical decoding tables.
4. **Reed-Solomon RS16 Cauchy Shards:**
   - Archive recovery records use a Cauchy matrix generator over the Galois Field $\text{GF}(2^{16})$ defined by the primitive polynomial:
     $$P(x) = x^{16} + x^{12} + x^3 + x + 1 \quad (0\text{x}1100B)$$
   - Multiplication of data words by Cauchy matrix coefficients generates error correction shards ($\text{ECC}$).

## 2. Workstream Chunk 1: Chunk-First Memory & Zero-Allocation Decompression (W1)

### 2.1 The Current Problem: Hot-Loop Heap Contention & Growth Copies
In the current implementation ([`src/compress/decompressor50.hpp`](../../src/compress/decompressor50.hpp) and [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp)), the decompression engine suffers from three major dynamic memory bottlenecks:

1. **Incremental Geometric Window Growth:**  
   `WindowBuffer` begins by allocating an initial window of `INITIAL_WINDOW = 256 KiB`. As decompression progresses, every match copy and literal emission checks `win_pos_ >= cap_` and calls `grow(n)`.  
   For windows $\le 64\text{ MiB}$ (which includes 99.9% of real-world archives: 4 MiB, 8 MiB, 16 MiB, 32 MiB, 64 MiB), `WindowBuffer` uses `std::vector<core::byte, default_init_allocator<core::byte>> vec_`. Every growth step triggers `vec_.resize(next)`:
   ```cpp
   // Current decompressor50.cpp:465-481
   bool Decompressor50::ApplyEngine::grow(size_t n) {
       if (cap_ == win_size_) return true;
       const size_t need = (n >= win_size_ - win_pos_) ? win_size_ : win_pos_ + n;
       if (need <= cap_) return true;
       size_t next = cap_ > win_size_ / 2 ? win_size_ : std::max(cap_ * 2, need);
       if (next > win_size_) next = win_size_;
       if (!window_.grow_to(next)) return false; // Triggers vec_.resize(next)!
       cap_ = window_.size();
       return true;
   }
   ```
   **Consequence:** In the middle of decoding hot loops, the CPU halts to allocate new heap memory via `malloc`/`operator new`, copies existing megabytes of dictionary history, and frees old memory.
2. **Dynamic Filter Queue Overhead:**  
   Post-processing filters (DELTA, E8/E9 x86 jump calls, ARM jumps) are managed via `std::vector<FilterEntry> filters_`. When filter records are parsed from the bitstream, they execute `filters_.push_back(fe)`. During flushes, consumed filters are removed via:
   ```cpp
   // Current decompressor50.cpp:732-735
   if (filters_head_) {
       filters_.erase(filters_.begin(), filters_.begin() + filters_head_);
       filters_head_ = 0;
   }
   ```
   **Consequence:** `filters_.erase()` invokes `std::memmove` across vector elements and triggers vector heap churn.
3. **Scratchpad Reallocations:**  
   `filter_scratch_` and `delta_scratch_` dynamically resize on demand when applying large filter blocks.

### 2.2 Target Architecture: Chunk-First Pinned Circular Buffer
To achieve mechanical sympathy and strict zero dynamic allocation, the decompression engine is re-engineered as follows:

```mermaid
flowchart TD
    subgraph "WindowBuffer (Pre-Allocated Chunk-First Architecture)"
        A["Decompressor Init: declared_win_"] --> B["WindowBuffer::init(win_size + 64)"]
        B -->|win_size > 64 MiB (64-bit OS)| C["VirtualAlloc / mmap (Page-Pinned VM)"]
        B -->|win_size <= 64 MiB or WASM| D["Direct Allocation with 64B Tail Margin"]
        C --> E["cap_ = win_size (Full Ring Ready Up Front)"]
        D --> E
        E --> F["Hot Loop: copy_match / write_literal"]
        F --> G["reserve(n) & grow(n) become Branchless NO-OPs"]
    end

    subgraph "Zero-Allocation Filter Ring Queue"
        H["Filter Bitstream Token"] --> I{"Pending Filters < 256?"}
        I -->|Yes| J["Ring Array: pending_filters_[tail_ & 255]"]
        I -->|No (Hostile Attack)| K["Fail-Closed: CorruptedArchive"]
        J --> L["Static Pre-Allocated Scratchpads (1 MiB Max)"]
    end
```

#### 1. Pre-Allocated Circular Ring Buffer with Invariant I-15 Safety Margin
- At decompressor instantiation (`Decompressor50::init`), the full dictionary capacity is committed immediately:
  $$\text{allocated\_bytes} = \text{win\_size} + 64$$
- The extra 64 bytes form the **Invariant I-15 Safety Tail Margin**. When vectorized copy routines write 16 or 32 bytes per instruction, any overshoot past the match end safely lands in this committed margin, eliminating bounds-checking branches inside the inner copy loop.
- `cap_` is initialized to `win_size_`. As a result:
  ```cpp
  inline bool reserve(size_t n) { return true; } // Completely branchless / inline no-op!
  inline bool grow(size_t n) { return true; }    // Never called on the hot path!
  ```

#### 2. Fixed-Capacity Circular Filter Queue (`FixedFilterQueue<256>`)
- Replace `std::vector<FilterEntry> filters_` with a fixed-capacity circular ring array:
  ```cpp
  template <size_t Capacity = 256>
  class FixedFilterQueue {
  public:
      bool push(const FilterEntry& entry) noexcept {
          if (count_ >= Capacity) return false; // Queue full: fail-closed!
          ring_[tail_ & (Capacity - 1)] = entry;
          ++tail_;
          ++count_;
          return true;
      }
      bool pop(FilterEntry& out) noexcept {
          if (count_ == 0) return false;
          out = ring_[head_ & (Capacity - 1)];
          ++head_;
          --count_;
          return true;
      }
      size_t size() const noexcept { return count_; }
      bool empty() const noexcept { return count_ == 0; }
      void clear() noexcept { head_ = tail_ = count_ = 0; }
  private:
      FilterEntry ring_[Capacity];
      size_t head_{0};
      size_t tail_{0};
      size_t count_{0};
  };
  ```
- **Security & DoS Defense:** If a hostile or malformed archive specifies $> 256$ concurrent pending filters, `push()` returns `false`, causing `Decompressor50` to immediately abort with `DecompressErrorCode::CorruptedArchive`. This eliminates memory-exhaustion attack surfaces.

#### 3. Static Pre-Allocated Filter Scratchpads
- Pre-allocate `filter_scratch_` and `delta_scratch_` during decompressor construction to `MAX_FILTER_BLOCK_SIZE = 1u << 20` (1 MiB, bounded by `docs/invariants.md` §2).
- Zero allocations or reallocations occur during filter application.

### 2.3 Scoped Allocator Monitor (`ScopedAllocTracker`)
To rigorously prove zero dynamic allocations without relying on fragile static grepping, we introduce an instrumented tracking allocator in [`tests/unit/tracking_allocator.hpp`](../../tests/unit/tracking_allocator.hpp):

```cpp
class ScopedAllocTracker {
public:
    ScopedAllocTracker() {
        active_ = true;
        alloc_count_ = 0;
        bytes_allocated_ = 0;
    }
    ~ScopedAllocTracker() { active_ = false; }

    static void record_alloc(size_t bytes) noexcept {
        if (active_) {
            ++alloc_count_;
            bytes_allocated_ += bytes;
        }
    }
    size_t alloc_count() const noexcept { return alloc_count_; }
    size_t bytes_allocated() const noexcept { return bytes_allocated_; }

private:
    static thread_local bool active_;
    static thread_local size_t alloc_count_;
    static thread_local size_t bytes_allocated_;
};
```
- In `stream_decoder_tests.cpp`, every execution of `process_available()` is wrapped in a `ScopedAllocTracker` assertion:
  ```cpp
  {
      ScopedAllocTracker tracker;
      bool ok = decompressor.process_available(chunk_ptr, chunk_len, is_final);
      CHECK(ok);
      CHECK_EQ(tracker.alloc_count(), 0); // Strict zero-allocation proof!
  }
  ```

## 3. Workstream Chunk 2: ISA Recovery Completion & Microarchitectural Hardware Acceleration (W2)

### 3.1 Mathematical Derivation: GFNI Half-Width RS16 Folding (§10 item 6)
In [`src/recovery/rs16_gfni.cpp`](../../src/recovery/rs16_gfni.cpp), the existing 512-bit GFNI kernel evaluates Reed-Solomon parity by computing four 8x8 affine Galois field transformations per byte:
```
out_lo = aff(lo, m[0]) ^ aff(hi, m[2])
out_hi = aff(lo, m[1]) ^ aff(hi, m[3])
```
where `m[0..1]` derive from the Cauchy coefficient applied to the low byte, and `m[2..3]` derive from $\text{coeff} \cdot x^8$ applied to the high byte.

#### The Half-Width Optimization Mechanism:
In sparse recovery scenarios or when processing half-width symbols (where the high byte $b_{\text{hi}} = 0$):
$$\text{aff}(0, m[2]) = 0 \quad \text{and} \quad \text{aff}(0, m[3]) = 0$$
This reduces the calculation to:
$$\text{out\_lo} = \text{aff}(\text{lo}, m[0]), \quad \text{out\_hi} = \text{aff}(\text{lo}, m[1])$$
This cuts the number of `_mm512_gf2p8affine_epi64_epi8` instructions by **50%** (from 4 vector evaluations to 2).

#### The 2.0% Kill Gate:
- **Experiment:** Benchmark standard recovery generation on 64 MiB multi-volume shards with half-width detection vs. baseline.
- **Kill Gate:** If the end-to-end recovery record throughput gain is $< 2.0\%$, the half-width path is **permanently closed as refuted**. We do not ship speculative complexity for measurement noise.

### 3.2 ARM NEON `pmull` vs. 16-Entry Nibble Lookup Tables
- **Current State:** [`src/recovery/rs16.cpp:240-256`](../../src/recovery/rs16.cpp#L240-L256) uses 16-entry nibble lookup tables applied via `vqtbl1q_u8`.
- **The Theoretical Question:** Can ARMv8 polynomial multiply (`vmull_p64`) exceed table lookups?
- **Microarchitectural Reality:** Degree-16 Galois field elements require modular reduction modulo $P(x)$ after polynomial multiplication. Reducing mod $P(x)$ requires a chain of secondary PMULLs and XORs (~6 instructions per lane). Conversely, `vqtbl1q_u8` executes in 1 cycle on Cortex-A78 / Apple Silicon cores.
- **Protocol:** Benchmark native Apple Silicon (M-series) and ARM64 Linux. If `pmull` fails to beat `vqtbl1q_u8`, record the mathematical refutation and ratify the existing v1.22 NEON kernel as optimal.

### 3.3 Microarchitectural SIMD Optimization Track

#### 1. Hypothesis H-09: Overlapping LZ Wildcopy & Pattern Doubling (Decompression Hotspot)
- **Target Component:** [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp) (`ApplyEngine::copy_match`).
- **Mechanism:**  
  Standard decompressors fall back to scalar byte loops `while (len--) *dst++ = *src++;` when `dist < length`, creating severe store-forwarding stalls in CPU load/store execution units.
  We implement pattern-doubling vector broadcast routines in `src/compress/arch/wildcopy_simd.hpp`:
  - `dist == 1`: Load 1 byte, broadcast across 128-bit vector with `_mm_set1_epi8` (`vpbroadcastb`), store 16 bytes per instruction.
  - `dist == 2`: Broadcast 2 bytes with `_mm_set1_epi16` (`vpbroadcastw`).
  - `dist == 4`: Broadcast 4 bytes with `_mm_set1_epi32` (`vpbroadcastd`).
  - `dist in [3, 5..15]`: Broadcast using `_mm_shuffle_epi8` (`pshufb`) with a precomputed modulo permutation table.
  - `dist >= 16`: Unconditional 16-byte/32-byte unaligned SIMD loads/stores (`_mm_loadu_si128` / `_mm_storeu_si128`), allowing overshoot into the Invariant I-15 64-byte trailing safety margin.
- **Kill Gate:** Decompression throughput gain must reach $\ge 15\%$ on synthetic/real extraction benchmarks with zero buffer overrun errors.

#### 2. Hypothesis H-10: Vectorized Batch Hash Updates in `Compressor50::hash_range`
- **Target Component:** [`src/compress/compressor50.cpp:721-746`](../../src/compress/compressor50.cpp#L721-L746).
- **Mechanism:**  
  Emitted matches execute `hash_range(p + 1, p + L)` to update hash table heads. Currently, this computes 32-bit multiplicative hashes sequentially in scalar code.
  Using AVX2:
  1. Load 32 window bytes via `_mm256_loadu_si256`.
  2. Shuffle 8 candidate dwords into 8 vector lanes via `_mm256_shuffle_epi8`.
  3. Multiply by constant `0x9E3779B1u` in parallel using `_mm256_mullo_epi32` (`vpmulld`).
  4. Shift in parallel with `_mm256_srli_epi32` to produce 8 hash indices simultaneously.
- **Kill Gate:** $\ge 3\%$ end-to-end compression throughput speedup on real text/source corpora with **zero size or digest regression** across the 30 golden cells (Invariant I-1).

#### 3. Hypothesis H-11: BMI2 Bitfield Extraction (`_bextr_u64`) & Branchless Huffman Decoding
- **Target Component:** [`src/compress/bitwriter.hpp`](../../src/compress/bitwriter.hpp), [`src/compress/decompressor50.hpp`](../../src/compress/decompressor50.hpp) (`HuffmanDecoder::decode`).
- **Mechanism:** Replace shift-and-mask sequences with x86-64 BMI2 `_bextr_u64` (ARM64 `ubfx`). Replace variable-depth prefix branches with a branchless 2-level lookup table using conditional moves (`cmov`).
- **Kill Gate:** $\ge 10\%$ branch misprediction reduction in entropy hot loops.

#### 4. Hypothesis H-12: Pipelined Dual-Track Prefetching in Match Finding
- **Target Component:** [`src/compress/compressor50.cpp:450-550`](../../src/compress/compressor50.cpp#L450-L550) (`find_match`).
- **Mechanism:** Memory latency hides behind compute: issue non-blocking software prefetch `_mm_prefetch((const char*)&window_[next_cand], _MM_HINT_T0)` for candidate $N+1$ while executing SIMD string comparisons on candidate $N$.
- **Kill Gate:** $\ge 4\%$ throughput gain at `-m5` on large dictionary windows (`-md16m`, `-md64m`).

## 4. Workstream Chunk 3: Greedy Quality Completion (W3)

### 4.1 Bounded Greedy Quality Agenda
Greedy compression ratio can be refined through four strictly bounded, isolated mechanisms. Under **Rule G-1 (Single Decision Function)**, no secondary parser will be introduced. Each mechanism is evaluated independently:

| ID | Hypothesis | Algorithmic Mechanism | Target Corpus | Kill Gate / Hard Stop |
|:---|:---|:---|:---|:---|
| **H-04** | Split Emission | Search for best split point $j$ in pending match where a shorter-distance match exists at $\text{pos} + j$. Emits literal prefix plus smaller distance code. | Text, source code | Loses on $\ge 2$ of 4 binaries, or $> 0.10\%$ on the fourth |
| **H-05** | Saved-Head Candidates | Exploit per-position saved heads for 2/3/4-byte candidates at distances $\le 0x100 / 0x2000 / 0x40000$. | Text, source code | No size reduction, or throughput drops below speed floor |
| **H-06** | EWMA Effort Switching | Dynamically modulate chain search depth based on literal-cost exponentially weighted moving average. | Text, binaries | Any ratchet byte increase on 30 deterministic cells |
| **H-07** | Distance-Band Rep3 Substitution | In lazy/rep test, substitute pending match's distance for `rep3` under strict distance-band gates. | Binaries, mixed data | Wins $< 3/4$ binaries, or $> 0.10\%$ loss on fourth |

### 4.2 Machine-Code Cost-Aware Arbiter Multi-Binary Gate
- Evaluate the cost-aware rep arbiter across all four reference binaries (Windows PE, Linux ELF, two dynamic libraries) with zero static distance concessions ($k$).
- **Success Gate:** Must win on $\ge 3$ binaries and lose $\le 0.10\%$ on the fourth without regressing `-m1`/`-m2` throughput. Otherwise, permanently closed.

## 6. Principal Solution Architect Challenge & Review Verdict

```markdown

**Plan Reviewed:** OpenRAR v2.3.0 Implementation Plan: Zero-Copy Completion, Zero-Allocation Decompression & Mechanical Sympathy  
**Architect Verdict:** 🟢 APPROVED WITH MANDATORY DIRECTIVES

---

### 1. Executive Summary & Core Posture
Milestone v2.3 embodies modern systems programming rigor: eliminating memory churn on decompression loops, embracing microarchitectural hardware sympathy, and enforcing strict fail-closed kill gates on speculative optimizations.

The initial technical concept had three critical engineering hazards that would have triggered runtime memory corruption and security vulnerabilities if unaddressed:
1. **Wildcopy Buffer Overrun Hazard:** SIMD 16/32-byte pattern-doubling stores overshoot match ends. Without an explicit safety padding margin on the circular buffer, vector stores will write into uncommitted virtual memory or corrupt adjacent heap allocations.
2. **Fixed-Capacity Filter Queue DoS Hazard:** Replacing dynamic filter vectors with a fixed 256-element queue creates an overflow vulnerability if hostile RAR archives declare > 256 pending filters.
3. **Flaky Allocator Tracking:** Global allocator hooking without thread-local call scoping captures harness setup overhead rather than decompressor execution.

All three hazards have been systematically mitigated in the finalized plan.

---

### 2. 🚨 Critical Red Flags & Fatal Flaws (Resolved)
- **Wildcopy Memory Overrun Hazard:** Resolved. Mandated Invariant I-15 requiring a minimum 64-byte trailing safety margin beyond `win_size` for all `WindowBuffer` allocations, ensuring unaligned 16-byte/32-byte SIMD wildcopy stores never write out of bounds.
- **Pathological Filter DoS Attack Surface:** Resolved. Fixed-capacity filter queue enforces strict fail-closed rejection: any archive presenting $> 256$ concurrent pending filters is immediately aborted with `DecompressErrorCode::CorruptedArchive`.

---

### 3. ⚠️ Weak Assumptions & Fragile Invariants (Resolved)
- **Allocator Hooking Noise:** Resolved. Replaced global allocator grep with a thread-local, scoped monitor (`ScopedAllocTracker`) active strictly between `process_available()` entry and exit.
- **Solid Archive Continuity:** Resolved. Circular ring window reset mechanics explicitly distinguish between non-solid members (retaining buffer capacity while clearing cursor) and solid members (preserving full dictionary history across file boundaries).

---

### 4. ⚡ High-Performance & Mechanical Sympathy Gaps (Addressed)
- **Store-Forwarding Stalls in Match Copy:** Addressed. H-09 pattern doubling (`vpbroadcast`, `pshufb`, unaligned vector stores) directly solves the store-forwarding bottleneck for overlapping small-distance copies (`dist < 16`).
- **Memory Latency vs. ALU Discipline:** Addressed. Pipelined dual-chain prefetching (`_mm_prefetch`) in H-12 ensures memory stall latency is hidden under useful SIMD execution.

---

1. *Enforce 64-Byte Buffer Tail Margin:* All `WindowBuffer` implementations across native VM and fallback vector allocators must append a 64-byte tail margin to protect against vector overshoots.
2. *Strict 2.0% Gate for GFNI/NEON:* If half-width GFNI folding or NEON `pmull` yields $< 2.0\%$ end-to-end throughput gain on reference benchmarks, close permanently as refuted. Do not ship speculative complexity.
3. *Intrinsics-Only Discipline:* All microarchitectural acceleration in `src/compress/arch/` must use C++ intrinsics with runtime CPU feature dispatch; no standalone `.asm` files unless register pressure forces it.
4. *Zero Ratchet Degradation:* Maintain 100% adherence to Invariant I-13 across all 30 deterministic ratchet cells.
```
