## 0. Executive Summary & Architectural Context

### 0.1 High-Level Vision
Following the successful completion of Milestone v2.2 (which permanently excised ~600 lines of dead forward-arrival parser code, restored `-m4`/`-m5` compression throughput via bounded lazy probing, and delivered the resumable decoder pump), Milestone v2.3 is the **mechanical-sympathy and high-performance engineering release**.

Milestone v2.3 fulfills the second half of the OpenRAR v2.0 Charter across two major arcs:
1. **Charter Arc 2.2 (Completion):** Streamable chunk-first memory architecture, circular page-pinned sliding buffers, and true **zero dynamic allocation on the decompression hot path**.
2. **Charter Arc 2.3 (Completion & Re-Baseline):** Mathematical closure and refutation protocols for Reed-Solomon RS16 hardware acceleration (GFNI half-width folding and NEON `pmull`), paired with microarchitectural SIMD optimizations (overlapping LZ wildcopy pattern doubling, AVX2 batch hashing, and BMI1 `BEXTR` bitstream acceleration).
3. **Greedy Quality Completion:** Systematic evaluation of the four pre-registered greedy quality mechanisms (split emission, saved-head short matches, EWMA effort switching, and distance-band rep3 substitution) without introducing speculative secondary parsers.

### 0.2 RAR 5.0 Technical & Wire Format Primer (For External Reviewers)
To evaluate this plan without external code access, reviewers must understand the four architectural pillars of RAR 5.0:

1. **Sliding Window Dictionary Geometry:**
   - The LZ77 sliding window dictionary is declared in the archive file header as an integer power-of-two or arbitrary size bounded from 64 KiB up to 4 GiB per the RAR5 version-0 spec, up to 1 TB with `unp_ver = 1` fractions. OpenRAR's implementation allocation limit is 64 GiB on 64-bit native and 1 GiB on 32-bit/WASM (`Decompressor50::ALLOC_LIMIT`); the earlier "64 MiB / 1 GiB" primer range was narrower than the declared format and is corrected here.
   - In circular sliding dictionaries, match distances $D$ point back into previously decoded output:
     $$\text{src\_pos} = (\text{win\_pos} - D) \pmod{\text{win\_size}}$$
   - When distance $D$ is smaller than match length $L$ ($D < L$), the copy region **overlaps itself**. For example, $D = 1$ denotes a Run-Length Encoded (RLE) sequence of identical bytes.
2. **Repeat Distance Registers:**
   - The codec maintains four historical distance registers: `rep0`, `rep1`, `rep2`, and `rep3`. Emitting a repeat distance token references one of these registers with minimal bit cost instead of encoding a full multi-bit distance descriptor.
3. **Canonical Prefix Huffman Bitstream:**
   - Compressed tokens (literals, matches, repeat lengths, table lengths) are encoded via canonical Huffman prefix trees. A 64-bit sliding accumulator reads bits MSB-first. Direct table lookups decode symbols up to 10 bits in a single cycle; longer codes fall back to multi-level canonical decoding tables.
4. **Reed-Solomon RS16 Cauchy Shards:**
   - Archive recovery records use a Cauchy matrix generator over the Galois Field $\text{GF}(2^{16})$ defined by the primitive polynomial:
     $$P(x) = x^{16} + x^{12} + x^3 + x + 1 \quad (0\text{x}1100B)$$
   - Multiplication of data words by Cauchy matrix coefficients generates error correction shards ($\text{ECC}$).

## 1. Architectural Contracts & Non-Negotiable Invariants

All work in Milestone v2.3 is governed by the following binding engineering contracts:

|:---|:---|:---|
| **I-1** | Deterministic Golden Digests | **Scoped (D-13):** applies to every *behavior-preserving* optimization — all W2 work in this plan — which must maintain bit-for-bit identical SHA-256 archive digests across all 30 deterministic test cells in `tools/release_regression_guard.py`. Ratio-changing W3 work (H-22…H-25) is governed by I-13 and a recorded ratchet re-baseline (§4.3), never by I-1. |
| **I-3** | Frozen Public C ABI | The public binary layout in `include/openrar.h` and exported dynamic symbols in `libopenrar` remain strictly frozen. Zero struct member or ABI export changes permitted. The `LimitExceeded` → `RAR_ERR_LIMIT_EXCEEDED` mapping reuses an existing error slot and is not an ABI change. |
| **I-6** | Bounded Working-Set RAM | Peak memory during decompression is `O(committed window)`, not `O(declared window)`: a hostile declared window over a tiny payload must still allocate kilobytes. Fixed object state (the `Decompressor50`/`StreamDecoder` objects) must stay small (kilobytes) and is pinned by object-size assertions; lazily created filter state is bounded separately by I-16 (1.5 MiB ring worst case, 1 MiB per scratchpad) and is absent for no-filter archives. The 1.5 MiB WASM figure is the **static/module** budget (`docs/wasm-limitations.md` §4.3.1), not a working-set ceiling; 1 GiB streams must peak near 1.2 GiB. The exact accounting is pinned by I-16. |
| **I-8** | Oracle Interoperability | All archives created or decompressed must achieve 100% byte-identical interoperability against the official reference oracle (`UnRAR 7.20+`) across the 35-stage test manifest. |
| **I-13** | Ratchet Primacy (Rule G-8) | Compression throughput optimizations must never degrade compression ratio. Any commit that increases compressed archive size beyond `RATCHET_BYTES` on any of the 30 golden cells triggers an immediate automatic rejection. W3 ratio wins change digests by definition and therefore must lower `RATCHET_BYTES` through the recorded re-baseline procedure (§4.3); they are exempt from I-1 but never from I-13. |
| **I-15** | 64-Byte Buffer Tail Margin | **Capacity-only (D-9):** every `WindowBuffer` allocation must reserve 64 bytes of address space *beyond* the declared logical window (`capacity = win_size + 64`). The logical geometry — `win_size_`, `win_mask_`, wrap arithmetic, distance checks, `flush_cadence()`, and the archive header value — remains exactly `win_size`; the margin is never part of the ring. The trailing 64 bytes are committed with the final window page so unaligned 16/32-byte wildcopy stores land in committed memory. |
| **I-16** | Lazy Window Commit & Bounded Per-Instance State | **New Invariant (2026-11-08 amendment, `docs/invariants.md` §9):** (a) VM-reserved windows commit pages on demand and never at `init`; `grow()` commits the next range and never reallocates; setting `cap_ = win_size` without a matching commit is forbidden. ## 2. Workstream Chunk 1: Chunk-First Memory & Zero-Allocation Decompression (W1)

### 2.1 The Current Problem: Hot-Loop Heap Churn, Growth Copies & Unbounded Per-Instance State
> **Amendment (adversarial directive D-4 / finding F-4, applied 2026-11-08; refined by D-9/D-10/D-12):** as of HEAD (`162300a`) the shipped `WindowBuffer` already implements VM reservation for declared windows above `WINDOW_VM_THRESHOLD` (64 MiB): `init()` reserves address space with `VirtualAlloc(MEM_RESERVE, PAGE_NOACCESS)` / `mmap(PROT_NONE)` and `grow_to()` commits page granules lazily. Chunk 1 therefore does **not** re-implement VM reservation. It (a) preserves lazy commit while eliminating reallocation from the hot path, (b) adds the capacity-only I-15 margin, (c) replaces the filter vector and reallocating scratchpads with bounded, lazily allocated state, and (d) completes the zero-allocation proof, including the residual staging work left by M-08.

The decompression engine at HEAD ([`src/compress/decompressor50.hpp`](../../src/compress/decompressor50.hpp), [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp), [`src/compress/stream_decoder.cpp`](../../src/compress/stream_decoder.cpp)) has four distinct memory costs:

1. **Per-write capacity checks and geometric commit/growth:**
   `ApplyEngine::reserve(n)` calls `grow(n)` whenever `n > cap_ - win_pos_`. On the VM path `grow_to()` commits the next 1 MiB granule (no copy, but a syscall in the middle of a token run); on the vector path (windows ≤ 64 MiB, 32-bit, WASM) `vec_.resize(next)` copies the whole dictionary prefix. The engine starts at `INITIAL_WINDOW = 256 KiB` (`decompressor50.cpp:455`) even when the declared window is already known.
   ```cpp
   // Current decompressor50.cpp:465-481
   bool Decompressor50::ApplyEngine::grow(size_t n) {
       if (cap_ == win_size_) return true;
       const size_t need = (n >= win_size_ - win_pos_) ? win_size_ : win_pos_ + n;
       if (need <= cap_) return true;
       size_t next = cap_ > win_size_ / 2 ? win_size_ : std::max(cap_ * 2, need);
       if (next > win_size_) next = win_size_;
       if (!window_.grow_to(next)) return false;
       cap_ = window_.size();
       return true;
   }
   ```
   **Consequence:** the hot loop pays a branch per write, the VM path pays a commit syscall under the token loop, and the vector path pays megabyte-scale copies. The target design keeps commit lazy but hoists it out of the per-token path and makes the vector fallback's growth amortized *without* changing the ring geometry.
2. **Dynamic Filter Queue Overhead:**  
   Post-processing filters (DELTA, E8/E9 x86 jump calls, ARM jumps) live in `std::vector<FilterEntry> filters_`. Parsing a filter record calls `filters_.push_back(fe)`; each flush `erase()`s the consumed prefix:
   ```cpp
   // Current decompressor50.cpp:733-736
   if (filters_head_) {
       filters_.erase(filters_.begin(), filters_.begin() + filters_head_);
       filters_head_ = 0;
   }
   ```
   **Consequence:** `push_back` reallocates as the pending set grows (up to the 65,536-entry envelope), and `erase` memmoves across elements plus triggers vector churn. `FilterEntry` is 32 bytes (`decompressor50.hpp:139-145`); an *inline* `FilterEntry[65536]` would be 2 MiB per decoder and is forbidden by I-16.
3. **Scratchpad Reallocations:**
   `filter_scratch_` and `delta_scratch_` (`decompressor50.hpp:512-513`) grow on demand up to the retained ceiling of 1 MiB each (`decompressor50.cpp:719-727`). They are currently ordinary vectors, so first use in a large filter block allocates inside the filter application path; an unconditional 1 MiB pre-allocation of each would add 2 MiB of resident state to every decoder, including no-filter archives.
4. **Streaming Staging and Retention:**
   M-08 is **partially landed** at HEAD: `StreamDecoder::feed` decodes complete blocks directly from the caller's buffer when its queue is empty and builds one `OutputCallback` per batch (`stream_decoder.cpp:51-75,108-124`). Residual churn remains: the incomplete tail is copied with `in_queue_.insert` (`:69,74`), consumed prefixes `erase` (`:102`), and `retain_output` appends every decoded byte with `output_.insert` (`:89`). `finish(std::vector&)` appends to a caller-owned vector. A zero-allocation proof against the streaming surface is therefore only meaningful with a **flush sink** and pre-reserved queue/output scratch (D-12).

### 2.2 Target Architecture: Lazy-Commit Reserved Ring, Bounded Filter State & Lazy Scratchpads
The target keeps the shipped lazy-commit design and removes the *reallocation* and *unbounded inline state* costs. Three rules govern the rewrite:

1. **Logical geometry and physical capacity are separate.** `win_size_` (mask, wrap, distances, cadence, header value) never changes. `cap_` is the committed prefix, always `<= win_size_`. The allocation reserves `win_size + 64` bytes so the I-15 margin exists in address space; the margin is *never* addressable by the ring.
2. **`grow()` never reallocates.** On the VM path it commits the next granule; on the vector fallback it reserves geometrically in place. It is never "a no-op" while bytes remain uncommitted — that would write into `PAGE_NOACCESS`.
3. **Fixed per-instance state stays small.** The filter queue and scratchpads are heap-owned and lazily created on first filter use.

```mermaid
flowchart TD
    subgraph "WindowBuffer (Lazy-Commit Reserved Ring)"
        A["Decompressor init: declared_win_"] --> B["WindowBuffer::init(win_size, tail_margin=64)"]
        B -->|win_size > 64 MiB (64-bit OS)| C["VirtualAlloc MEM_RESERVE / mmap PROT_NONE for win_size + 64"]
        B -->|win_size <= 64 MiB, 32-bit, WASM| D["In-place vector reservation for win_size + 64"]
        C --> E["Initial commit: min(win_size, INITIAL_WINDOW); cap_ = committed"]
        D --> E
        E --> F["Hot loop: copy_match / write_literal"]
        F --> G{"win_pos_ < cap_?"}
        G -->|Yes| H["Branch predicted taken: write"]
        G -->|No| I["grow(): commit next granule (VM) or reserve in place (vector); NEVER reallocates; cap_ <= win_size"]
        I --> H
        H --> J["Last granule commits the +64 I-15 margin"]
    end

    subgraph "Lazily Allocated Filter State (I-16)"
        K["Filter Bitstream Token"] --> L{"FilterRing created?"}
        L -->|No| M["Allocate FilterRing once (heap, pooled); ~24 B/entry x 65536 = 1.5 MiB max"]
        L -->|Yes| N{"Pending < 65536?"}
        M --> N
        N -->|Yes| O["ring_[tail_ & 65535] = entry"]
        N -->|No (Hostile Attack)| P["Fail-Closed: LimitExceeded -> RAR_ERR_LIMIT_EXCEEDED"]
        O --> Q["Scratchpads: lazily sized to actual block, <= 1 MiB each; released above cap"]
    end
```

#### 1. Lazy-Commit Reserved Ring with Invariant I-15 Safety Margin
- **Reservation:** `WindowBuffer::init(win_size, /*tail_margin=*/64)` reserves `win_size + 64` bytes. On 64-bit native this is `VirtualAlloc(MEM_RESERVE, PAGE_NOACCESS)` / `mmap(PROT_NONE)`; on the fallback path the vector reserves (not resizes) `win_size + 64` bytes in place. `size()` continues to report the **logical** usable window (≤ `win_size`); a new `committed()` reports physical committed bytes for the peak-memory test. Callers never clamp the margin themselves.
- **Commit:** `WindowBuffer` stores `logical_ = max_bytes - tail_margin_`; `size()` returns `min(n, logical_)`, and `grow_to(n)` commits `max(round_up(n), n + tail_margin_)` capped at `reserved_`. `ensure_window_alloc()` commits `min(win_size, INITIAL_WINDOW)` as today. `grow(n)` computes `need = min(win_size, win_pos_ + n)`; `cap_ = window_.size()` (logical, so `cap_ <= win_size`). The `n + 64` term matters when `win_size` is an exact granule multiple: it guarantees the trailing 64 bytes are committed too, so an unaligned 32-byte wildcopy store that starts at `win_size - 1` never touches uncommitted memory.
- **Hot path:** `reserve(n)` remains the inline fast path:
  ```cpp
  // Target: logical ring stays win_size; the +64 bytes are capacity-only.
  inline bool reserve(size_t n) {
      if (n <= cap_ - win_pos_) return true;   // predicted taken, one compare
      return grow(n);                          // commits ahead by >= one granule; no reallocation
  }
  ```
  The branch is not removed (it is the only way to keep commit lazy); it is amortized to one commit per granule rather than one allocation per growth step. `write_literal` keeps its `win_pos_ >= cap_` guard for the same reason.
- **Vector fallback (≤ 64 MiB, 32-bit, WASM):** keep geometric `vec_.resize(next)` growth but reserve `win_size + 64` logical capacity up front where the platform allows, and never copy once `first_win_done_` is set. The correctness invariant (`cap_ < win_size_` implies the ring has not wrapped and data is a linear prefix) is unchanged.
- **Hostile-header property (must be tested):** a 64 GiB declared window with a tiny payload commits only `INITIAL_WINDOW` plus the granules actually crossed. `window_capacity()` continues to report committed bytes; `declared_win()` reports the claim. The I-15 margin does not change `win_size()`, `flush_cadence()`, distance validation, or the header value.
- **Failure mapping:** a failed reserve/commit returns false from `grow()`, which `write_literal`/`copy_match` map through `window_alloc_failed()` → `DecompressErrorCode::AllocationFailed` → `RAR_ERR_NOMEM` (unchanged shipped behavior). The filter-queue overflow is the *only* new fail-closed path and maps to `LimitExceeded` → `RAR_ERR_LIMIT_EXCEEDED`.

#### 2. Lazily Allocated Fixed-Capacity Filter Ring (`FixedFilterQueue<65536>`)
- Replace `std::vector<FilterEntry> filters_` with a heap-owned ring created on the first filter token (not in the constructor):
  ```cpp
  struct FilterEntry {                 // reordered, packed; static_assert below
      core::uint64 block_start{0};     // absolute output position
      core::uint64 file_offset{0};     // linear file position for E8/ARM fixup
      core::uint32 block_length{0};
      core::uint8  type{0};
      core::uint8  channels{0};
  };
  static_assert(sizeof(FilterEntry) == 24, "filter ring envelope assumes 24-byte entries");

  template <size_t Capacity>
  class FixedFilterQueue {
      static_assert((Capacity & (Capacity - 1)) == 0, "ring capacity must be a power of two");
  public:
      bool push(const FilterEntry& e) noexcept {
          if (count_ == Capacity) return false;      // fail-closed; no overwrite
          ring_[tail_ & (Capacity - 1)] = e;
          ++tail_; ++count_;
          return true;
      }
      const FilterEntry& peek() const noexcept { return ring_[head_ & (Capacity - 1)]; }
      const FilterEntry& back() const noexcept { return ring_[(tail_ - 1) & (Capacity - 1)]; } // last pushed
      bool pop(FilterEntry& out) noexcept {
          if (count_ == 0) return false;
          out = peek();
          ++head_; --count_;
          return true;
      }
      size_t size() const noexcept { return count_; }
      bool empty() const noexcept { return count_ == 0; }
      void clear() noexcept { head_ = tail_ = count_ = 0; }
  private:
      FilterEntry ring_[Capacity];
      size_t head_{0}, tail_{0}, count_{0};
  };
  // ApplyEngine member: std::unique_ptr<FixedFilterQueue<65536>> filters_;  (8 bytes inline)
  ```
- **Memory accounting (I-16):** 24 B x 65536 = **1.5 MiB** worst case, allocated only for archives that actually carry filters; a no-filter archive carries 0 bytes and only the 8-byte pointer. The ring is allocated once per decoder lifetime and returned to a small process-wide pool on destruction so repeated decodes do not re-allocate. `reset()` clears the ring (`clear()`) and retains its capacity/scratch, so a re-decode after reset is allocation-free; only destruction returns the ring to the pool. This preserves the 65,536 pending-filter envelope (`decompressor50.cpp:1146,1828`). If the `FilterEntry` compaction proves infeasible, the 2 MiB (32 B) envelope must be recorded as an explicit I-16 re-baseline before implementation, not silently shipped.
- **Security & DoS defense:** if a hostile or malformed archive specifies more than **65536** pending filter regions, `push()` returns `false` and the decoder fails closed with `DecompressErrorCode::LimitExceeded` → `RAR_ERR_LIMIT_EXCEEDED`. A distinct `CorruptedArchive` verdict remains rejected: `LimitExceeded` expresses the resource bound without adding an internal error slot.
- **Stack safety:** the ring is heap-owned, so `StreamDecoder dec(win, method);` on the stack in `tests/unit/stream_decoder_tests.cpp:78,108` stays small. Build-time pins: `static_assert(sizeof(Decompressor50) <= 64 * 1024)` and `static_assert(sizeof(StreamDecoder) <= 64 * 1024)`; a dedicated stack-usage test exercises construction in a 256 KiB coroutine/thread stack.
- **Ring integration (D-16):** `has_completed_filter()` becomes a **peek** (`filters_ && !filters_->empty() && filters_->peek()...`) and `flush_pending()` becomes the **pop** loop. `filters_head_` is deleted. `begin_call()` resets only `last_flushed_` and **must not** clear pending filters — pending regions legitimately cross block boundaries within one member. `reset_window()` (the non-solid member reset) calls `filters_->clear()` when present; a solid continuation preserves the pending set because it belongs to the still-open member. `block_start` remains an absolute output position measured from the member start (the frame used by `begin_call`/`apply_begin`), and `file_offset` remains the linear position within the current member; both frames are pinned by tests across block, call, and solid-member boundaries.

#### 3. Lazy, Capped Filter Scratchpads
- `filter_scratch_` and `delta_scratch_` become `std::vector<core::byte>` that are **not reserve()d in the constructor**. They size to the actual filter block (`resize_if_needed`), never above `MAX_RETAINED_FILTER_SCRATCH = 1 MiB` (a local `constexpr` at `decompressor50.cpp:719`; there is no `MAX_FILTER_BLOCK_SIZE` invariant). On completion, capacity above 1 MiB is released exactly as today (`decompressor50.cpp:719-727`).
- A no-filter archive therefore allocates no scratch; a filtered archive allocates only what its first block needs. Peak engine state is bounded by `committed window + 1.5 MiB ring + 2 x 1 MiB scratch`, and the ring/scratch are dynamic state rather than fixed object size. This is the recorded I-16 accounting.

### 2.3 Scoped Allocator Monitor (`ScopedAllocTracker`) & the Zero-Allocation Claim Matrix
A zero-allocation claim is only as strong as the allocation path it observes and the API surface it wraps. The plan therefore uses **one instrumented proof at the `Decompressor50` boundary** (the engine contract) and a **secondary, explicitly-qualified proof at the `StreamDecoder` boundary** (the shipping streaming surface). It never claims more than the matrix below.

#### 1. Tracker design (complete, nesting-safe)
```cpp
// tests/unit/tracking_allocator.hpp  (new test-support header)
class ScopedAllocTracker {
public:
    ScopedAllocTracker() noexcept : prev_(current_) { current_ = this; }
    ~ScopedAllocTracker() { current_ = prev_; }        // restore the enclosing scope

    static void record_alloc(size_t bytes) noexcept {
        if (current_) { ++current_->alloc_count_; current_->bytes_allocated_ += bytes; }
    }
    static void record_free(size_t /*bytes*/) noexcept {}
    void reset() noexcept { alloc_count_ = 0; bytes_allocated_ = 0; }
    size_t alloc_count() const noexcept { return alloc_count_; }
    size_t bytes_allocated() const noexcept { return bytes_allocated_; }

private:
    ScopedAllocTracker* prev_;
    size_t alloc_count_{0};
    size_t bytes_allocated_{0};
    inline static thread_local ScopedAllocTracker* current_ = nullptr;
};

// Exactly one global replacement pair in the test target's main/translation unit.
void* operator new(std::size_t n) { ScopedAllocTracker::record_alloc(n); /* malloc + throw */ }
void  operator delete(void* p) noexcept { ScopedAllocTracker::record_free(0); /* free */ }
void* operator new[](std::size_t n) { ScopedAllocTracker::record_alloc(n); }
void  operator delete[](void* p) noexcept { ScopedAllocTracker::record_free(0); }
```
- Per-instance counters plus a thread_local innermost pointer make nesting exact: an inner tracker counts only its own scope, and the outer tracker resumes with its counts intact when the inner scope ends.
- The hook must be linked **only** into the dedicated test target (`openrar_allocation_tests`), never into `openrar_core`, the DLL, or the WASM module. `std::malloc`/C-runtime allocations are out of scope for the hook and are covered by the failure-mode/peak-RSS tests instead (the roadmap assumption §4.2.4 is qualified accordingly).

#### 2. Primary proof: `Decompressor50` + flush sink (the claim of record)
The engine is driven directly, with a no-op flush sink so no output is retained:
```cpp
core::byte* packed = ...;                 // allocated BEFORE the tracker
Decompressor50 dec(win, /*extra_dist=*/false); // constructed BEFORE the tracker
const auto sink = [](const core::byte*, size_t) { return true; };
{
    ScopedAllocTracker tracker;
    CHECK(dec.decompress(packed, packed_size, expected, /*solid=*/false, sink));
    CHECK_EQ(tracker.alloc_count(), 0);   // hot-path proof of record
}
```
This proves the call graph `decompress` → block parse → `ApplyEngine` window writes → filter application → flush sink. Window commit is a VM syscall, not `operator new`, so it is not counted; peak RSS/commit is asserted separately. On the **vector fallback** (windows ≤ 64 MiB, 32-bit, WASM) `vec_.resize` does call `operator new`, so the primary proof of record runs on the VM path (64-bit native, window > 64 MiB). A vector-fallback zero-allocation claim is made only when the window has been pre-grown to `win_size` through an untracked test hook (`prepare_window_for_test`); the claim is steady-state, never "first growth is free".

#### 3. Secondary proof: `StreamDecoder` with a flush sink (qualified)
```cpp
static int sink_fn(void*, const core::byte*, size_t) { return 0; } // no retention
StreamDecoder dec(win, method);
dec.set_flush(&sink_fn, nullptr);         // no output_ retention
dec.reserve_staging(/*max tail bytes=*/packed_size); // new C++-only method (Step 1.5); allocates here
std::vector<core::byte> scratch;          // reserved before the tracker iff take_output() is used
scratch.reserve(expected);
{
    ScopedAllocTracker tracker;
    for (size_t off = 0; off < packed_size; off += chunk)
        CHECK(dec.feed(packed + off, std::min(chunk, packed_size - off)));
    CHECK(dec.finish(scratch));
    CHECK_EQ(tracker.alloc_count(), 0);   // steady-state, flush-sink, pre-reserved path only
}
```

## 3. Workstream Chunk 2: ISA Recovery Completion & Microarchitectural Hardware Acceleration (W2)

### 3.1 Mathematical Derivation: GFNI Half-Width RS16 Folding (§10 item 6)
In [`src/recovery/rs16_gfni.cpp`](../../src/recovery/rs16_gfni.cpp), the existing 512-bit GFNI kernel evaluates Reed-Solomon parity by computing four 8x8 affine Galois field transformations per byte:
```
out_lo = aff(lo, m[0]) ^ aff(hi, m[2])
out_hi = aff(lo, m[1]) ^ aff(hi, m[3])
```
where `m[0..1]` derive from the Cauchy coefficient applied to the low byte, and `m[2..3]` derive from $\text{coeff} \cdot x^8$ applied to the high byte.

#### The Half-Width Optimization Mechanism:
In sparse recovery scenarios or when processing half-width symbols (where the high byte $b_{\text{hi}} = 0$):
$$\text{aff}(0, m[2]) = 0 \quad \text{and} \quad \text{aff}(0, m[3]) = 0 \quad \text{only if the GFNI immediate has a zero constant term}$$
This reduces the calculation to:
$$\text{out\_lo} = \text{aff}(\text{lo}, m[0]), \quad \text{out\_hi} = \text{aff}(\text{lo}, m[1])$$
This cuts the number of `_mm512_gf2p8affine_epi64_epi8` instructions by **50%** (from 4 vector evaluations to 2). **Assumption to verify first:** the affine transform used by the kernel must satisfy `aff(0, m) = 0` (zero constant/immediate). A non-zero GFNI immediate invalidates the half-width algebra; the implementation must assert the matrix shape at table-build time. Half-width symbols are also data-dependent, so the sparse-detection cost and the branch are part of the measurement, not free.

#### The 2.0% Kill Gate:
- **Experiment:** Benchmark standard recovery generation on 64 MiB multi-volume shards with half-width detection vs. baseline, under the G-3 protocol (§5.2).
- **Kill Gate:** If the end-to-end recovery record throughput gain is $< 2.0\%$, the half-width path is **permanently closed as refuted**. We do not ship speculative complexity for measurement noise. An isolated-kernel win with a flat end-to-end result is still a refutation.

### 3.2 ARM NEON `pmull` vs. 16-Entry Nibble Lookup Tables
- **Current State:** [`src/recovery/rs16.cpp:240-256`](../../src/recovery/rs16.cpp#L240-L256) uses 16-entry nibble lookup tables applied via `vqtbl1q_u8`.
- **The Theoretical Question:** Can ARMv8 polynomial multiply (`vmull_p64`) exceed table lookups?
- **Microarchitectural Reality:** Degree-16 Galois field elements require modular reduction modulo $P(x)$ after polynomial multiplication. Reducing mod $P(x)$ requires a chain of secondary PMULLs and XORs (~6 instructions per lane). Conversely, `vqtbl1q_u8` executes in 1 cycle on Cortex-A78 / Apple Silicon cores. The v1.22 roadmap design note already refuted `pmull` on this arithmetic; re-running it is optional science, not a v2.3 deliverable.
- **Protocol:** Benchmark native Apple Silicon (M-series) and ARM64 Linux under G-3 (§5.2). If `pmull` fails to beat `vqtbl1q_u8`, record the mathematical refutation permanently and ratify the existing v1.22 NEON kernel as optimal.
- **G-9 blocked rule:** If no native Apple Silicon or ARM64 Linux runner is available, the result is recorded as **blocked**, never as pass. A QEMU result is reported as emulated evidence only and cannot discharge the gate.

#### 1. Hypothesis H-18: Overlapping LZ Wildcopy & Pattern Doubling (Decompression Hotspot)
- **Target Component:** [`src/compress/decompressor50.cpp`](../../src/compress/decompressor50.cpp) (`ApplyEngine::copy_match`) plus a **new decompression-side dispatch kernel** `src/compress/arch/wildcopy_dispatch.hpp` / `wildcopy_simd.cpp` (this file does not exist yet; it is created by Chunk 2). The existing `src/compress/arch/match_simd.hpp` / `match_avx512.cpp` are **compressor-side match-comparison** kernels and are not the target of H-18.
- **Mechanism:**  
  Standard decompressors fall back to scalar byte loops `while (len--) *dst++ = *src++;` when `dist < length`, creating severe store-forwarding stalls in CPU load/store execution units.
  The new decompression wildcopy kernel implements pattern-doubling broadcast routines:
  - `dist == 1`: Load 1 byte, broadcast across 128-bit vector with `_mm_set1_epi8` (`vpbroadcastb`), store 16 bytes per instruction.
  - `dist == 2`: Broadcast 2 bytes with `_mm_set1_epi16` (`vpbroadcastw`).
  - `dist == 4`: Broadcast 4 bytes with `_mm_set1_epi32` (`vpbroadcastd`).
  - `dist in [3, 5..15]`: Broadcast using `_mm_shuffle_epi8` (`pshufb`) with a precomputed modulo permutation table.
  - `dist >= 16`: Unconditional 16-byte/32-byte unaligned SIMD loads/stores (`_mm_loadu_si128` / `_mm_storeu_si128`), allowing overshoot into the Invariant I-15 64-byte trailing safety margin.
- **Kill Gate:** Decompression throughput gain must reach $\ge 15\%$ on synthetic/real extraction benchmarks with zero buffer overrun errors, measured under the G-3 protocol (§5.2) on the sequential, parallel (record-applier), spool, streaming, and WASM paths (§5.6).

#### 2. Hypothesis H-19: Vectorized Batch Hash Updates in `Compressor50::hash_range`
- **Target Component:** [`src/compress/compressor50.cpp:721-746`](../../src/compress/compressor50.cpp#L721-L746).
- **Mechanism:**  
  Emitted matches execute `hash_range(p + 1, p + L)` to update hash table heads. Currently, this computes 32-bit multiplicative hashes sequentially in scalar code (`calc_hash`: `load_le32(d) * 0x9e3779b1u >> (32 - HASH_BITS)`), with call sites at `compressor50.cpp:1950` and `:2180`.
  Using AVX2:
  1. Load 32 window bytes via `_mm256_loadu_si256`.
  2. Rearrange overlapping 4-byte windows into eight lanes with `_mm256_permutevar8x32_epi32` (or two lane-local `_mm256_shuffle_epi8` passes plus blends — `vpshufb` alone is lane-local and cannot gather all eight overlapping windows).
  3. Multiply by constant `0x9E3779B1u` in parallel using `_mm256_mullo_epi32` (`vpmulld`).
  4. Shift in parallel with `_mm256_srli_epi32` to produce 8 hash indices simultaneously.
  The SIMD path must reproduce the scalar `load_le32` hash values **exactly on every host** (C-07 big-endian guard included).
- **Kill Gate:** $\ge 3\%$ end-to-end compression throughput speedup under the G-3 protocol (§5.2) on real text/source corpora with **bit-identical archive digests** across the 30 golden cells — digest identity, not merely "no size regression" (I-1 as scoped). A scalar-vs-SIMD differential test asserts identical hash sequences.

#### 3. Hypothesis H-20: BMI1 Bitfield Extraction (`_bextr_u64`) & Branchless Huffman Decoding
- **Target Components:** `BitOutput` at [`src/compress/compressor50.hpp:17`](../../src/compress/compressor50.hpp#L17); `BitReader` at [`src/compress/decompressor50.hpp:16`](../../src/compress/decompressor50.hpp#L16); `HuffmanDecoder::decode` at [`src/compress/decompressor50.hpp:54`](../../src/compress/decompressor50.hpp#L54). There is **no** `src/compress/bitwriter.hpp` and no separate bit-reader header — the earlier citation was wrong.
- **Mechanism:** Replace shift-and-mask sequences with x86-64 **BMI1** `_bextr_u64` (BEXTR; ARM64 `ubfx`). BEXTR is BMI1, not BMI2: CPUID dispatch and the platform fallback must test the **BMI1** feature bit (`core::cpu` feature query), not BMI2. Replace variable-depth prefix branches with a branchless 2-level lookup table using conditional moves (`cmov`), and measure the added L1 table pressure.
- **Kill Gate:** $\ge 10\%$ branch-misprediction reduction is a **diagnostic only**; the gate of record is cycles/byte or throughput improvement under the G-3 protocol (§5.2), with no regression on the 30 golden cells' digest identity (I-1) and no L1-pressure regression on incompressible data.

#### 4. Hypothesis H-21: Pipelined Dual-Track Prefetching in Match Finding
- **Target Component:** [`src/compress/compressor50.cpp:1219`](../../src/compress/compressor50.cpp#L1219) (`Compressor50::find_match`; implementation helper `find_match_impl` at `:760`). The earlier `:450-550` citation was `begin_archive` / `normalize_window_size` / `begin_stream`, not match finding.
- **Mechanism:** Memory latency hides behind compute only if the two chains are **independent**. `prev_`/`head_` are index arrays, so prefetching candidate N+1 requires first loading `prev_[cand]` — a dependent load that serializes a naive prefetch. H-21 must therefore define a two-chain node layout: two independent chain heads (or a node pair fetched in one cache line) so `_mm_prefetch((const char*)&node[next_a], _MM_HINT_T0)` and `&node[next_b]` can issue together while SIMD compares candidate N. Without the two independent chains the gate is not adjudicable and the hypothesis must be closed.
- **Kill Gate:** $\ge 4\%$ throughput gain at `-m5` on large dictionary windows (`-md16m`, `-md64m`) under the G-3 protocol (§5.2), with identical digests (I-1) and thread-parity across the sequential/parallel engines (§5.6).

### 5.2 Measurement Protocol (Rule G-3, applies to H-18…H-25)
Every hypothesis is adjudicated by a fingerprinted measurement record, not by an informal benchmark:

- **Benchmark identity:** the harness name, source hash, compiler version, build type, and the exact command line are recorded. Integrated-vs-isolated A/B is stated explicitly: kernel microbenchmarks are diagnostics only; the kill gate is the end-to-end path unless the plan names a kernel gate.
- **Corpus:** the pinned real corpora plus the 30 deterministic ratchet cells; synthetic data is labelled and cannot alone satisfy a gate.
- **Repetitions & statistics:** at least 7 repetitions per configuration, report median and a spread (IQR or min/max); a delta inside the observed spread is "no signal", not a win.
- **Environment disclosure:** CPU model, RAM, OS build, power plan, and virtualization are recorded. Turbo/thermal state is noted.
- **Binary identity:** SHA-256 of every binary and archive used by the measurement.
- **Integrated A/B:** the same binary with the runtime kill switch on/off (one `G-1` dispatch function) so code layout is the only difference; separate binaries are allowed only when the switch is compiled out, and the difference is disclosed.
- **Refutations are permanent:** a failed gate is recorded with its numbers and the mechanism is not resurrected without a new hypothesis row.
- **G-9:** unavailable hardware (Apple Silicon, AVX-512, ARM64) is recorded as **blocked**; blocked is never pass, and a skipped leg cannot discharge a release gate.

- **Single decision function (G-1):** all runtime ISA selection goes through one function (e.g. `compress::arch::select_wildcopy_kernel()`) backed by one CPU-feature query. H-18/H-19/H-20/H-21 must name it; no per-call `__builtin_cpu_supports` branches scattered through kernels.
- **Thread parity:** the scalar and SIMD paths must produce identical output on every thread count; parallel compression chunk boundaries are invariant under kernel selection.
- **Trace matrix:** each hypothesis is traced through sequential decode/encode, parallel record-applier, spool, streaming, and WASM. A path with no SIMD variant must fall back to scalar and be tested there; a path that cannot run the feature is recorded as blocked, not skipped silently.
