## M0 — Symlink Read-Link Legality & Link Matrix

### M0.1 — `validate_symlink_target` function

**File:** `src/archive/archive_mutator.hpp` (new declaration), `src/archive/archive_mutator.cpp` (implementation)

```cpp
struct SymlinkLegality {
    bool valid{false};
    std::string reason;  // empty when valid
};

static SymlinkLegality validate_symlink_target(
    const std::string& arc_entry_name,
    const std::string& target);
```

Rejection rules (all checked on the raw target string, no filesystem access):

| # | Check | Condition | Reason string |
|---|-------|-----------|---------------|
| 1 | Empty | `target.empty()` | `"empty_target"` |
| 2 | Null byte | `target.find('\0') != npos` | `"null_byte"` |
| 3 | Absolute (POSIX) | starts with `/` | `"absolute_path"` |
| 4 | Absolute (Win) | `[A-Za-z]:` prefix | `"absolute_path"` |
| 5 | UNC | starts with `\\` or `//` | `"unc_path"` |
| 6 | Traversal (net-escape) | Normalize the target: resolve `foo/../bar` → `bar`, `a/b/../../c` → `../c`. Reject only when the normalized result starts with `../` (escapes the entry's parent directory). Valid relative `..` within the tree (e.g. `subdir/../sibling` → `sibling`) is accepted. | `"traversal"` |
| 7 | ADS (Windows only) | `:` after first component — `#ifdef _WIN32` only. Colons are legal in POSIX filenames; false-positive risk is unacceptable on macOS/Linux. | `"ads_stream"` |
| 8 | Reserved DOS (Windows only) | component matches `CON\|PRN\|AUX\|NUL\|COM[0-9]\|LPT[0-9]` (case-insensitive, with or without extension) — `#ifdef _WIN32` only. These names are valid on POSIX. | `"reserved_name"` |

**Hardlink target exemption:** `prepare_add_hardlink_from_memory` targets
are archive-internal entry names (references to other entries in the same
archive), not filesystem paths. They do not reach the filesystem at
create-time; extraction-time safety (H3 containment check in ArchiveReader)
already validates them. Only checks #1 (empty) and #2 (null byte) apply.

### M0.2 — Wire validation into `prepare_add_symlink_from_memory`

**Decision:** Add an optional `std::string* rejection_reason` parameter to

### M0.5 — Unit tests

**File:** `tests/unit/archive_tests.cpp` (or new `symlink_legality_tests.cpp`)

Test each rejection rule:
- Empty target → rejected
- Null byte → rejected
- Absolute POSIX `/etc/passwd` → rejected
- Absolute Windows `C:\Windows` → rejected
- UNC `\\server\share` → rejected
- Traversal `../../etc/shadow` → rejected
- Traversal `foo/../../bar` → rejected
- ADS `file:stream` → rejected
- Reserved `CON` → rejected
- Reserved `com1.txt` → rejected (reserved even with extension)
- Valid relative `../sibling` → **rejected** (net-escaping traversal)
- Valid relative `subdir/../sibling` → **accepted** (normalizes to `sibling`)
- Valid relative `a/b/../../c` → **rejected** (normalizes to `../c`, escapes)
- Valid relative `subdir/file` → accepted
- Valid relative `file.txt` → accepted
- ADS `file:stream` on Windows → rejected; on POSIX → accepted
- Reserved `CON` on Windows → rejected; on POSIX → accepted
- Target with forward slashes `dir/file` → accepted
- Target with backslashes `dir\file` → accepted (normalized)

### M1.3 — Timestamp-unavailable policy

When `-ts` requests ctime/atime but the source format doesn't provide them:
- **Omit the field from the archive header** (do not set epoch-0)
- Add `"ctime_unavailable"` / `"atime_unavailable"` to the per-entry JSON
  report when the source format lacks the requested timestamp
- GZIP sources never carry ctime/atime → always omitted with report entry
- ZIP sources: only when Extended Timestamp (0x5455) or NTFS (0x000A) extra
  field is present
- TAR sources: only when PAX `atime`/`ctime` headers are present

## M2 — FILECOPY Default-Materialization on `cv`

### M2.1 — Duplicate detection in transcode loop

**File:** `src/archive/foreign_transcode.cpp:280+`

1. Add a hash map with a custom hasher (required — `std::hash` does not
   specialize for `std::array`):
   ```cpp
   struct Blake2spHash {
       size_t operator()(const std::array<core::byte, 32>& d) const noexcept {
           size_t h;
           std::memcpy(&h, d.data(), sizeof(h));
           return h; // first 8 bytes of a 256-bit cryptographic hash
       }
   };
   std::unordered_map<std::array<core::byte, 32>, std::string, Blake2spHash>
       hash_to_master;
   ```
   Place after the `migrated_names` set.

2. After hashing each file entry (line 420), check `hash_to_master`:
   ```cpp
   auto it = hash_to_master.find(digest);
   if (it != hash_to_master.end()) {
       // Emit FILECOPY reference instead of staged file
       ArchiveMutator::PreparedAdd pa;
       // Need a from-memory variant of prepare_add_filecopy
       // (no src_file path needed for foreign entries)
       emit_filecopy_from_memory(e.name, it->second, e.mtime_sec, pa);
       batch.push_back(std::move(pa));
       migrated_names.insert(e.name);
       source_hashes.push_back(digest);
       migrated_entries.push_back(&e);
       ++result.migrated_files;
       add_report_entry(e, ForeignStatus::Ok, {});
       std::filesystem::remove(staging_file, rm_ec);
       continue;
   }
   hash_to_master[digest] = e.name;
   ```

### M2.2 — `prepare_add_filecopy_from_memory`

**File:** `src/archive/archive_mutator.hpp`, `archive_mutator.cpp`

The existing `prepare_add_filecopy` requires a `src_file` filesystem path
for stat (timestamps, logical size). The foreign transcode path has the
entry metadata already. Add:

```cpp
static bool prepare_add_filecopy_from_memory(
    const std::string& arc_entry_name,
    const std::string& target_entry_name,
    int64_t mtime_sec,
    core::uint64 logical_size,
    PreparedAdd& out,
    core::uint32 times_mask = time_flags::MTIME,
    const std::string& default_group = "",
    const std::string& default_user = "");
```

This mirrors `prepare_add_hardlink_from_memory` but with `redir_type = 5`
and FILECOPY-specific header layout (zero-length data area, dummy CRC32).

### M2.3 — Roundtrip verify adjustment

**File:** `src/archive/foreign_transcode.cpp:496+`

FILECOPY entries in the emitted archive extract to the same content as their
master. The verify loop must:
1. Include FILECOPY entries in `payload_indices` (they have `pack_size = 0`,
   not `< 0`)
2. Extract them (they resolve via ArchiveReader's FILECOPY materialization)
3. Compare the extracted content against `source_hashes[i]`

The current filter (`ae.header.pack_size < 0`) already excludes only
directory records, so FILECOPY entries with `pack_size = 0` are included.
Verify this is correct.
