# 🏛️ Principal Architect Challenge & Review

**Plan Reviewed:** OpenRAR v1.47.0 Pre-Analysis & Architectural Specification (`docs/v1.47.0-pre-analysis.md`)  
**Architect Verdict:** 🟢 CONDITIONAL APPROVAL (PASS WITH ARCHITECTURAL DIRECTIVES)

---

## 1. Executive Summary & Core Posture

The v1.47 proposal tackles long-overdue security infrastructure across foreign-format fuzzing, multi-threaded span decode race prevention, integer arithmetic safety in audio filter detection, and platform privilege confinement on macOS. 

The proposal is technically sound and avoids the architectural traps that plagued earlier drafts:
1. **Honest Platform Confinement:** It adheres to the established architectural doctrine (*"A cut ships two solid models plus honest docs"*), declining to paper over macOS Seatbelt's deprecation and SBPL profile opacity with false parity claims.
2. **Defect-Targeted Fuzzing:** The proposed fuzzers (`fuzz_zip`, `fuzz_tar`) target known protocol mismatch surfaces (Central Directory vs Local File Header; GNU/PAX extensions) rather than mindless generic byte mangling.
3. **Precision Arithmetic Bounds:** The remediation for OPT-F01 directly eliminates integer truncation and overflow UB in WAV delta filter detection.

Subject to the specific engineering directives below, this plan is cleared for implementation planning.

## 2. Critical Flaws & Architectural Risks

### [Risk 1 - macOS Sandbox Scope & Library Dependencies]
- **Mechanism:** Seatbelt SBPL profiles that restrict file-read access `(deny file-read*)` often break dyld runtime linking and system framework initialization if necessary system libraries (`/usr/lib`, `/System/Library`) are not explicitly allowed.
- **Consequence:** Spawning the sandboxed worker fails immediately on macOS with opaque `sandbox_init` error codes before the worker can even parse its IPC pipes.
- **Directive:** The SBPL profile for macOS worker isolation must strictly follow the system-allowlist pattern:
  ```scheme
  (version 1)
  (deny default)
  (allow file-read* (subpath "/usr/lib") (subpath "/System/Library") (subpath "/dev/urandom"))
  (deny file-write*)
  (deny network*)
  (deny process-fork)
  (deny process-exec)
  ```
  The profile must be validated on actual macOS hardware or virtualized CI runners. If `sandbox_init` fails, the parent must fail closed or emit the mandated loud capability-unavailable disclosure.

### [Risk 2 - ZIP64 Decompression Bomb Clamping in `fuzz_zip`]
- **Mechanism:** A malicious ZIP archive can declare 64-bit uncompressed entry sizes (e.g. 16 Exabytes) inside ZIP64 extra fields while presenting a tiny compressed size.
- **Consequence:** If `foreign_zip.cpp` allocates buffer space based on declared uncompressed size without capping, the fuzzer or consumer process will crash via OOM or thrash virtual memory.
- **Directive:** `foreign_zip.cpp` must enforce an explicit ceiling on single-member in-flight decompression allocation (matching the established RAR `ALLOC_LIMIT` ceiling) and reject or stream entries that declare uncompressed sizes exceeding this ceiling.

### [Risk 3 - Audio Delta Filter Backward Compatibility]
- **Mechanism:** Correcting the audio stride calculation (`filters50.cpp:140`) means archives previously compressed with malformed WAV inputs (e.g. `channels=2, bps=1032`) will no longer receive a Delta filter upon recompression.
- **Consequence:** Emitted archives for malformed WAV inputs will produce different compressed bytes.
- **Directive:** This is the intended security remediation. Legitimate WAV files (`stride 1..32` with standard channel counts and bit depths) must produce byte-identical archives before and after the fix. The regression test suite must assert byte identity on valid WAV corpora while proving filter suppression on malformed headers.

## 3. Pillar-by-Pillar Challenge

### Pillar 1: Correctness & Invariants
- **Stride Range Validation:** The proposal checks `(total_bits % 8 == 0) && stride >= 1 && stride <= 32`. This ensures not only that the stride fits within the filter limit (32), but also that partial-bit sample depths (which RAR delta filters cannot represent) are rejected cleanly.

### Pillar 2: Mechanical Sympathy & Performance
- **Zero-Allocation Fuzzing:** `fuzz_zip` and `fuzz_tar` must operate within bounded scratch memory. Fuzz targets must reuse input buffers and avoid unbounded vector reallocations.

### Pillar 3: Failure Modes & Robustness
- **Fail-Closed Foreign Readers:** A CD-vs-LFH discrepancy in ZIP must continue to trigger exit code 2 (structural refusal) with zero bytes emitted to destination.

### Pillar 4: Platform Realities
- **Host Sandbox Parity:** The published capability-gap table satisfies Section 7.5's governance requirements. Each capability class has an explicit disposition and user-visible disclosure.

### Pillar 5: API / ABI Stability
- No public ABI structs or export signatures in `openrar_dll.h` are altered.

### Pillar 6: Verification Depth
- The negative test plan explicitly covers all boundary cases, including integer wrap, oversized PAX headers, and hostile ZIP descriptors.

## 4. Architectural Directives for Implementation Plan

1. **Directive 1 (Seatbelt Profile Minimality):** Construct the macOS Seatbelt profile with explicit dyld/system-lib read permissions to avoid launch aborts.
2. **Directive 2 (WAV Regression Matrix):** Add unit tests in `compress_tests.cpp` verifying both the negative truncation cases and positive standard audio formats (8-bit mono, 16-bit stereo, 24-bit 5.1, 32-bit quad).
3. **Directive 3 (ZIP64 Fuzz Safety):** Ensure `foreign_zip.cpp` enforces safe memory ceilings during fuzzer execution.
4. **Directive 4 (TSan Proof):** Provide automated test assertions that `two_phase_tests` engages parallel decode threads so that TSan actively validates span synchronization.
