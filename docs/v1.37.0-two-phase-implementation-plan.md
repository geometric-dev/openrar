# v1.37.0 Implementation Plan — Two-Phase Parallel Decode

Gate 0: `docs/v1.37.0-two-phase-pre-analysis.md` (statelessness answered;
α probed; architect-challenge review round 1: 🟡 conditional approval with
directives R1–R10 — all applied below; the review's numbering is referenced
as [R#]). Measurement protocol: v1.34 §3. Prior-art pins carried from the
original review where still normative (P1/P2 synchronization pins, D5/D9).

## Review round 1 — applied directives (normative)

- **[R1] One apply path.** The apply engine (ring window, `copy_match`
  semantics, filter queue lifecycle, out-of-place transforms, flush
  cadence) is EXTRACTED from `decompress_internal` into a component driven
  by both the sequential token loop and the record applier. The applier is
  not a clone; the sequential path is bit-frozen through the refactor by
  the existing gate suite. The refactor lands FIRST (M0) and must be
  byte-identity-neutral on its own (full gate + fuzz before any
  parallel-only commit).
- **[R2] Pre-scan memory cap.** The block timeline is capped
  (`PRESCAN_MAX_BLOCKS = max(65536, packed/2)` entries ⇒ ≤ ~48 MiB at any
  packed size ≤ 96 MiB, and proportional thereafter); overflow ⇒ pre-scan
  failure ⇒ sequential fallback. Closes the minimal-header block-count DoS
  (3-byte headers could otherwise force ~16× packed amplification).
  Negative test `prescan_block_cap_fallback`.
- **[R3] Span topology.** `spans = clamp(packed / 4 MiB, 2, 4 × workers)`;
  engagement requires spans ≥ 3 (a 2-span member has one symbol worker —
  degenerate). Rationale: the applier's work is split-invariant; span count
  exists to keep the applier fed while stragglers finish (imbalance between
  packed-even splits and output density is real: 1.0–1.25× output/packed,
  non-uniform).
- **[R4] Pipeline bounds + failure propagation.** In-flight window = 2
  spans ahead of the applier (bounded record memory); a worker finishing
  further ahead parks (semaphore/CV). Any failure (worker, applier,
  spawn, OOM) sets the failure record and wakes EVERYONE (`notify_all` —
  original P1 pin); per-range sync state stays cache-line padded (original
  P2 pin). Join always terminates. Cancellation checks at block
  granularity (bounded stall ≈ one block decode, ~9 ms measured).
- **[R5] Partial-output semantics.** The driver's mid-stream failure
  behavior is EXACTLY the sequential decoder's: bytes already emitted to
  the consumer before a later span fails are discarded by the consumer's
  existing containment (v1.24 AtomicWriter temps are never committed on
  failure; `t` reports FAILED). No new "no partial output" guarantee is
  claimed beyond what sequential provides; F2/F3 assert the SAME contract,
  not a stronger one.
- **[R6] Engine trace + decision function.** `should_use_parallel_decode`
  (single, total, deterministic; pre-scan results are an input) is consumed
  by the CLI extraction path AND the CLI verify path (`t`). Documented
  sequential surfaces: `stream_decoder` (per-block streaming — cannot
  phase-split without buffering the whole member), DLL
  `decompress_to_vector` (unknown dest size), WASM (G6 compile-out),
  `buffer_archive` (unknown dest size). DLL conformance row
  (`two_phase_dll_conformance`) documents non-engagement through the C ABI
  (original D5); `-mt` default = 2 on decode when unset (original D9);
  kill switch `OPENRAR_NO_PARALLEL_DECODE=1`; measurement override
  `OPENRAR_PARALLEL_DECODE_THREADS`.
- **[R7] Coordinate-frame table (v1.21.1 rule).**

  | State | Frame | Converted at |
  |---|---|---|
  | Block timeline (bit positions) | packed-stream bytes/bits | nowhere (same frame everywhere) |
  | Operation records | member-local, span-relative order | nowhere — the applier's running position resolves them |
  | Match distance | absolute (window) | parse (fresh) / apply (rep) |
  | Filter start delta | as-read (position-relative) | apply: `start = applier_pos + delta` |
  | Filter `block_start` | member-local output position | apply-time queue (absolute frame owned by the applier) |
  | Worker Σ output | span-relative lower bound | never crosses a boundary (span-internal only) |

  Record fields never require the absolute output position at record time
  (the pre-scan cannot know it and no record needs it).
- **[R8] Span-boundary semantic tests.** Named: `span257_first_record`
  (slot-257 as a span's first token — applier's last_length resolves it),
  `dest_cross_span_front|middle|last` (dest_size crossing at each span
  position), `prescan_empty_terminator` (BlockSize 0 + last block),
  `prescan_flagclear_first_block` (non-solid member starting flag-clear ⇒
  fallback ⇒ sequential rejects identically).
- **[R9] Claims on both stream shapes.** Paired-delta rows on our-encoder
  corpora AND Rar 7.20-made members (512 KiB blocks, bit-7 reuse shapes) —
  the α probe measured our block shapes only.
- **[R10] Worker table seeding.** Workers receive the pre-scan's PARSED
  descriptions (memcpy + the `initialize_from_description` build path —
  identical product to `read_tables`, original P7 preserved); no per-worker
  description re-parse; validated by the span-records identity test.

## M0 — Apply-engine extraction [R1] (lands first, byte-identity-neutral)

Files: `src/compress/decompressor50.{hpp,cpp}`.

1. Extract from `decompress_internal`: the ring window state
   (`window_`/`win_pos_`/`unp_ptr_`/`first_win_done_`), `copy_match`, the
   filter queue (`filters_`) with its lifecycle checks, the out-of-place
   transform application, and the flush machinery
   (`flush_plain_up_to`/`flush_pending_blocks` + the 64 KiB cadence) into
   an internal `ApplyEngine` type (member of `Decompressor50`, not a public
   ABI surface).
2. The sequential token loop keeps: BitReader, token parse, rep-state
   (`old_dist_`/`last_length_` — parse-side in sequential, apply-side in
   the applier; `copy_match` reads neither), validations, dest_size
   clamping — and drives `ApplyEngine` at the same points it drives that
   state today (identical flush triggers, identical call order).
3. Gate: full `tools/gate.ps1` + fuzz + the golden/interop suites — the
   refactor commit must be behavior-neutral (no new code paths engaged; no
   emitted-byte change; no test vector change).

## M1 — Pre-scan [R2, R7]

Files: `src/compress/decompressor50.{hpp,cpp}` (extends the parked scout's
structures; the full-token scout is superseded but its validated framing
walk is reused verbatim).

1. Walk block headers with the decoder's `read_block_header`; for
   bit-7-set blocks parse the description with the decoder's `read_tables`
   and store the parsed lengths. Produce: per-block {header byte offset,
   payload end bit, desc id in force}, the description pool, last-block
   flag, and the `PRESCAN_MAX_BLOCKS` cap [R2].
2. Fail-closed on any framing anomaly ⇒ sequential (F1); the pre-scan is
   at least as strict as the sequential framing walk (its contract —
   accepting what sequential would reject is impossible by reuse; asserted
   by the records-identity test).
3. Cost: header walk + one description parse per table block (~7 µs each);
   ~1 ms on a 128-block member. No token decoding.

Tests: `prescan_block_cap_fallback` [R2], `prescan_empty_terminator`,
`prescan_flagclear_first_block` [R8], boundary agreement vs the sequential
walk on every corpus member (extends the parked 141/141 comparison).

## M2 — Operation records + span workers [R7, R8, R10]

Files: `src/compress/decompressor50.{hpp,cpp}`.

1. Record types (tagged, varint): `LIT`(byte), `MATCH`(varint adjusted
   length — the distance-band ladder applied here exactly once — varint64
   distance), `REP`(index 0..3, varint length — no ladder), `R257`(no
   payload), `FILTER`(raw 1..4-byte start delta, length post-clamp
   > 0x400000 ⇒ 0, type, channels). 64-bit distance fields from the start
   (slot-64+ > 4 GiB distances).
2. Span worker = the parked scout's token loop restricted to a block span,
   appending records; position-free checks only (dist = 0, dist >
   win_size ⇒ early fail); NO window, NO rep-state dependency (worker Σ
   output is a span-relative lower bound used for nothing but the
   terminal-crossing hint [R7/R8]). Tables seeded from the pre-scan's
   parsed descriptions [R10]. Record pool pre-reserved from the G5 bound
   `max(4 MiB, 4 × span packed)`; overflow ⇒ span fails ⇒ sequential
   fallback (the bound's arithmetic: worst legal corners ~1.6× packed for
   literal-dense, ~2.7× for match-dense — margin documented in the Gate 0).
3. Per-span trailer: record count, last_block-seen flag. The applier is
   the sole authority for stop and clamp semantics [R5, R8].

## M3 — The pipelined applier + driver [R3, R4, R5, R6]

Files: `src/compress/parallel_decode.{hpp,cpp}` (driver); applier in
`decompressor50.cpp` driving the M0 `ApplyEngine`.

1. The applier consumes spans strictly in order through the SAME
   `ApplyEngine` the sequential decoder uses: `MATCH` ⇒ resolve window
   copy (dist 0/over-window already rejected at parse; `dist == win_size`
   advance case and zero-fill past written prefix inherited, not
   reimplemented); `REP` ⇒ resolve `old_dist[i]` (sentinel/window checks
   here — the sequential checks verbatim), rotate, set last_length (no
   ladder); `R257` ⇒ re-emit from applier state (no-op when
   last_length = 0); `FILTER` ⇒ push to the engine queue (position-free
   parse checks already done; the queue's disjointness/overlap,
   length-vs-window, aggregate-budget, and count-cap checks run here
   verbatim at apply positions). Flush triggers land at identical
   positions ⇒ byte- AND chunk-identical emission.
2. Driver: gates (G1–G6, with G3's span topology per [R3] and G5's record
   bound per [R2]/[R4]); static split at block boundaries nearest
   `spans`-even packed split; R−1 workers + the driver thread running the
   applier; in-flight window 2 [R4]; single in-flight failure ⇒
   `notify_all` ⇒ join ⇒ fail with the sequential taxonomy [R4, R5];
   cancellation at block granularity [R4].
3. `two_phase_dll_conformance`: C-ABI decode paths documented and
   exercised as sequential (engagement false) [R6].

## M4 verification record (shipped state)

**R3 amended by measurement.** The Gate 0 probe's 5-span topology left the
applier idle through the first span decode and serialized the tail
(1.14x at `-mt4`); per-span fixed costs (wakeup, table build from the
recorded description, publish) measure in tens of microseconds against a
~17 ms span decode, so the shipped topology is
`spans = clamp(packed / 1 MiB, 3, 32)` with the G3 floor kept on the
MEMBER (`workers x 4 MiB`). At 21-32 spans the pipeline overlaps end to
end (trace: apply span k runs while spans k+2.. decode).

**En-route defect found by the identity suite (fixed before ship).** The
bulk literal fast path in the applier clamped each stretch at
`last_flushed + 65536 - total`. With a PENDING FILTER, flush_pending stops
at the region start and freezes last_flushed below total, so the clamp
wraps to zero and the loop spun forever - the filter-bearing identity row
hung intermittently (~50-75% of runs). Fix: segment at the cadence only
while the flush cursor is inside the current window; the post-copy flush
attempt still fires at the same positions (chunk boundaries unchanged,
pinned by the chunk-identity rows). Three consecutive clean full-suite
runs after the fix.

**Measurement record** (v1.34 SS3 protocol: paired deltas, min-of-15,
alternating order, single sessions; host 2C/4T i7-7500U):

| row (64 MiB text unless noted) | ratio vs our sequential |
|---|---:|
| Rar-made m3 -md2m, `-mt4` | 1.21-1.26x (3 sessions) |
| Rar-made m3 -md128m, `-mt4` | 1.35x |
| our-encoder m3 -md2m, `-mt4` | 1.14-1.26x |
| Rar-made `-mt8` (2C/4T host: oversubscribed) | 1.00-1.02x |
| 4-block member / stored / zeros / `-mt1` (no-regression) | 0.96-1.09x |
| UnRAR 7.20 `-mt4` cross-baseline on the Rar-made archive | 348 ms vs our 660-760 ms |

**Prediction revision (stated up front in the Gate 0 as 1.5-2.2x at
`-mt4`; measured 1.2-1.35x - the miss is structural and understood).** The
probe's alpha (0.53-0.74) measured the symbol share of the NULL-CALLBACK
kernel; the SERIAL stage of an end-to-end extraction is
apply + flush + CRC + write, which measures 0.55-0.62 of the sequential
total, and on a 2C/4T host the single applier thread hyperthread-contention
with R decode workers stretches it further (the applier is the pipeline
floor: 21 ms/span apply vs 42 ms/span decode at 4 workers -> wall =
max(symbols/R, apply+consumer)). The pipelined design therefore lands at
reference parity on this host (the 1.29x baseline is within session noise)
rather than beating it. The win GROWS with core count (the contention term
shrinks; the apply floor does not) and compounds with v1.38's faster
symbol kernel only up to the apply floor - after v1.38 the apply stage
becomes the dominant serial cost, which is the next arc's lever.

**Honest scope note.** `-mt8` on a 2C/4T host oversubscribes and returns
~1.0x (the requested worker count is honored; the default is
min(hardware_concurrency, 8)). Pattern-dominated members whose packed size
stays under the G3 floor (zeros-class) are gated to sequential by design
(alpha 0.10 there; the reference's own 1.07x confirms the shape).
