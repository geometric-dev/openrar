# tests — OpenRAR Test Suites & Conformance Harness

Validation suites and conformance test harness for OpenRAR.

## Running every test layer

| Layer | Command | Needs |
|---|---|---|
| C++ unit suites (ctest) | `ctest --test-dir build -C Release --output-on-failure` | built binaries |
| Build + ctest + interop in one shot | `powershell -File tools/gate.ps1` | cmake, Python, (WinRAR for interop) |
| Writer conformance (node) | `node tools/run-tests.cjs` (all) or `node tools/run-tests.cjs format roundtrip parity` (WinRAR-independent subset) | built `openrar` (`OPENRAR_EXE` to override); WinRAR/UnRAR optional oracle (`UNRAR_EXE`) |
| Interop gate (cross-decode vs WinRAR) | `python tools/interop_gate.py --quick` | local WinRAR strongly recommended (CI degrades to self-roundtrip) |
| Encryption smoke vs goldens | `powershell -File tests/test_crypt.ps1` | built binary + golden archives |
| Fuzz sweeps | configure with `-DOPENRAR_FUZZ=ON`, then `ctest -R fuzz` | — |
| Nightly libFuzzer | `.github/workflows/fuzz.yml` (clang, corpus cached) | CI |

Suites that need WinRAR skip their oracle asserts visibly when it is absent;
the WinRAR-independent checks still run everywhere.

## Files

- `make_archives.ps1` — generates minimal **stored** archives for CI smoke tests:
  - `hello5.rar` — RAR5 (8-byte sig `Rar! 1A 07 01 00`, HEAD_FILE stored, 2 files: `hello.txt` + 100 KB `data.bin`).
  - `hello4.rar` — RAR4 (7-byte sig `Rar! 1A 07 00`, FILE_HEAD LONG_BLOCK stored).
  No compressor is invoked; blocks are hand-built with correct CRCs, vints, and HS.
- `hello5.rar` / `hello4.rar` — pre-generated archives (checked-in). Regenerate with `make_archives.ps1`.
- `hello5_p.rar` — RAR5, **file-data encrypted** (`-p secret`); headers are in clear.  
  Pre-generated golden file (do not regenerate unless the spec changes).
- `hello5_hp.rar` — RAR5, **headers + file data encrypted** (`-hp secret`).  
  Pre-generated golden file (do not regenerate unless the spec changes).
- `test_crypt.ps1` — six-test smoke harness for AES-256-CBC encryption (spec §4, §8):
  correct-password extraction, wrong-password rejection, header-visibility assertions.
- `out_ci/` — CI extraction dir (git-ignored via `*.rar` + `build/` rules; created at runtime).
- `out_crypt/` — encryption test extraction dir (created/cleaned by `test_crypt.ps1`; git-ignored).


## Usage

```powershell
# Regenerate archives (deterministic: Random seed 42 + clock/pid pattern)
powershell -NoProfile -ExecutionPolicy Bypass -File tests\make_archives.ps1

# Smoke test with built openrar.exe (mirrors .github/workflows/build.yml)
cmake --build build --config Release
& build\Release\openrar.exe x -y tests\hello5.rar tests\out_ci\
Get-Content tests\out_ci\hello.txt -Raw   # -> "Hello from open-rar!"
```

## Determinism

- `make_archives.ps1` uses fixed seed `Random 42` for `data.bin` and avoids `Get-Random`.
- Temp-dir helper `New-MkTempSuffix`: deterministic pid + clock loop.
- PowerShell 5.1 gotchas:
  - Hex `≥0x80000000` via `[Convert]::ToUInt32('EDB88320',16)` (see `$POLY`).
  - Single-element unwrap via `@(Get-ChildItem ...)[0]`.
  - Avoid `$args` reserved variable — use `$argList`/`$fileList`.
  - CRLF normalize `Replace("`r`n","`n")` before content asserts.
  - `@()` wrapping on pipeline results that may be singletons.
